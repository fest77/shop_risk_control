## 1. 模块定位

| 项 | 内容 |
|---|---|
| **职责** | 调接口取数 → 渲染 4 张指标卡片 + 3 类图表 + SSE 实时事件流；提供时间范围/场景/等级筛选与下钻跳转 |
| **上游** | 00 公共基础（壳、组件、`api.js`）；**11 监控指标引擎**（全部数据来源）；03（SSE 事件） |
| **下游** | 无（终端展示页） |
| **对应 PRD** | **2.3.3 风控态势大盘页** |
| **对应实体** | E15 `metric_buckets`（**只读，且不直接查库，一律走 11 的接口**） |
| **对应原型** | `02_风控态势大盘页.pen` |
| **对应架构决策** | AD-03（指标桶增量聚合——本模块因此可以「取数即用」，不做聚合） |

**本模块明确不做的事（关键边界，见 `00_模块划分与边界.md` §3.2）**：
- **禁止在页面里计算任何比率/均值/排行**（如拦截率、平均分）。所有派生指标由模块 11 算好下发
- 不直接访问 MongoDB
- 不负责指标桶的写入与聚合（归 11）

## 2. 页面结构

对应原型 `02_风控态势大盘页.pen`（画布 1440×1040）。

### 2.1 顶部工具栏 `dbToolbar`

| 元素 | 控件 | 默认值 | 说明 |
|---|---|---|---|
| 时间范围 | 下拉 | **近 24 小时** | 选项：近 1 小时 / 近 24 小时 / 近 7 天 |
| 场景筛选 | 下拉 | 全部场景 | 选项来自 `GET /common/enums` 的 `rule_scenes`（登录/领券/下单/支付/售后） |
| 风险等级 | 下拉 | 全部风险等级 | `low` / `medium` / `high` |
| 自动刷新 | 开关 + 绿点 | **开**，间隔 5 秒 | 关闭后仅手动刷新 |
| 「刷新」按钮 | ghost | — | 立即重取全部数据 |
| 「导出快照」按钮 | plain | — | 导出当前大盘为 PNG + 指标 JSON |

**交互约束**：三个筛选器**联动刷新全部 4 张卡片 + 3 张图表**，不允许只刷局部（原型标注已声明）。

### 2.2 指标卡片行 `statRow`（4 张，等宽，间距 16）

| # | 卡片标题 | 数值示例 | 单位 | 数据字段 | 下钻行为 |
|---|---|---|---|---|---|
| 1 | 实时事件请求量 | `12,847` | 次 / 近1小时 | `event_cnt` | 无 |
| 2 | 拦截率 | `4.7` | % | `block_rate` | 无 |
| 3 | 待审案件数 | `23` | 件 | `review_cnt` | 点击 → 跳 `#/cases?status=pending` |
| 4 | 预估挽回资损 | `3,580` | 元 | `estimated_saved_amount` | 点击 → 跳 `#/cases?decision=reject` |

- 数值字号 28/700（Funnel Sans），单位 12px 灰
- 每张卡片下方一行 12px 灰字**数据口径提示**（原型已写，例如"来源 metric_buckets.event_cnt"）
- 卡片 2（拦截率）> 10% 时数值变红，提示异常

### 2.3 图表行一 `chartRow`（2 张，等高 260）

| 图表 | 类型 | 数据 | 说明 |
|---|---|---|---|
| 拦截率趋势 | 折线图 + 面积，**双 Y 轴** | 时间桶序列（`1m` 或 `1h`，随筛选自动选粒度） | 左轴事件量、右轴拦截率(%)；X 轴时间 |
| 风险等级分布 | 环形图（doughnut） | `low / medium / high` 三项占比 | 中心显示近区间总量 |

### 2.4 图表行二 `chartRow2`（2 块，等高 260）

| 块 | 内容 | 数据 |
|---|---|---|
| 规则命中排行榜 | **横向柱状图** Top10 | 规则命中次数；点击柱子 → 跳 `#/rules?code=<rule_code>` |
| 实时事件流 | **表格**（SSE 推送，最新在上） | 列：时间 / 事件类型 / 用户 / 得分 / 决策 |

**实时事件流列宽与配色**

| 列 | 宽 | 规则 |
|---|---|---|
| 时间 | 110 | `HH:mm:ss` |
| 事件类型 | flex | 英文枚举值原样展示 |
| 用户 | 120 | 用户编号 |
| 得分 | 80 | 0~100 |
| 决策 | 90 | `pass` 灰 / `review` 橙 / `reject` 红 |

**滚动行为**：仅保留最近 **50** 条；新事件插入顶部并有 0.3s 高亮淡出；**用户手动向上滚动时暂停自动滚动**，回到底部后恢复。

### 2.5 页面状态

| 状态 | 表现 |
|---|---|
| 首次加载 | 卡片显示骨架、图表显示占位、事件流显示「连接中…」 |
| 有数据 | 正常渲染 |
| 空数据（该区间无事件） | 卡片显示 `0`、图表显示「该时间范围内暂无数据」空态、事件流显示「暂无实时事件」 |
| 接口失败 | 该区块显示错误占位 + 「重试」按钮，**其他区块不受影响**（区块级隔离） |
| SSE 断线 | 事件流区显示「实时连接已断开，正在重连…」（黄条），指数退避重连（1s→2s→4s，上限 30s） |
| SSE 重连成功 | 黄条消失，拉取最近 50 条补齐 |

## 3. 接口字段

> 全部由**模块 11** 提供；本模块只消费。

### 3.1 `GET /api/v1/metrics/overview`

**请求**：`range`（`1h`/`24h`/`7d`，默认 `24h`）、`scene`（可选）、`level`（可选）

**响应 `data`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `event_cnt` | int | 事件量 |
| `block_rate` | float | 拦截率，**已由后端算好**，保留 1 位小数 |
| `review_cnt` | int | 待审案件数 |
| `estimated_saved_amount` | int | 预估挽回资损（单位：**分**） |
| `range` | object | `{from, to, granularity}` 实际生效区间与粒度 |
| `degraded` | bool | 数据是否来自降级路径（如桶缺失时回退实时聚合） |

> **金额单位统一为「分」**，前端负责转元展示（`3580000` → `3,580` 元）。

### 3.2 `GET /api/v1/metrics/trend`

**响应**：`{ granularity, points: [{ts, event_cnt, block_rate}] }`（按 `ts` 升序）

### 3.3 `GET /api/v1/metrics/distribution`

**响应**：`{ total, items: [{key: "low"|"medium"|"high", label, cnt, ratio}] }`

### 3.4 `GET /api/v1/metrics/rule-ranking`

**响应**：`{ items: [{rule_code, rule_name, hit_cnt}] }`（已按 `hit_cnt` 降序，最多 10 条）

### 3.5 `GET /api/v1/metrics/stream`（SSE）

| 项 | 约定 |
|---|---|
| 协议 | `text/event-stream` |
| 事件名 | `event`（默认） |
| 数据体 | 单条事件的决策摘要：`{event_id, ts, event_type, user_id, score, decision}` |
| 心跳 | 每 **15s** 发一次 `: ping` 注释行，防中间层断连 |
| 重连 | 前端指数退避；服务端不保证补发历史（前端重连后主动拉 `/overview` 与最近事件） |
| 关闭 | 页面切走 / `visibilitychange` 为 hidden 时**主动断开**以省资源；回到页面重新连接 |

## 4. 业务规则

### 4.1 取数与计算边界

| 编号 | 规则 |
|---|---|
| **BR-02-01** | 页面**只做展示与格式化**；所有比率、均值、排行的计算一律由模块 11 完成后下发（**禁止前端二次计算**） |
| **BR-02-02** | 金额一律以「分」传输、由前端转元并千分位；**禁止后端下发已格式化的字符串** |
| **BR-02-03** | 百分比保留 **1 位小数**，由前端统一格式化函数处理，不在各视图重复实现 |
| **BR-02-04** | 时间序列的粒度由**后端**根据 `range` 决定并回传，前端不自选（避免前后端口径不一致） |

### 4.2 刷新与实时

| 编号 | 规则 |
|---|---|
| **BR-02-05** | 自动刷新间隔 **5 秒**，仅在页面可见时生效（`visibilitychange` 为 hidden 时暂停） |
| **BR-02-06** | 手动「刷新」与自动刷新**共用同一取数函数**，避免两套逻辑 |
| **BR-02-07** | 筛选器变更后**先取消在途请求**（`AbortController`），再发起新请求，防止旧响应覆盖新结果 |
| **BR-02-08** | SSE 只用于事件流；**卡片与图表不走 SSE**，走定时轮询（简化且足够） |
| **BR-02-09** | 事件流最多保留 50 条，超出丢弃最旧 |
| **BR-02-10** | 用户手动上滚时暂停自动滚动（不打断阅读），回到底部自动恢复 |

### 4.3 区块级容错

| 编号 | 规则 |
|---|---|
| **BR-02-11** | 4 张卡片、3 张图表、事件流**互相独立**：任一区块失败只影响自身，其余照常渲染 |
| **BR-02-12** | 每个区块失败时显示「加载失败 + 重试」，**不允许整页白屏或整页报错** |
| **BR-02-13** | 后端返回 `degraded=true` 时，页面在对应区块显示黄色提示「数据来自降级路径，仅供参考」，**不隐藏** |

### 4.4 下钻与跳转

| 编号 | 规则 |
|---|---|
| **BR-02-14** | 「待审案件数」卡片点击 → `#/cases?status=pending`（筛选条件通过 hash query 传递） |
| **BR-02-15** | 「预估挽回资损」卡片点击 → `#/cases?decision=reject` |
| **BR-02-16** | 规则排行柱子点击 → `#/rules?code=<rule_code>` 并高亮该行 |
| **BR-02-17** | 下钻目标页必须能**识别并应用** hash query 中的筛选条件（模块 07 / 06 需支持） |
| **BR-02-18** | 无该项权限的角色点击下钻时，按模块 01 规则跳回 `#/dashboard` + 提示，而非进入空白页 |

### 4.5 图表实现

| 编号 | 规则 |
|---|---|
| **BR-02-19** | 图表统一用**本地 vendor 的 ECharts**（`/static/vendor/echarts.min.js`），**禁止 CDN**（D-01 已确认） |
| **BR-02-20** | 每个图表实例在视图卸载时 `dispose()`，防止内存泄漏与重复渲染 |
| **BR-02-21** | 窗口 resize 时 `chart.resize()`（节流 200ms） |
| **BR-02-22** | 图表配色必须取自主题变量（风险等级用 `#D93025 / #E8710A / #1E8E3E`），不硬编码 |

## 5. 异常处理

| 错误码 | 场景 | HTTP | 用户可见提示 | 处理 |
|---|---|---|---|---|
| `DASH-4001` | 图表/维度参数非法 | 422 | 「参数不合法」 | 正常不触发（下拉已限定） |
| `DASH-5001` | SSE 实时流连接建立失败 | 200（降级） | 「实时流已断开，正在重连…」 | 指数退避重连，上限 30s |
| `DASH-5002` | SSE 推送中断 | 200（降级） | 同上 | **保留已展示数据不清空**，避免视觉跳变 |
| `MET-4001` | `range` 取值非法 | 422 | 「时间范围参数不合法」 | 前端下拉已限定，正常不触发 |
| `MET-4002` | 时间范围超出可查询上限（如 >90 天） | 422 | 「查询范围过大，请缩小时间范围」 | 禁止全表扫描 |
| `MET-5001` | 指标桶查询失败 | 503 | 「指标服务暂时不可用」 | 区块级错误占位 + 重试 |
| `MET-5002` | 指标桶缺失（区间无数据） | 200 | 空态「该时间范围内暂无数据」 | **不是错误**，`total=0` 正常返回 |
| `DASH-5001` | SSE 连接建立失败 | — | 「实时连接失败，正在重试」 | 指数退避重连，最长 30s |
| `DASH-5002` | SSE 中途断开 | — | 「实时连接已断开，正在重连…」 | 同上；重连成功后主动补齐最近数据 |

> **本模块不参与放行判定**，因此不涉及 fail-closed；但**数据异常时不得静默显示 0**——必须区分「真的没有」与「取数失败」（`MET-5002` vs `MET-5001`）。

## 6. 文件规划

```
static/
├── css/
│   └── dashboard.css              # 大盘专有样式（卡片行、图表行、事件流）
└── js/
    ├── views/
    │   └── dashboard.js           # 视图主逻辑：取数编排、筛选联动、区块状态机
    ├── charts/
    │   ├── echarts.js             # ECharts 初始化/销毁/resize 的薄封装
    │   ├── trend.js               # 趋势折线（双轴）配置
    │   ├── doughnut.js            # 风险等级环形图配置
    │   └── ranking.js             # 规则排行横向柱状图配置
    ├── stream.js                  # SSE 连接管理（重连、心跳、暂停、补数）
    └── format.js                  # 百分比/金额（分→元）/千分位/时间 统一格式化（BR-02-03）
```

> 后端侧本模块**不新增文件**——数据全部来自模块 11 的 `metrics_api.py`。

| 文件 | 职责 | 可测 |
|---|---|---|
| `views/dashboard.js` | 视图编排与状态机 | 手工/浏览器 |
| `stream.js` | SSE 生命周期与重连 | 手工/浏览器 |
| `format.js` | 统一格式化（唯一实现处） | ✔ 纯函数，可单测 |
| `charts/*.js` | 图表配置与实例管理 | 手工/浏览器 |

**要求**：`format.js` 必须被模块 07/12/13 的列表页复用，**不允许各自再写一份格式化**。
