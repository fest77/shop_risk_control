## 1. 模块定位

| 项 | 内容 |
|---|---|
| **职责** | 建案（review/reject 沉淀）→ 认领 → 状态机流转 → 处置结论与联动动作执行 → 联动写名单库 → 调 `BizAdapter` → 写 `case_actions` 与 `audit_logs`（哈希链） |
| **触发时机** | 建案：决策链路异步触发（中低频）；处置：审核员人工点击并二次确认后（**低频、不可撤销**） |
| **上游** | 05 规则决策引擎（`decision ∈ {review, reject}` 时本模块建案）、07 审核工作台（传入 `case_no` 与人工选择）、01 鉴权（提供 `operator` / `operator_role`） |
| **下游** | 06 名单库（写入 `list_entries`，`source=auto`）、12 审计日志（写 `audit_logs` 哈希链）、09 画像图谱（`case.disposed` 事件驱动边 `risk_flag` 与 `blacklist_history` 标签） |
| **对应 PRD** | 2.3.4 案件生成与协同处置规则、**2.3.7-2 高危案件调查与处置流程**、2.3.5 处置交互模块、2.3.8 审核留痕信息 |
| **对应实体** | **写 E08 `risk_cases`**（状态字段）、**写 E09 `case_actions`**；间接写 E07 `list_entries`、E16 `audit_logs`；读 E01/E02/E03（渲染证据引用） |
| **对应原型** | `03_风控审核工作台.pen` 右栏 `dpCard`、`06_处置二次确认弹窗.pen` 全部节点 |
| **对应架构决策** | **AD-08**（`BizAdapter` 可插拔，默认 `MockBizAdapter`）、**AD-04**（审计哈希链单写者）、AD-01（异步落库）、AD-02（名单 TTL 缓存需主动失效） |

**本模块明确不做的事**（防止与 06 / 07 / 09 / 12 重叠）：

- 不做案件列表的筛选、分页、三栏联动、画像与图谱渲染 —— **全部归 07**；本模块只提供「处置执行」所需的读写接口
- 不做名单条目的增删改与批量导入 —— **归 06**；本模块只调用 06 暴露的 `ListService.add_auto()`
- 不做哈希链的存储结构与全链校验 —— **归 12**；本模块只调用 `AuditService.append()`
- 不做画像聚合与图谱遍历 —— **归 09**
- **不做处置的撤销**（见 BR-08-27）——无 undo 接口，纠错只能通过 06 的反向名单操作 + 留痕

## 2. 页面结构

处置交互的可见元素**集中在两处**（03 右栏 + 06 弹窗），另有若干结果反馈位落在 03 右栏。

### 2.1 展示点 A：`03_风控审核工作台` 右栏 · `dpCard` 研判与处置

| 元素（原型节点名） | 绑定字段 / 取值 | 约束与交互 |
|---|---|---|
| `dpConclusion` 处理结论 * | `conclusion` | 单选，**必填**；`optViolate`→`violation` 确认违规 / `optNormal`→`normal` 确认为正常 / `optDoubt`→`suspicious` 存疑待观察 |
| `dpActOpts` 联动处置动作（可多选）* | `action_types[]` | **必填且至少 1 项**；`ck1` 拦截订单→`block_order`、`ck2` 拉黑用户→`blacklist_user`、`ck3` 封禁设备→`ban_device`、`ck4` 驳回退款→`reject_refund` |
| `dpRemark` / `dpRemBox` 处置原因备注 *（必填） | `remark` | **trim 后非空**；≤500 字（BR-08-16）；前端软提示「建议不少于 10 字」 |
| 底部警示行 | 固定文案 | 原型原文**必须保留**：「⚠ 提交后将同步写入名单库与审计哈希链，不可撤销；执行前需二次确认。」 |
| `btnRelease` 放行 | 预置 `conclusion=normal` + `action_types=[pass]` | 仍走二次确认；与 `normal` 不相容的动作不得被预置 |
| `btnReject` 违规拦截 | 预置 `conclusion=violation` + `action_types=[block_order, blacklist_user, ban_device]` | 预置值可再手工勾选增删；仍走二次确认 |
| `btnSubmit` 提交处置 | 取当前表单值 | **置灰条件**：结论未选 或 动作为空 或 备注 trim 后为空（对齐原型 `wbNote` 第 2 条） |

**动态禁用**：结论切换时按 BR-08-14 的相容矩阵即时禁用非法动作复选框，并在 `dpActions` 下方给出原因文案（如「结论为『确认为正常』时不可勾选拦截类动作」）。

**空态 / 不可用态**：案件 `status ≠ reviewing`（非本人认领）时，`dpConOpts` / `dpActOpts` / `dpRemBox` 整体置灰，`dpBtns` 三按钮禁用，并提示「请先认领该案件」或「该案件已处置，不可重复处置」。

### 2.2 展示点 B：`06_处置二次确认弹窗` · **必须列出全部副作用**

弹窗内容**由服务端权威生成**（调 `POST /cases/{case_no}/dispose/preview`），**禁止前端自行拼装**——否则漏列副作用就是安全漏洞。

| 元素（原型节点名） | 绑定字段 | 说明 |
|---|---|---|
| `ds1` 案件编号 | `case_no` | E08._id |
| `ds2` 涉事用户 | `user_id` + `user_age_days` | 文案「U000128（注册 42 天）」 |
| `ds3` 风险评分 | `risk_score` + `risk_level` | 文案「86 分 · 高风险」（E08 冗余快照） |
| `ds4` 处理结论 | `conclusion_label` | 文案「确认违规」 |
| `ds5` 联动动作 | `action_labels[]` | 文案「拦截订单 · 拉黑用户 · 封禁设备」 |
| `dlgRemark` | `remark` | 只读回显；说明「将写入审计日志」 |
| 副作用警示行 | `side_effects[]` | 原型原文**必须逐字呈现**：① 写 `case_actions` ② 写 `list_entries` ③ 调用 `BizAdapter` ④ 写审计哈希链。**并追加本模块补充的 ⑤ 更新案件状态为 `disposed`** |
| `dlgCancel` 取消 | — | 关闭弹窗，不发任何请求，**不产生任何副作用** |
| `dlgOk` 确认执行 | `confirm_token` | danger 色；点击后携 `confirm_token` 调 `POST /cases/{case_no}/dispose` |

> **澄清**：弹窗中 ①~④ 的编号是**副作用清单的展示编号**，不是执行顺序；真实执行顺序见 BR-08-29。

### 2.3 展示点 C：`03` 右栏 · 处置结果反馈（本模块新增的最小反馈位）

| 结果 | 展示 |
|---|---|
| 全部成功 | Toast「已处置：结论=违规 · 动作=拦截订单/拉黑用户/封禁设备」；案件状态徽标置为「已处置」；刷新处置流水 |
| **技术性部分失败**（BizAdapter 失败，`DSP-5003`） | 黄色警示条「业务系统同步失败（模拟业务系统未对接），已加入重试队列」+「重试同步」按钮（调 `/biz-sync/retry`）；案件状态**仍为已处置** |
| **紧操作失败**（名单写入失败，`DSP-5002`） | 红色错误条「处置未生效：黑名单写入失败，已回滚本次名单变更，案件保持『审核中』」；**不得把状态显示为已处置** |
| 审计待重试（`DSP-5004`） | 橙色提示条「处置已生效，审计落库待重试（audit_pending）」 |

### 2.4 展示点 D：`07 审计日志页`（只读，间接展示）

`case.dispose` 动作行由 12 渲染（`auTblR1` 示例：`结论=违规；动作=拦截+拉黑+封禁`）。**本模块只负责写入格式正确**，不负责该页渲染。

## 3. 接口字段

### 3.1 本模块拥有的接口

> 全部要求 `Authorization: Bearer <JWT>`，且角色为 `reviewer`（BR-08-36）。

#### `POST /api/v1/cases/{case_no}/claim` — 认领案件

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `case_no` | path | ✔ | 案件编号 `CASE{yyyyMMdd}{6位序列}` |

**响应**：`{case_no, status:"reviewing", assignee, claimed_at, claim_deadline_at}`
**状态码**：`200` / `404 DSP-4040` / `409 DSP-4003`（状态非 `pending`）/ `409 DSP-4005`（已被他人认领）
**幂等**：同一 `assignee` 重复认领返回 `200` 且不刷新 `claimed_at`。

#### `POST /api/v1/cases/{case_no}/dispose/preview` — 签发二次确认令牌 + 副作用清单

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `conclusion` | enum | ✔ | `violation` / `normal` / `suspicious` |
| `action_types` | array[enum] | ✔ | 去重后 ≥1；取值 `pass` / `block_order` / `blacklist_user` / `ban_device` / `reject_refund` |

**响应**：`{case_no, summary:{...同 2.2 ds1~ds5...}, side_effects:[{seq, code, target, detail}], list_writes_preview:[{list_type, entity_type, entity_value, expire_at}], confirm_token, expires_in:30}`
**状态码**：`200` / `400 DSP-4001` / `422 DSP-4002`（结论与动作不相容）/ `409 DSP-4003` / `409 DSP-4004`（已处置）
**说明**：`confirm_token` 一次性、TTL 30s、**签名绑定** `case_no + conclusion + action_types 有序哈希 + operator`，参数变更即失效。

#### `POST /api/v1/cases/{case_no}/dispose` — 执行处置（核心接口）

**请求**

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `conclusion` | enum | ✔ | `violation` / `normal` / `suspicious` |
| `action_types` | array[enum] | ✔ | ≥1，去重；与 `conclusion` 相容（BR-08-14） |
| `remark` | string | ✔ | **trim 后非空**，≤500 字 |
| `confirm_token` | string | ✔ | 由 `/dispose/preview` 签发；**校验失败一律拒绝**（BR-08-25） |
| `list_writes` | array | | 可选覆盖默认映射（BR-08-20）；元素 `{list_type, entity_type, entity_value, expire_at}`；`list_type` 仅允许 `black` / `gray` |
| `evidence_refs` | array | | 快照 ID / 关联账号列表，落 E09.`evidence_refs` |
| `idempotency_key` | string | | 同 key 重复提交返回**首次**结果，不重复产生副作用 |
| `biz_targets` | object | | 业务单据号 `{order_no, after_sale_no, device_id}`，供 `BizAdapter` 使用；缺省时取该案件 `event_id` 关联的 E01 |

**响应**

| 字段 | 类型 | 说明 |
|---|---|---|
| `case_no` | string | 案件编号 |
| `status` | enum | 成功恒为 `disposed` |
| `action_id` | string | `case_actions._id` |
| `conclusion` / `action_types` / `remark` | — | 回显 |
| `operator` / `operator_role` / `acted_at` | string/string/long | **取自 JWT**，不接受请求体传入（BR-08-37） |
| `list_writes` | array | `[{list_type, entity_type, entity_value, entry_id, status:"active"}]` |
| `biz_sync` | object | `{target:"mock", status:"ok"/"failed", message, retryable:bool}` |
| `audit` | object | `{log_id, hash, prev_hash}` |
| `degraded` | bool | `true` 表示存在待重试的旁路副作用（审计 / 业务同步） |
| `retry_hint` | object \| null | `{biz_sync:bool, audit:bool}` |

**状态码**：`200` / `400 DSP-4001` / `422 DSP-4002` / `409 DSP-4003` / `409 DSP-4004` / `409 DSP-4005` / `422 DSP-4006` / `404 DSP-4040` / `503 DSP-5002`（名单写入失败，**已回滚**）/ `500 DSP-5001`（案件状态写入失败）

#### `POST /api/v1/cases/{case_no}/biz-sync/retry` — 重试业务系统同步

**请求**：`{action_id}`（可选，缺省重试该案件全部未成功的联动）
**响应**：`{action_id, biz_sync, retried_at, attempt_no}`
**状态码**：`200` / `404 DSP-4040` / `409 DSP-4003`（案件未处置，无联动记录）/ `503 DSP-5003`
**幂等**：`attempt_no` 递增，同一 `action_id` 可重复重试；每次重试**追加**一条审计记录，不覆盖原记录。

#### `POST /api/v1/cases/{case_no}/archive` — 归档

**请求**：`{remark?}`；**响应**：`{case_no, status:"archived", archived_at}`
**状态码**：`200` / `409 DSP-4003`（仅 `disposed` 可归档）；角色限 `admin` 或系统定时任务。

#### `GET /api/v1/cases/{case_no}/actions` — 处置流水（供 07 详情页复用）

**响应**：`{case_no, items:[CaseActionDoc...], total}`；**只读**，任何角色均可读（07 复用）。

## 4. 业务规则

> 编号规则：`BR-08-xx`，从 01 连续。每条**可判定、可测**。

### 4.1 建案与认领

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-08-01** | 仅当 `decision ∈ {review, reject}` 时建案；`pass` 不建案。建案 `status=pending`，`risk_score` / `risk_level` / `decision` / `risk_tags` 均取决策时的**冗余快照** | PRD 2.3.4 |
| **BR-08-02** | 建案幂等：同一 `decision_id`（等价 `event_id`）只允许一案，重复触发返回既有案件 | E08 唯一 `event_id` |
| **BR-08-03** | 建案写入 `estimated_loss`（取事件 `amount`，无金额则 `0`），供 11 的资损统计使用 | E08 / G-09 |
| **BR-08-04** | 认领必须是**原子**操作：以 `findAndModify({_id, status:"pending"}, {status:"reviewing", assignee, claimed_at})` 实现，**禁止先查后写** | 防并发重复认领 |
| **BR-08-05** | 认领后写入 `claim_deadline_at = claimed_at + case_claim_timeout_min × 60s`，默认 **30 分钟** | ⚠️ 悬空点 **G-06**（取值由本 Spec 给出，需确认） |
| **BR-08-06** | `assignee` 非当前用户时，禁止处置（`DSP-4005`）；**admin 也不得代为处置**，只能归档 | 09 矩阵 `mr2`（职责分离） |
| **BR-08-07** | 处置人 `operator` / `operator_role` **一律取自 JWT**，请求体传入的同名字段被忽略 | 防伪造留痕 |

### 4.2 状态机

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-08-08** | 唯一合法迁移：`pending --认领--> reviewing --处置--> disposed --归档--> archived`。任何其他迁移（含跨级、回退）一律拒绝 `DSP-4003` | E08 状态机 |
| **BR-08-09** | 状态迁移**必须**伴生一条可追溯记录：`→ reviewing` 写 `risk_cases`（`assignee/claimed_at`）；`→ disposed` 写 `case_actions`；`→ archived` 写 `audit_logs`（`case.archive`）。**禁止无留痕的状态变更** | PRD 2.3.4 |
| **BR-08-10** | **G-06 超时回收**：`reviewing` 且超过 `claim_deadline_at` 未处置的案件，由定时任务（每 60s 扫一次）回收为 `pending`，清空 `assignee` / `claimed_at` | ⚠️ 悬空点 **G-06** |
| **BR-08-11** | 回收事件写入 `audit_logs`（`action="case.recycle"`，`before/after` 记 `assignee` 与状态）。**不写 `case_actions`**——E09 的 `action_type` 枚举中没有「回收」值 | ⚠️ 见第 8 章「新增待确认」 |
| **BR-08-12** | `case_claim_timeout_min` 由 13 系统设置下发；取 `0` 表示**关闭超时回收** | G-06 可配 |

### 4.3 处置结论与联动动作

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-08-13** | 每次处置**有且仅有 1 个** `conclusion`，取值 `violation` / `normal` / `suspicious`；**必填** | E09.conclusion |
| **BR-08-14** | **结论与动作相容矩阵**：`violation` → 至少 1 个紧动作（`block_order`/`blacklist_user`/`ban_device`/`reject_refund`），禁止只有 `pass`；`normal` → **只允许** `[pass]`；`suspicious` → 只允许 `[pass]`，或 `[pass] + 写灰名单`。违反返回 `DSP-4002` | E09 / 原型 `wbNote` 2 |
| **BR-08-15** | `action_types` 去重后**至少 1 项**；空数组拒绝 `DSP-4001` | 原型「可多选 *」 |
| **BR-08-16** | `remark` **必填**：trim 后非空且 ≤500 字；未填或超长拒绝 `DSP-4001`。备注**原样**写入 `case_actions.remark` 与审计 `after` | PRD 2.3.3 / 2.3.7-2 |
| **BR-08-17** | `pass`（放行）是一条**独立动作**，落 `case_actions.action_type="pass"`；`normal` 结论必须走 `pass` | E09 枚举 |
| **BR-08-18** | 处置**不可撤销**：不提供 undo / 回滚处置接口。纠错必须走 06 的反向名单操作（移除黑名单）或人工再处置新案件，并各自留痕 | PRD 2.3.4「不可篡改」 |

## 5. 异常处理

| 错误码 | 场景 | HTTP | 处理策略 | 用户可见提示 |
|---|---|---|---|---|
| `DSP-4001` | 处置参数非法（结论缺失 / 动作空 / 备注空或超长） | 400 | 拒绝，**无任何副作用** | 「请选择处理结论、至少一项处置动作并填写处置原因备注」 |
| `DSP-4002` | 结论与动作不相容（如 `normal` + `block_order`） | 422 | 拒绝 | 「『确认为正常』不可与拦截类动作同时提交」 |
| `DSP-4003` | 案件状态不允许该操作 | 409 | 拒绝 | 「案件当前状态为『已处置』，无法认领 / 重复处置 / 归档」 |
| `DSP-4004` | 重复处置 | 409 | 拒绝；同 `idempotency_key` 时返回首次结果 | 「该案件已完成处置」 |
| `DSP-4005` | 非当前认领人处置 | 409 | 拒绝 | 「案件由 reviewer02 认领，请先由本人处置或等待超时回收」 |
| `DSP-4006` | 确认令牌无效 / 过期 / 与参数不匹配 | 422 | 拒绝，**不执行任何副作用** | 「确认已过期或参数已变更，请重新确认」（前端自动回退到弹窗） |
| `DSP-4040` | 案件不存在 | 404 | 拒绝 | 「案件不存在或已归档」 |
| `DSP-5001` | 案件状态写入失败（Mongo 不可用） | 500 | 整体失败；已写的名单条目**回滚**；提示重试 | 「处置失败：数据库不可用，本次未生效，请重试」 |
| `DSP-5002` | **名单库联动写入失败**（紧操作） | 503 | **fail-closed**：回滚本次名单写入、案件保持 `reviewing`、不置 `disposed`、不写成功态 `case_actions` | 「处置未生效：黑名单写入失败，已回滚本次名单变更」 |
| `DSP-5003` | 业务系统同步失败（`BizAdapter` 异常 / 无真实系统） | 200 | 处置**保留**，`biz_sync_result.status="failed"`，入重试队列，`degraded=true` | 「处置已生效，业务系统同步失败，已加入重试队列」+「重试同步」按钮 |
| `DSP-5004` | 审计哈希链写入失败 | 200 | 处置**保留**，置 `audit_pending=true`，入重试队列，`degraded=true` | 「处置已生效，审计落库待重试」 |
| `DSP-5005` | 处置流水 `case_actions` 落库失败 | 500 | 整体失败；名单回滚；案件保持 `reviewing` | 「处置失败：流水未落库，本次未生效」 |

> **fail-closed 原则（本模块重要）**：**紧操作**（拉黑用户 / 封禁设备 / 拦截订单 / 驳回退款）依赖的名单写入一旦失败，
> **必须明确报错并回滚**，绝不允许「接口返回成功但黑名单没生效」。
> 与之相对，**旁路副作用**（`BizAdapter` 同步、审计落库）失败时**不撤销**已生效的处置，但必须**显式标记 + 可重试**，不允许静默成功。
