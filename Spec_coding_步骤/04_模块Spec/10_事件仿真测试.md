## 1. 模块定位

| 项 | 内容 |
|---|---|
| **职责** | ① 测试用例模板管理与载入 ② 结构化事件参数表单 ③ **复用真实决策链路**执行单条检测 ④ **五步链路单步回溯**（含每步耗时）⑤ 批量回放与误伤统计 ⑥ 用例保存复用 |
| **触发时机** | 人工操作（策略师验证新规则、审核员复现历史作弊） |
| **上游** | 00 公共基础；**05 规则决策引擎**（`POST /engine/evaluate`）；04 特征计算；03 事件校验 |
| **下游** | 无（终端工具页）；其产出的 `sim_runs.trace` 可被引用为规则上线依据 |
| **对应 PRD** | **2.3.3 事件仿真测试页**、2.3.5「仿真测试模块」、2.3.7-3「规则上线与调优流程」、2.3.10「仿真测试页完成单条事件的模拟检测与判定链路回溯」 |
| **对应实体** | E17 `sim_cases`、E18 `sim_runs`；**只读**消费 E01/E02/E03/E04/E05/E07 |
| **对应原型** | `05_事件仿真测试页.pen` |
| **对应架构决策** | AD-01（决策链路）、AD-07（条件树） |

**本模块明确不做的事**：
- **禁止另写一套判定逻辑**——必须调用 05 的 `POST /api/v1/engine/evaluate`。否则"仿真通过"不能证明线上会通过，验证即失去意义
- 不产生真实业务副作用（不建案件、不改名单、不写 `decisions`/`decision_hits`）
- 不写入真实特征窗口（见 BR-10-06）

## 2. 页面结构

对应原型 `05_事件仿真测试页.pen`（画布 1440×1440）。左栏宽 430，右栏弹性。

### 2.1 左栏上 · 测试用例模板 `tplCard`

| 元素 | 说明 |
|---|---|
| 标题「测试用例模板」 | — |
| 用例列表（纵向 4 条，高 40，可点击） | 每条显示用例名 + 预期决策（如「羊毛党批量领券（预期 Reject）」） |
| 选中态 | 当前用例高亮（背景 `#F0F0F0` + 左侧品牌色竖条） |
| 「把当前参数存为新用例」按钮 | plain，占满宽度 |

**默认内置用例（4 条，由种子脚本灌入 `sim_cases`）**

| # | 用例名 | 分类 | 预期决策 |
|---|---|---|---|
| 1 | 羊毛党批量领券 | `coupon_abuse` | `reject` |
| 2 | 恶意退款欺诈 | `aftersale_abuse` | `review` |
| 3 | 正常下单支付 | `normal` | `pass` |
| 4 | 代理 IP 聚集登录 | `boundary` | `review` |

**空态**：无用例时显示「暂无用例，可手动填写参数后保存」。

### 2.2 左栏下 · 事件参数表单 `simForm`

| 字段 | 控件 | 必填 | 说明 |
|---|---|:--:|---|
| `event_type` | 下拉 | ✔ | 五类事件之一 |
| `user_id` | 输入 | ✔ | 如 `U000128` |
| `device_id` | 输入 | | 如 `D8F2A1C4` |
| `ip` | 输入 | | IPv4/IPv6 |
| `phone` | 输入 | | 若填则参与名单匹配 |
| `address_id` | 输入 | | 如 `ADDR-7712` |
| `amount` | 输入（数字） | | **单位：分**；输入框标注 `amount(分)` |
| `scene_extra` | 多行文本（等宽字体） | | JSON 字符串；按 `event_type` 变化，如领券需 `coupon_id/face_value/activity_id` |

**按钮组**：`▶ 执行检测`（primary）/ `重置`（ghost）/ `批量回放此用例 × 20`（plain）

**表单校验**：`event_type` 与 `user_id` 必填；`scene_extra` 必须是合法 JSON，否则标红并提示（`SIM-4002`）。

### 2.3 右栏 · 判定链路单步回溯 `chainCard`

五个步骤块，纵向排列，每块显示：步骤徽标 + 步骤名 + 结论行（含耗时）。样式随结果变化。

| 步骤 | 标题 | 结论行示例 | 配色 |
|---|---|---|---|
| 1 | 事件校验 | `通过 · event_id=EVT…218 · 耗时 1ms` | 通过=绿；失败=红 |
| 2 | 特征提取（18 项） | `完成 · 耗时 3ms · 缺失 0 项` | 缺失>0 时转橙 |
| — | 步骤 2 附特征小表 | 4~6 项关键特征 KV | — |
| 3 | 名单快速过滤 | `未命中黑白名单 · 继续规则判定` | 命中白=绿、命中黑=红 |
| 4 | 规则命中链路 | `命中 3 条 · 累计 86 分` | 有命中=红/橙，无命中=灰 |
| — | 步骤 4 附命中表 | 规则 / 分值 / 原因 | — |
| 5 | **最终决策** | `score=86 · level=high · decision=REJECT · 总耗时 6ms` | 按决策着色：pass 绿底 / review 橙底 / reject 红底 |

**链路未执行时**：五块显示灰色骨架 + 「点击"执行检测"开始」。

**执行中**：步骤块按顺序逐个点亮（体现"单步呈现"），**不是一次性全亮**。

### 2.4 批量回放结果（执行批量后追加显示）

| 指标 | 说明 |
|---|---|
| 命中数 | 与预期决策**一致**的条数 |
| 未命中数 | 与预期**不一致**的条数 |
| 与预期不符数 | 单列（即未命中数），并给出**前 3 条不符样例**的 `sim_run` 链接 |
| 误伤统计 | 预期 `pass` 但被判 `review/reject` 的条数（**误伤**，规则调优最关心） |

**配色**：误伤数 > 0 时标橙并提示「存在误伤，建议复核规则阈值」。

## 3. 接口字段

### 3.1 `GET /api/v1/sim/cases` — 用例列表

**响应**：`{ items: [{case_id, name, category, expected_decision, description, event_template, created_by, created_at}] }`

### 3.2 `POST /api/v1/sim/cases` — 保存用例

**请求**

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `name` | string | ✔ | 2~64 字符 |
| `category` | enum | ✔ | `coupon_abuse` / `aftersale_abuse` / `normal` / `boundary` / `other` |
| `expected_decision` | enum | ✔ | `pass` / `review` / `reject` |
| `description` | string | | ≤200 字 |
| `event_template` | object | ✔ | 完整事件体（结构同 `POST /events` 的 `event`） |

**响应**：`{case_id, created_at}`

### 3.3 `POST /api/v1/sim/run` — 单条仿真执行（**核心接口**）

**请求**

| 字段 | 类型 | 必填 | 说明 |
|---|---|:--:|---|
| `event` | object | ✔ | 事件体 |
| `case_id` | string | | 来源用例（用于预期比对） |
| `trace` | bool | | 默认 `true`（本模块需要链路明细） |

**响应 `data`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `run_id` | string | 本次执行记录 `SIMR*` |
| `steps` | array | **五步链路**：`[{seq, name, status, detail, elapsed_ms, payload}]` |
| `features` | object | 步骤 2 的 18 项特征 |
| `missing_features` | array | 缺失特征 |
| `list_hit` | object | 步骤 3 结果 `{hit, list_type, entity_type, entity_value}` |
| `hits` | array | 步骤 4 命中规则明细 |
| `rule_score` / `final_score` | int | 分值 |
| `risk_level` / `decision` | enum | 等级与动作 |
| `expected_decision` | enum \| null | 预期（来自用例）；用于前端显示"是否符合预期" |
| `matched_expected` | bool \| null | 是否与预期一致 |
| `elapsed_ms` | int | 总耗时 |
| `dry_run` | bool | 恒 `true`（仿真不落业务库） |

**`steps[].name` 取值固定**：`event_validate` / `feature_extract` / `list_filter` / `rule_evaluate` / `arbitrate`

**状态码**：`200` / `400`（`SIM-4001` 事件体非法）/ `422`（`SIM-4002` `scene_extra` 非合法 JSON）/ `503`（`SIM-5001` 决策引擎不可用）

### 3.4 `POST /api/v1/sim/batch` — 批量回放

**请求**：`{case_id, repeat: 20, seed: 42}`

**响应**

| 字段 | 类型 | 说明 |
|---|---|---|
| `total` | int | 执行条数 |
| `matched` | int | 与预期一致 |
| `mismatched` | int | 与预期不一致 |
| `false_positive` | int | **误伤数**（预期 pass 但被拦/转审） |
| `mismatch_samples` | array | 前 3 条不符样例 `[{run_id, decision, expected_decision}]` |
| `elapsed_ms` | int | 总耗时 |

### 3.5 `GET /api/v1/sim/runs/{run_id}` — 查看历史执行详情

**响应**：同 3.3 的 `data`（`trace` 从 `sim_runs.trace` 还原）。

**状态码**：`404`（`SIM-4004`）

## 4. 业务规则

### 4.1 与真实链路的一致性（**本模块的核心价值**）

| 编号 | 规则 |
|---|---|
| **BR-10-01** | 仿真**必须调用** 05 的 `POST /api/v1/engine/evaluate`（或同进程内的 `decide()` 函数），**禁止另写任何判定、条件求值或计分逻辑** |
| **BR-10-02** | 仿真结果必须与直接调用决策引擎的结果**逐字段一致**（含 `rule_score`、`hits`、`decision`） |
| **BR-10-03** | 仿真使用的规则集必须是**当前生效版本**（`status=enabled`），不得使用快照或缓存副本 |
| **BR-10-04** | 仿真需回传 `rule_versions`，便于说明"这次结论是基于哪一版规则" |

### 4.2 数据隔离（**极易出错的点**）

| 编号 | 规则 |
|---|---|
| **BR-10-05** | 仿真**不产生业务副作用**：不写 `risk_events`/`decisions`/`decision_hits`/`risk_cases`，不改名单，不建图 |
| **BR-10-06** | **仿真事件绝不写入真实特征窗口**（04 的 `FeatureStore`）。仿真只**读取**当前窗口状态计算特征。理由：否则仿真会污染线上特征，导致后续真实事件的判定被扭曲（例如仿真灌 20 条就抬高 `device_user_cnt`） |
| **BR-10-07** | 仿真必须如实记录"特征是基于**当前真实窗口**"这一前提；若窗口为空，特征会偏低，页面需提示「当前无历史窗口数据，特征可能偏低」 |
| **BR-10-08** | 仿真**写 `sim_runs`**（仅执行记录，用于回溯与批量统计），这是唯一被写入的集合 |
| **BR-10-09** | 仿真接口必须带 `dry_run=true` 语义；**不得因参数遗漏而误落业务库**（服务端强制，不信任前端传参） |

### 4.3 链路回溯

| 编号 | 规则 |
|---|---|
| **BR-10-10** | 五步必须**每步独立记录**：名称、状态（`ok`/`failed`/`skipped`）、结论摘要、耗时、结构化 `payload` |
| **BR-10-11** | 步骤 3（名单过滤）命中白/黑名单时，步骤 4 状态为 **`skipped`**（不是 `ok`）——如实反映"未求值规则"（对齐 05 的 BR-05-02/03） |
| **BR-10-12** | 每步耗时之和与总耗时的差值需可解释（其余为编排开销）；差值 > 50% 时记录告警 |
| **BR-10-13** | 链路数据完整落 `sim_runs.trace`，刷新页面后仍可完整回看 |

### 4.4 前端呈现

| 编号 | 规则 |
|---|---|
| **BR-10-14** | 步骤块**按顺序逐个点亮**（体现"单步呈现"），不得一次性全部渲染完成态 |
| **BR-10-15** | 失败步骤必须**显式标红**并显示原因，后续步骤标记为"未执行"，不得跳过显示 |
| **BR-10-16** | 决策结果用决策配色（pass 绿 / review 橙 / reject 红）**贯穿**步骤 5 与结果徽标，保持一致 |

### 4.5 用例与可复现

| 编号 | 规则 |
|---|---|
| **BR-10-17** | 用例模板必须包含**完整事件体**，载入即填充整个表单，不允许只填部分字段 |
| **BR-10-18** | 批量回放支持 `seed` 参数；**同一 `seed` + 同一用例必须产生完全一致的结果**（演示可复现） |
| **BR-10-19** | 批量回放的默认条数 20，上限 200（防止误操作打爆服务） |
| **BR-10-20** | 用例删除采用**软删除**（`status=archived`），保留历史 `sim_runs` 的可追溯性 |
| **BR-10-21** | 只有 `reviewer` 与 `strategist` 可使用仿真（`admin` 无此权限，见 01 的权限矩阵） |
| **BR-10-22** | 策略师在**启用规则前必须先跑通仿真**（对齐 PRD 2.3.7-3 的流程）；模块 06 的"送仿真验证"按钮跳转到本页并预填规则相关用例 |

## 5. 异常处理

| 错误码 | 场景 | HTTP | 用户可见提示 | 处理 |
|---|---|---|---|---|
| `SIM-4001` | 事件体缺必填字段 | 400 | 「事件参数不合法：缺少 xxx」 | 步骤 1 标红，链路停止 |
| `SIM-4002` | `scene_extra` 非合法 JSON | 422 | 「扩展参数不是合法 JSON」 | 表单该字段标红 |
| `SIM-4003` | 用例名重复 | 409 | 「已存在同名用例」 | 提示改名或覆盖 |
| `SIM-4004` | 执行记录不存在 | 404 | 「未找到该次仿真记录」 | — |
| `SIM-4005` | 批量回放条数超上限 | 422 | 「单次最多回放 200 条」 | — |
| `SIM-5001` | 决策引擎不可用 | 503 | 「决策引擎暂时不可用，无法仿真」 | 整体失败并提示；**不得降级为"用简化逻辑算一下"**（会误导结论） |
| `SIM-5002` | 链路记录落库失败 | 200 | 「本次结果已返回，但记录保存失败」 | 结果照常展示，提示可能无法回看 |
| `SIM-5003` | 仿真超时（>5s） | 504 | 「执行超时，请简化参数后重试」 | 中断并标记失败步骤 |

> **不放宽**：`SIM-5001` 时**绝不允许**用"简化判定"给出结论。仿真的价值在于"与线上一致"，降级即说谎。

## 6. 文件规划

```
app/
├── api/
│   └── sim_api.py             # /sim/cases（GET/POST）、/sim/run、/sim/batch、/sim/runs/{id}
├── services/
│   └── sim_service.py         # 链路编排：分步调用 03/04/05，收集 trace，比对预期
├── engine/
│   └── tracer.py              # 链路追踪器：步骤记录、耗时统计、payload 收集
├── repos/
│   ├── sim_case_repo.py       # sim_cases 读写（含软删除）
│   └── sim_run_repo.py        # sim_runs 写入与查询
└── schemas/
    └── sim_schema.py          # 用例/执行/批量 请求响应模型

static/
└── js/
    ├── views/sim.js           # 仿真页视图：表单、用例、链路渲染、批量结果
    └── chain.js               # 五步链路渲染组件（含逐块点亮的时序）
```

| 文件 | 职责 | 可单测 |
|---|---|---|
| `engine/tracer.py` | 链路步骤记录与耗时 | ✔ |
| `services/sim_service.py` | 编排与预期比对 | ✔（重点：与线上一致性） |
| `sim_api.py` | 路由与参数校验 | 集成 |
| `sim_case_repo.py` / `sim_run_repo.py` | 持久化 | 集成 |
| `views/sim.js` / `chain.js` | 表单与链路呈现 | 手工/浏览器 |

**测试重点**：① 仿真与直连引擎结果一致（BR-10-02）② 仿真不写窗口、不落业务库（BR-10-06/09）③ 同 seed 批量结果可复现（BR-10-18）。

## 7. 验收标准

## 8. 本模块遗留与待确认
