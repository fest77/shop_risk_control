## 1. 模块定位

| 项 | 内容 |
|---|---|
| **职责** | 五类事件接收与 Pydantic v2 校验 → `event_id` 生成 → **幂等防重** → 分发决策链路（依次调用 04、05）→ **同步返回决策**；附带**事件流模拟器**（四模式 + 固定随机种子） |
| **触发时机** | ① 业务端 / 模拟器每次 POST 事件（高频路径，本模块自身开销目标 ≤ 1ms）；② 管理员启停模拟器（低频） |
| **上游** | 00 公共基础（枚举 `event_type`、错误码、`AsyncMongoClient`）、01 鉴权（模拟器控制接口限 `admin`） |
| **下游** | **04 特征计算引擎**、**05 规则决策引擎**；异步旁路：11 指标桶、12 审计、08 案件（由各归属模块负责，非本模块） |
| **对应 PRD** | 2.3.1 实时事件接入、**2.3.6 事件网关模块**、**2.3.7-1 实时交易风控检测流程**、2.3.4 五类事件支持、2.3.10 验收第 1 条 |
| **对应实体** | **写 E01 `risk_events`**（本模块唯一写入的集合）；**只读** E02 `feature_snapshots` / E03 `decisions` / E04 `decision_hits`（仅 `GET /events/{event_id}` 详情聚合） |
| **对应原型** | `05_事件仿真测试页.pen` · **事件参数表单**（主展示点）+ 步骤 1「事件校验」；`08_系统设置页.pen` · 事件流模拟器状态行 |
| **对应架构决策** | AD-01（同步决策 / 异步落库）、AD-02（TTL 缓存思路复用于幂等缓存）、`00_模块划分与边界` §3.3 三段分工 |

**本模块明确不做的事**

- **不做特征计算与窗口维护**（归 04）；**不做名单匹配、条件树求值、打分与仲裁**（归 05）。本模块对这两步只做**调用与异常兜底**。
- **不写除 `risk_events` 之外的任何集合**：`feature_snapshots` 归 04、`decisions`/`decision_hits` 归 05、`metric_buckets` 归 11、`audit_logs` 归 12、`risk_cases` 归 08。
- 不做仿真页的**链路回放编排**（5 步可视化归 10）；本模块只提供**事件字段与校验规则**（schema 唯一所有者）+ **连续事件流生成器**。
- 不实现名单缓存、不实现规则版本管理（归 05 / 06）。

**链路位置**（`00` §3.3 裁定，本模块严格遵守）：

```
事件 → [03 校验/幂等] → [04 特征快照] → [05 名单过滤+规则+仲裁] → 同步返回决策
                                     ↓ 异步（各归属模块）
                   [11 指标桶] [12 审计] [08 案件] [09 图谱边]
```

## 2. 页面结构

引擎无独占页面。其**输入契约**与**输出字段**出现在三个页面的四处位置，字段绑定如下。

### 2.1 展示点 A：`05_事件仿真测试页` · 事件参数表单（主展示点，Schema 定义归本模块）

> 页面渲染与提交归 10，但**字段清单、必填标记、格式约束、错误文案**由本模块定义 —— 因为 03 是事件 Schema 的唯一所有者。

| 原型元素 | 绑定字段 | 类型 | 必填 | 约束（本模块校验） |
|---|---|---|:--:|---|
| `sfTypeS` | `event_type` | enum | ✔ | 五值之一：`login` / `coupon_receive` / `order_create` / `order_pay` / `after_sale_apply` |
| `sfUserI` | `user_id` | string | ✔ | 长度 3~32，`^[A-Za-z0-9_-]+$` |
| `sfDevI` | `device_id` | string | 见 G-07 | 长度 3~64 |
| `sfIpI` | `ip` | string | 见 G-07 | 合法 IPv4 / IPv6（`ipaddress` 校验，拒绝内网以外的非法串） |
| `sfPhoneI` | `phone` | string | 否 | 11 位手机号；**入库前脱敏**（`138****6621`） |
| `sfAddrI` | `address_id` | string | 见 G-07 | 长度 3~32 |
| `sfAmtI` | `amount` | int | 见 G-07 | **单位分**，正整数（`> 0`）；与 `scene_extra` 金额字段必须一致（BR-03-06） |
| `sfExtraBox` | `scene_extra` | object | 见 G-07 | 按 `event_type` 的判别联合（表 2.2）；出现不属于该类型的键 → 拒绝 |
| （页面隐含） | `biz_no` | string | 否 | 业务单据号；建议与 `scene_extra` 中的单号一致 |
| （页面隐含） | `ts` | long | 否 | 毫秒时间戳；**省略时由网关补 `received_at`** |
| （页面隐含） | `source` | string | 否 | 默认 `manual_sim`（页面手填）/ `mock_biz`（模拟器） |

**必填标记的动态性（与原型冲突，需 10 配合）**：原型表单仅给 `event_type *` 与 `user_id *` 打了星号，但 G-07 的取值要求**按事件类型追加必填**（表 2.2）。页面须在切换 `event_type` 时**动态重绘星号与 `scene_extra` 模板键**，否则用户会在提交后才被 400 拒绝。

### 2.2 展示点 B：`05_事件仿真测试页` · 步骤 1「事件校验」

| 原型元素 | 绑定字段 | 文案规则 |
|---|---|---|
| `s1h` 步骤标题 | — | 固定「步骤 1 · 事件校验」 |
| 校验结论行 | `validation.passed` + `event_id` + `elapsed_ms` | 通过：`通过 · event_id=EVT20260923000218 · 耗时 1ms`；失败：`未通过 · 缺失字段：ip · 耗时 1ms`（红色） |
| 失败明细 | `validation.errors[]` | 逐条列出 `EVT-4xxx` 错误码 + 字段名 + 中文说明 |

**归属说明**：步骤 1 的结论由本模块产出并写入 `trace[0]`（E18 `sim_runs.trace`），由 10 渲染。

### 2.3 展示点 C：`08_系统设置页` · 吞吐与接口健康度

| 原型元素 | 绑定字段 | 说明 |
|---|---|---|
| `hcTblR2C1/C2` 事件流模拟器状态 | `GET /api/v1/simulator/status` → `running` / `mode` / `rate` / `seed` / `emitted_total` | 文案示例：`运行中` / `模式=羊毛党 · 5 events/sec · seed=42`；停止时显示 `已停止` |
| `hc1V` 实时 QPS | 11 监控指标引擎提供 | 本模块只上报事件计数，**不自己算 QPS**（避免与 11 口径打架） |
| `hcTblR0C2` DB 集合数 | 00 公共基础提供 | `risk_events` 由本模块负责建索引（见 §6） |

**归属说明**：模拟器的**启停控制**归本模块（`/api/v1/simulator/*`），页面只读展示归 13 系统设置模块。

### 2.4 展示点 D：`02_风控态势大盘` · 实时事件流（SSE）的 `event_type` 列

SSE 数据由 11 提供，但**五类事件枚举的唯一守门人是本模块** —— 未通过 03 校验的 `event_type` 不可能进入 `risk_events`，因此大盘 `streamTblH1` 列的取值域天然收敛为 5 值。

**空态与错误态**：模拟器未启动时 `08` 状态行显示 `已停止` 且置灰；`05` 表单在 `event_type` 变更后若 `scene_extra` 未同步，页面显示占位提示而非静默提交。

## 3. 接口字段

### 3.1 `POST /api/v1/events` — 单条事件接入（**同步返回决策**）

**请求**（`Content-Type: application/json`）

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `event_id` | string | 否 | **幂等键**（可选，见 BR-03-09）；提供时须匹配 `^EVT\d{8}\d{12}$` |
| `event_type` | enum | ✔ | 五值之一 |
| `user_id` | string | ✔ | 见 §2.1 |
| `biz_no` | string | 否 | 业务单据号 |
| `device_id` / `ip` / `phone` / `address_id` | string | 见 G-07 | 见 §2.1 |
| `amount` | int | 见 G-07 | 单位分，正整数 |
| `scene_extra` | object | 见 G-07 | 判别联合；**未知键拒绝**（BR-03-05） |
| `ts` | long | 否 | 毫秒；省略时取服务端 `now` |
| `source` | string | 否 | 默认 `mock_biz` |

**按 `event_type` 的必填字段集（G-07 取值，本 Spec 固化）**

| `event_type` | 基础必填 | `scene_extra` 必填键 | `scene_extra` 可选键 |
|---|---|---|---|
| `login` | `user_id`、`device_id`、`ip` | `login_type`(pwd/sms/scan) | `ua`、`success`(默认 true) |
| `coupon_receive` | `user_id`、`device_id`、`ip`、`amount` | `coupon_id`、`activity_id` | `face_value`、`batch_id` |
| `order_create` | `user_id`、`device_id`、`ip`、`address_id`、`amount` | `order_no`、`sku_count` | `total_amount`、`address_id` |
| `order_pay` | `user_id`、`amount` | `order_no`、`pay_channel` | `pay_amount`、`card_tail` |
| `after_sale_apply` | `user_id`、`biz_no`、`amount` | `after_sale_no`、`order_no`、`reason_code` | `refund_amount`、`received_goods` |

> ⚠️ 该必填集**PRD 未定义**（悬空点 **G-07**），本 Spec 按电商常识取值并固化；`after_sale_apply` 另强制要求 `biz_no`（售后单号），便于案件关联。

**响应**（`200`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `event_id` | string | 最终事件编号（客户端未传时为网关生成） |
| `received_at` | long | 接收时间戳（毫秒） |
| `duplicate` | bool | 是否幂等命中（首次为 `false`） |
| `persisted` | bool | `risk_events` 是否已异步落库完成（通常 `false`，见 BR-03-18） |
| `degrade` | object \| null | `{degraded: bool, reason: str, stage: "feature"\|"rule"\|"timeout"}`；正常时为 `null` |
| **决策块** | object | `rule_score` 起至 `engine_version` 止，**与 05 §3.1 逐字段一致**（`list_hit`/`rule_score`/`model_score`/`final_score`/`risk_level`/`decision`/`hit_rule_count`/`hits`/`rule_versions`/`engine_version`/`snapshot_id`/`elapsed_ms`） |

**契约冻结**：本模块**不得自行拼装**决策块；必须直接透传 05 的返回值（`00` §3.3）。

**状态码**：`200` 成功（含幂等命中）／`400` 校验失败／`409` `event_id` 载荷冲突／`422` 按类型必填缺失／`503` 下游不可用（**返回 `review`，不返回 `pass`**）

### 3.2 `POST /api/v1/events/batch` — 批量接入（模拟器 / 压测）

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `events` | array | ✔ | 单批 1~500 条；> 500 → `EVT-4010` |
| `verbose` | bool | 否 | 默认 `false`；`true` 时返回逐条结果（仅压测/调试用，演示链路不开启） |

**响应**：`{total, pass_cnt, review_cnt, reject_cnt, failed_cnt, elapsed_ms, results?}`。
**逐条语义**：批内**逐条走同一决策链路**（非并发批量落库），任一条校验失败**只计入 `failed_cnt` 并在 `results` 中标注，不影响其余条目**（BR-03-16）。

### 3.3 `GET /api/v1/events/{event_id}` — 事件详情（聚合读，三处只读）

**响应**：`event`（E01 原文，`phone` 已脱敏）+ `snapshot`（E02，含 `missing_features`）+ `decision`（E03）+ `hits`（E04）。
**状态码**：`200` / `404 EVT-4404`（异步落库尚未完成时提示 `500ms 后重试`）。
**边界说明**：本接口对 E02/E03/E04 **只读**，不构成越界写入。

### 3.4 事件流模拟器控制接口（本模块独有）

| 方法 | 路径 | 角色 | 说明 |
|---|---|---|---|
| `POST` | `/api/v1/simulator/start` | admin | 启动模拟器任务 |
| `POST` | `/api/v1/simulator/stop` | admin | 停止并返回本次汇总 |
| `GET` | `/api/v1/simulator/status` | admin | 运行状态（08 页只读展示） |

**`start` 请求**

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `mode` | enum | ✔ | `normal`（正常流）/ `wool`（羊毛党）/ `brush`（刷单）/ `refund`（恶意退款） |
| `rate` | number | ✔ | `0.1 ~ 200` events/sec |
| `seed` | int | ✔ | **固定随机种子**，默认 `42`；决定账号池、设备/IP 池与事件序列 |
| `max_events` | int | 否 | 默认 `500`，上限 `20000`；与 `duration_sec` 二者取先到者 |
| `duration_sec` | int | 否 | 默认 `60`，上限 `600` |
| `anchor_ts` | long | 否 | 虚拟时钟锚点；省略时取 `now - duration_sec*1000`（见 BR-03-25） |

**`status` 响应**：`{running, mode, rate, seed, anchor_ts, emitted, emitted_total, decision_counts{pass,review,reject,failed}, started_at, last_error}`

## 4. 业务规则

> 编号 `BR-03-xx`，从 01 连续。每条可判定、可测。

### 4.1 接收与校验

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-03-01** | 请求体必须是 JSON 对象；非对象/非法 JSON → `EVT-4001` | 本模块定义 |
| **BR-03-02** | `event_type` 必须属于五类枚举，否则 `EVT-4003`（**枚举不在网关之外定义**） | PRD 2.3.4 |
| **BR-03-03** | 按表 3.1 的**类型必填集**校验；缺失 → `422 EVT-4004`，响应必须**逐字段列出缺失名** | 悬空点 G-07 |
| **BR-03-04** | 字段级格式校验：`ip` 用 `ipaddress`、`amount` 为 `> 0` 整数、`ts` 为毫秒整数、`phone` 为 11 位、`user_id` 匹配字符集；违反 → `EVT-4005` | 本模块定义 |
| **BR-03-05** | `scene_extra` 中**出现不属于该 `event_type` 的键** → `EVT-4006`（防前端模板串味） | E01 `scene_extra` 设计 |
| **BR-03-06** | `amount` 与 `scene_extra` 金额字段（`face_value`/`total_amount`/`pay_amount`/`refund_amount`）**同时提供且不等** → `EVT-4007`；只提供其一 → 双向补齐 | 避免双口径歧义 |
| **BR-03-07** | `ts` 省略时取服务端 `now`；`ts > received_at + 60s`（时钟超前）→ `EVT-4005` | 本模块定义 |
| **BR-03-08** | `ts < now - long_window`（1440 分钟，G-02）视为**迟到事件**：仍落 `risk_events`，但**入滑窗会污染窗口语义**，故标记 `late_arrival=true` 并**直接转 `review`**（fail-closed） | 与 04 窗口语义协同 |

### 4.2 `event_id` 生成与幂等

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-03-09** | 客户端**可传** `event_id` 作为幂等键；未传时由网关注册表生成，格式 `EVT{yyyyMMdd}{12位序列}` | E01 + 概要设计 §6「幂等」 |
| **BR-03-10** | 12 位序列 = **当日全局自增**；进程重启后通过查询 `risk_events` 当日最大 `_id` 恢复起点，保证不重号 | E01 主键设计 |
| **BR-03-11** | 幂等判定基于**内存 TTL 缓存**（`event_id → 首次响应体`，TTL 24h，容量 20000，LRU 淘汰）；命中且**载荷哈希一致** → 返回首次响应并置 `duplicate=true`，**不重复计分、不重复落库** | 概要设计 §6 |
| **BR-03-12** | 同一 `event_id` 但**载荷哈希不同** → `409 EVT-4009`（同一编号承载不同事实属数据事故） | 本模块定义 |
| **BR-03-13** | 内存缓存未命中时，以 `risk_events._id` 的**唯一索引**作为最终兜底：插入冲突即判定重复，返回 `duplicate=true` 且**不含决策块**，提示调用方改用 `GET /api/v1/events/{event_id}` | E01 索引 |
| **BR-03-14** | 幂等缓存**必须在返回响应之前写入**（同步写入、临界区内零 `await`），否则并发重复提交会穿透 | 本模块定义 |

### 4.3 分发与同步返回

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-03-15** | 分发顺序**严格串行**：`04.observe_and_compute()` → `05.decide(snapshot)`。本模块不并发调用两者 | `00` §3.3（见 §8 待确认 N-03-2） |
| **BR-03-16** | 批量接口**逐条串行走同一链路**；单条失败不中断批次 | 本模块定义 |
| **BR-03-17** | 决策结果**同步返回**；`risk_events` 的写入**异步**提交（AD-01） | AD-01 / PRD 2.3.7-1 |
| **BR-03-18** | 异步落库失败**不回滚决策**：仍返回 200 + 决策块，落库任务进重试队列并告警 | 概要设计 §6 一致性 |
| **BR-03-19** | 本模块只上报事件计数与链路耗时；QPS / 拦截率等**口径计算归 11** | `00` §3.2 精神 |
| **BR-03-20** | 本地事件计时埋点：`t_validate`、`t_feature`、`t_rule`、`t_total`，随 `EventTiming` 上报 11 与 12 | 概要设计 §6 可观测 |

### 4.4 降级（fail-closed）

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-03-21** | **04 抛异常 / 返回不可用** → 本模块返回 `decision=review`、`degrade={degraded:true, stage:"feature"}`、`rule_score=0`、`hits=[]`；**绝不返回 `pass`** | fail-closed 硬要求 |
| **BR-03-22** | **05 抛异常** → 同上，`stage:"rule"` | fail-closed |
| **BR-03-23** | 同步链路超时预算 **200ms**（值取自 08 页「决策链路超时（毫秒）＝200」）：`asyncio.wait_for` 超时 → `stage:"timeout"`，并**取消未完成的下游协程** | 08 运行参数 / 与 05 `RUL-5004` 对齐 |
| **BR-03-24** | 降级时**必须仍写入 `risk_events`**（保住不可篡改的原始证据），并在响应中给出 `degrade.reason` 供人工复核定位 | E01 设计原则 1 |

### 4.5 事件流模拟器

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-03-25** | 模拟器使用**虚拟时钟**：`ts = anchor_ts + round(i*1000/rate)`；默认 `anchor_ts = now - duration_sec*1000`，使事件落在当前时间附近**同时序列可复现** | 概要设计 §3.4 可复现性要求 |
| **BR-03-26** | 随机源为 `random.Random(seed)` + `numpy.random.Generator(PCG64(seed*1000+mode_index))`；**禁止使用全局 `random`**，避免与其它模块串味 | 概要设计 §3.4 |
| **BR-03-27** | 四种模式的账号/设备/IP/地址池**全部由 `seed` 派生**，不使用 Faker 的默认随机源（Faker 亦须 `seed_instance(seed)`） | 同上 |
| **BR-03-28** | 模式定义：`normal` 常态流量（多数 pass）；`wool` 10 个**新账号 + 同 `device_id` + 同 `ip`**，60s 内密集 `coupon_receive`；`brush` 同 `sku` 高频 `order_create`+`order_pay`，收货地址聚集；`refund` 老账号高额订单 → 密集 `reason_code=not_received` 的 `after_sale_apply` | 概要设计 §3.4 / PRD 2.3.9 |
| **BR-03-29** | 模拟器**必须调用本模块的 `EventService`**（与真实链路同一入口），**不得直接写库、不得直接调 05** | 概要设计 §3.4 |
| **BR-03-30** | 模拟器写出的 `source` 固定为 `mock_biz`；`event_id` 仍按 BR-03-09 生成 | E01 |
| **BR-03-31** | 重复 `start` → `409 EVT-5006`；`stop` 后 `emitted/decision_counts` 汇总写入日志，**不写入任何集合**（E17/E18 的用例与执行记录归 10） | `00` §3.3 |
| **BR-03-32** | **可复现断言**：同 `(mode, seed, rate, max_events)` 两次运行，生成的事件序列除 `ts` 的绝对偏移外**逐字段一致** | 概要设计 §3.4 |

## 5. 异常处理

| 错误码 | 场景 | HTTP | 处理策略 | 用户可见提示 |
|---|---|---|---|---|
| `EVT-4001` | 请求体非 JSON 对象 | 400 | 拒绝 | 「请求体格式非法」 |
| `EVT-4002` | 缺 `user_id`（最基础标识） | 400 | 拒绝 | 「缺少必填字段：user_id」 |
| `EVT-4003` | `event_type` 不在五类枚举 | 400 | 拒绝 | 「不支持的事件类型：xxx（仅支持 login/coupon_receive/order_create/order_pay/after_sale_apply）」 |
| `EVT-4004` | 按类型必填字段缺失 | 422 | 拒绝 | 「`coupon_receive` 缺少必填字段：device_id、ip」 |
| `EVT-4005` | 字段格式非法（ip / amount / ts / phone） | 400 | 拒绝 | 「字段 ip 格式非法：`117.136.12.888`」 |
| `EVT-4006` | `scene_extra` 含不属于该类型的键 | 400 | 拒绝 | 「`login` 事件不接受扩展字段 `coupon_id`」 |
| `EVT-4007` | `amount` 与 `scene_extra` 金额字段不一致 | 400 | 拒绝 | 「amount(20000) 与 face_value(2000) 不一致」 |
| `EVT-4009` | 同 `event_id` 不同载荷 | 409 | 拒绝 | 「事件编号已存在且内容不同，疑似编号复用」 |
| `EVT-4010` | 批量超上限 | 400 | 拒绝整批 | 「单批最多 500 条，当前 812 条」 |
| `EVT-4404` | 详情查询时尚未落库 | 404 | 返回重试建议 | 「事件已接收，数据写入中，请 500ms 后重试」 |
| `EVT-5001` | 决策链路超时（>200ms） | **200** | **降级 `review`**，`degrade.stage=timeout` | 「检测超时，已转人工审核」 |
| `EVT-5002` | 04 特征计算不可用 | **200** | **降级 `review`**，`stage=feature` | 「特征服务不可用，已转人工审核」 |
| `EVT-5003` | 05 规则决策不可用 | **200** | **降级 `review`**，`stage=rule` | 「决策服务不可用，已转人工审核」 |
| `EVT-5004` | `risk_events` 异步落库失败 | **200** | 决策照常返回；进重试队列 + 告警，**不回滚** | 无（内部告警；详情查询暂 404） |
| `EVT-5005` | 模拟器启动失败（`mode` 非法 / 任务异常） | 500 | 停止任务并释放资源 | 08 页状态行显示 `启动失败：<reason>` |
| `EVT-5006` | 模拟器已在运行 | 409 | 拒绝重复启动 | 「模拟器已在运行，模式=wool」 |

> **fail-closed 原则（本模块是第一道执行者）**：任何下游依赖异常/超时时，**默认动作是 `review` 而非 `pass`**。
> `EVT-5001/5002/5003` 三条是风控系统"不确定就不放行"的落地证据，也是验收 V-03-07/08/09 的对象。
