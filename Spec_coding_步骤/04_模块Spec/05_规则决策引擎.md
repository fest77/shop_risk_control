## 1. 模块定位

| 项 | 内容 |
|---|---|
| **职责** | 名单快速过滤 → 条件树求值 → 分值累加 → 仲裁分级；产出 `decisions` 与 `decision_hits` |
| **触发时机** | 每个事件进入决策链路时（高频路径，P95 < 50ms） |
| **上游** | 04 特征计算引擎（提供 `feature_snapshots`） |
| **下游** | 03（把决策结果同步返回给调用方）、08 案件处置（review/reject 时建案）、11 监控指标、12 审计 |
| **对应 PRD** | 2.3.1 多层决策引擎、**2.3.4 决策评级与仲裁规则**、2.3.8 决策结果输出 |
| **对应实体** | 写 **E03 `decisions`**、**E04 `decision_hits`**；读 E05 `rules`、E06 `rule_scenes`、E07 `list_entries` |
| **对应原型** | 03 审核工作台右栏（判定摘要 / 命中明细）、02 大盘（规则命中排行）、05 仿真页（步骤 4） |
| **对应架构决策** | AD-01（同步决策 / 异步落库）、AD-02（名单 TTL 缓存）、AD-07（JSON 条件树）、AD-09（模型引擎空实现） |

**本模块明确不做的事**（防止与 06 重叠）：
- 不做规则的增删改、不做名单维护、不做条件树编辑 UI
- 不做落库以外的统计聚合（归 11）、不做画像聚合（归 09）
- **不做条件树的结构校验实现**——`validate_tree()` 由本模块提供，06 只调用

## 2. 页面结构（本模块的展示点）

引擎无独占页面。其输出出现在**三个页面的四处位置**，字段绑定如下。

### 2.1 展示点 A：`03_风控审核工作台` 右栏 · 系统风险判定摘要

| 元素 | 绑定字段 | 约束 |
|---|---|---|
| 风险评分大字 | `decisions.final_score` | 0~100；≥80 红、60~79 橙、<60 绿 |
| 风险等级标签 | `decisions.risk_level` | `low/medium/high` → 低/中/高 |
| 系统建议标签 | `decisions.decision` | `pass/review/reject` → 放行/人审/拦截 |
| 引擎说明行 | `engine_version` + `list_hit` + `hit_rule_count` | 文案：`决策引擎：rule-engine-v1 · 名单未命中 · 命中规则 3 条` |
| 名单直通态 | `list_hit.hit = true` | 直通时**不展示**分值，改为展示「白名单直通放行」/「黑名单直通拦截」并隐藏命中明细 |

**空态**：无决策记录时展示「该事件未产生决策记录（数据异常）」并置灰，不显示 0 分。

### 2.2 展示点 B：`03_风控审核工作台` 右栏 · 规则命中明细表

| 列 | 字段 | 说明 |
|---|---|---|
| 规则编码 / 名称 | `rule_code` + `rule_name` | 名称取 `decision_hits` 的**冗余快照**，不实时联查 `rules` |
| 分值 | `score` | 展示为 `+40` |
| 触发原因 | `reason` | 由规则模板生成，需含**实际值**（如"近1h同设备下单 12 次 ≥ 阈值 5"） |

**排序**：按 `score` 降序。
**空态**：无命中时展示「未命中任何规则（累计 0 分）」。

### 2.3 展示点 C：`02_风控态势大盘` · 规则命中排行榜

| 元素 | 数据来源 |
|---|---|
| 横向柱状图 Top10 | `metric_buckets`（`bucket_type=rule`），**不是**本模块实时聚合 |
| 柱子点击 | 跳转 06 的规则配置页并定位该规则 |

> **边界提醒**：本模块只负责产生命中记录；排行统计由 **11 监控指标引擎** 提供。

### 2.4 展示点 D：`05_事件仿真测试页` · 步骤 4 规则命中链路

| 元素 | 绑定 |
|---|---|
| 命中条数 + 累计分 | `hit_rule_count` + `rule_score` |
| 逐条命中表 | 同 2.2 |

## 3. 接口字段

### 3.1 本模块拥有的接口

#### `POST /api/v1/engine/evaluate` — 单条事件决策求值（仿真 / 调试用）

> 仿真模块（10）必须调用此接口以复用真实链路，**禁止另写判定逻辑**。

**请求**

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `event` | object | ✔ | 完整事件体，结构同 `POST /api/v1/events` 的 `event` |
| `dry_run` | bool | | 默认 `true`；`true` 时不写 `decisions` / `decision_hits` |
| `trace` | bool | | 默认 `false`；`true` 时返回逐规则求值过程（供仿真链路展示） |

**响应**

| 字段 | 类型 | 说明 |
|---|---|---|
| `event_id` | string | 事件编号 |
| `snapshot_id` | string | 特征快照编号 |
| `list_hit` | object | `{hit: bool, list_type, entity_type, entity_value}` |
| `rule_score` | int | 规则累加分（截断后） |
| `model_score` | int \| null | **恒为 `null`**（AD-09 模型引擎空实现） |
| `final_score` | int | 当前恒等于 `rule_score` |
| `risk_level` | enum | `low` / `medium` / `high` |
| `decision` | enum | `pass` / `review` / `reject` |
| `hit_rule_count` | int | 命中条数 |
| `hits` | array | `[{rule_code, rule_name, rule_version, score, reason, matched_facts}]` |
| `rule_versions` | object | `{rule_code: version}`，用于决策重放 |
| `engine_version` | string | `rule-engine-v1` |
| `elapsed_ms` | int | 决策耗时 |
| `degraded` | bool | 是否发生降级（如名单缓存不可用） |
| `trace` | array \| null | 仅 `trace=true` 时返回：`[{rule_code, evaluated: bool, matched: bool, reason}]` |

**状态码**：`200` 成功 / `400` 事件体非法 / `422` 特征缺失且无法继续 / `503` 引擎依赖不可用（返回 `degraded=true` 与人工审核建议，**不返回 pass**）

### 3.2 本模块对外提供的**契约**（被 03 复用）

`POST /api/v1/events` 的响应中，决策部分字段与 3.1 完全一致（`rule_score` 起至 `engine_version` 止）。
**契约冻结**：03 不得自行拼装该结构，必须直接透传本模块返回值。

### 3.3 本模块读取的内部数据结构

| 结构 | 来源 | 说明 |
|---|---|---|
| `RuleDoc` | `rules` | `{_id, name, scene_code, condition, score, status, priority, version}` |
| `ListEntryDoc` | `list_entries` | `{list_type, entity_type, entity_value, status, expire_at}` |
| `features` | 04 产出 | 18 项特征 KV |

## 4. 业务规则

> 编号规则：`BR-05-xx`。每条都必须**可判定、可测**。

### 4.1 名单过滤

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-05-01** | 按 5 个维度依次匹配名单：`user_id` → `phone` → `ip` → `device_id` → `address_id` | PRD 2.3.1 |
| **BR-05-02** | 命中**白名单** → 直接 `pass`，`rule_score=0`，**不求值任何规则**，`hits=[]` | PRD 2.3.4 |
| **BR-05-03** | 命中**黑名单** → 直接 `reject`，`rule_score=0`，**不求值任何规则**，`hits=[]` | PRD 2.3.4 |
| **BR-05-04** | 黑白名单**同时命中** → **黑名单优先**，判 `reject` | ⚠️ 悬空点 G-04（已按默认值实现） |
| **BR-05-05** | 仅 `status=active` 且（`expire_at` 为空 或 `expire_at > now`）的名单条目参与匹配 | E07 设计 |
| **BR-05-06** | **灰名单不参与决策**，既不拦截也不放行，只在画像上标注 | ⚠️ 悬空点 G-05 |
| **BR-05-07** | 名单查询走进程内 TTL 缓存（默认 10s），命中缓存不查库 | AD-02 |

### 4.2 规则选取与求值

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-05-08** | `event_type` → `scene_code` 映射：`login→login`、`coupon_receive→coupon`、**`order_create→order`**、**`order_pay→pay`**、`after_sale_apply→aftersale` | E06 设计｜**决策 D12 修正**：原把 `order_pay` 也映射到 `order`，导致 E06 定义的 `pay` 场景**永远不可达** |
| **BR-05-09** | 参与求值的规则 = `status=enabled` **且** `scene_code IN (本次匹配场景, 'common')`。`common` 是 E06 中**真实存在的场景数据行**（决策 D10），**不得在代码里特判字符串** | PRD 2.3.3｜决策 D10 D13 |
| **BR-05-10** | 条件树按 `logic`（`and`/`or`）**递归求值**，叶子节点 `{field, op, value}` 与 `features[field]` 比较 | AD-07 |
| **BR-05-11** | 算子语义：`eq/ne` 恒等比较；`gt/gte/lt/lte` 仅数值；`in/not_in` 右侧为数组；`exists` 判字段是否为 `null`；`contains` 仅字符串 | 本模块定义 |
| **BR-05-12** | **特征缺失（`null`）时**：除 `exists` 外所有算子返回 `false`（**不抛异常、不计分**） | 冷启动场景（E02.missing_features） |
| **BR-05-13** | 单条规则求值抛异常时，该规则**记为求值失败、不计分**，写入告警日志，**不影响其余规则** | 容错设计 |
| **BR-05-14** | `priority` **仅用于稳定排序与展示，不用于短路**——因为分值累加模式必须全量求值才能得出总分 | 对 PRD「优先级」的澄清 |

### 4.3 计分与仲裁

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-05-15** | `rule_score = Σ(命中规则.score)` | PRD 2.3.4 |
| **BR-05-16** | 累加结果 **截断到 100**（超过按 100 计） | ⚠️ 悬空点 G-03 |
| **BR-05-17** | 分级：`0~59 → low/pass`；`60~79 → medium/review`；`80~100 → high/reject` | PRD 2.3.4（已确认三档，**不做 Challenge**） |
| **BR-05-18** | `final_score = rule_score`（`model_score` 恒为 `null`） | AD-09 / 悬空点 G-01 |
| **BR-05-19** | 决策结果**同步返回**；`decisions` / `decision_hits` **异步落库** | AD-01 / PRD 2.3.7-1 |
| **BR-05-20** | 落库时必须写入 `rule_versions` 快照，保证任何历史决策可用当时版本重放 | 本模块防腐设计 |

### 4.4 命中明细的快照语义

| 编号 | 规则 |
|---|---|
| **BR-05-21** | `decision_hits` 必须**冗余存** `rule_name` 与 `score`，不得只存 `rule_code`——否则规则改名/改分后历史决策的解释会失真 |
| **BR-05-22** | `reason` 必须包含**实际特征值**（如 `device_user_cnt = 12`），便于人工复核时直接看到证据 |

## 5. 异常处理

| 错误码 | 场景 | HTTP | 处理策略 | 用户可见提示 |
|---|---|---|---|---|
| `RUL-4001` | 事件体非法（缺 `event_type` / `user_id`） | 400 | 拒绝 | 「事件参数不合法：缺少必填字段 xxx」 |
| `RUL-4002` | 条件树结构非法（`op` 不支持 / 缺 `field`） | 422 | 拒绝该规则，其余继续 | 06 保存时提示「条件树第 N 个节点不合法」 |
| `RUL-5001` | 名单缓存不可用且 Mongo 查询失败 | 503 | **降级：`degraded=true`，返回 `review`，绝不返回 `pass`** | 「名单服务不可用，已转人工审核」 |
| `RUL-5002` | 规则集加载失败 | 503 | 同上，fail-closed | 「规则服务不可用，已转人工审核」 |

> **[决策 D5] 降级也必须建案**：发生 `RUL-5001/5002` 降级时，本模块**仍写入一条 `decisions`**（`decision=review`、`degraded=true`），模块 08 据此**正常创建风控案件**。
> 理由：fail-closed 的意义就是把不确定的请求交给人工；若降级不落库、不建案，这些请求将**无人处理**，等于变相丢弃。
| `RUL-5003` | 单条规则求值异常 | 200 | 该规则跳过不计分 + 告警日志 | 页面在命中明细下方提示「有 N 条规则求值失败」 |
| `RUL-5004` | 决策耗时超过阈值（200ms） | 200 | 仍返回结果，但记 `slow` 告警 | 无（内部告警） |

> **fail-closed 原则（重要）**：决策链路任何依赖异常时，**默认动作是 `review` 而非 `pass`**。
> 风控系统的安全默认必须是"不确定就不放行"，把判断权交给人工。
