## 1. 模块定位

| 项 | 内容 |
|---|---|
| **职责** | 规则与名单的**管理时写入侧**：规则 CRUD / 启停用 / 版本管理 / 条件树编辑 UI 与保存前校验；多维名单库（黑/白/灰 × user/phone/ip/device/address）增删、批量导入、模板下载、过期清理 |
| **触发时机** | 人工操作时（低频）。**不在任何一个事件的决策链路上** |
| **上游** | 00 公共基础（枚举、错误码、HTTP 客户端）；**05 规则决策引擎**（提供 `validate_tree()` 与条件树 schema） |
| **下游** | **05**（读本模块写入的 `rules` / `list_entries` 并求值）、12 审计日志（本模块所有写操作落 `audit_logs`）、01 登录鉴权（页面与按钮可见性）、10 事件仿真测试（"送仿真验证"跳转） |
| **对应 PRD** | **2.3.3 策略与规则配置页**、2.3.4 决策评级与仲裁规则（名单与分值语义）、2.3.7-3 风控规则上线与调优流程、2.3.2 风控策略师职责 |
| **对应实体** | 写 **E05 `rules`**、**E07 `list_entries`**；读 **E06 `rule_scenes`**；写 E16 `audit_logs`（经 12 模块的 `AuditService`，本模块不自己拼哈希链） |
| **对应原型** | `04_策略与规则配置页.pen`（规则配置 / 名单库 / 规则场景 三标签页 + 规则编辑抽屉 + 条件树构建器） |
| **对应架构决策** | **AD-02**（名单 TTL 缓存与失效）、**AD-07**（JSON 条件树，禁字符串表达式）、AD-04（审计哈希链单写者）、AD-01（同步决策 / 异步落库的反面：本模块是低频同步写） |

### 1.1 边界裁定（对齐 `00_模块划分与边界` §3.1，**本模块最重要的一节**）

| 关注点 | 05 规则决策引擎 | **06 本模块** |
|---|---|---|
| 触发时机 | 每个事件进来时（高频，P95 < 50ms） | 人工操作时（低频） |
| 做什么 | **读**规则与名单 → 求值 → 打分 → 仲裁 | **写**规则与名单 → 校验 → 版本 → 审计 |
| 条件树 | **求值器** `evaluate()`、**结构定义**、**`validate_tree()`** | **编辑 UI**，保存前**调用 05 的 `validate_tree()`** |
| 名单 | 只做**快速过滤**（TTL 缓存读，命中即直通） | 增删改、批量导入、模板下载、过期清理 |
| 接口归属 | `POST /api/v1/engine/evaluate`、`GET /api/v1/rule-scenes` | `GET/POST/PUT/DELETE /api/v1/rules`、`/api/v1/lists` |
| 共享代码 | `app/engine/condition.py`（条件树模型 + `condition_op` 枚举），**06 只 import，不复制** | 同左 |

**本模块明确不做的事**：不实现条件树求值（归 05）；不实现条件树结构校验逻辑（归 05，只调用 `validate_tree()` 并回显错误）；不实现名单匹配语义与优先级（归 05），只负责"把条目正确写进去"；不做决策链路（03/04/05）、不做处置后自动写名单（归 08，本模块只提供写入接口）、不做命中排行统计（归 11）、不自己写审计哈希链（归 12）。

> **fail-closed 立场（本模块的核心安全观）**：本模块是**写入侧**，写入失败**绝不允许**演变成"风控放行"。任何写入失败都必须显式暴露（返回错误 + 设置名单降级标记 + 主动失效缓存），保证 05 下一轮决策时**要么读到变更后的完整数据，要么进入降级转人审**，不存在"静默吞掉导致沿用过期的宽松数据"这条路径。

#### 2.3 条件树构建器 `condTree`（本模块的核心 UI）

原型结构：根节点 `condRoot`（`condLogic` AND ▾ + `condAdd` ＋ 添加条件 + `condAddGroup` ＋ 添加条件组），其下 `condL1` / `condL2` / `condL3` 三行叶子，每行 = `字段选择` + `算子选择` + `值输入` + `删除`。

| UI 能力 | 说明 |
|---|---|
| 嵌套 | 任意节点可切换 `AND`/`OR`；任意节点可插入**子条件组**，组内同样可再嵌套（递归渲染，与后端 JSON 树同构） |
| 叶子三件套 | `field`（下拉，选项来自 04 特征引擎公布的特征名白名单）、`op`（下拉，选项来自共享的 `condition_op` 枚举）、`value`（控件按 `field` 类型切换：数值框 / 开关 / 多值输入） |
| 删除 | 叶子删除；组的子项删空后自动移除该组，**根节点不可删** |
| 只读 JSON 预览 | 抽屉底部可展开当前树的 JSON（只读），便于与 05 排查分歧 |
| 保存前校验 | 先**本地**做 UI 级完整性检查（空值、未选字段），再调 `POST /api/v1/rules/validate-tree`（服务端转调 **05 的 `validate_tree()`**）；本地检查**不是**结构校验的第二实现，只是"未填完就不必发请求"的前置短路 |

**校验错误回显**：接口返回的 `errors[]` 每项含 `path`（如 `children[1].children[0].op`）与 `message`；前端按 `path` **定位到对应节点行**并高亮，同时在抽屉顶部汇总「条件树有 N 处问题」。

## 3. 接口字段

> 统一前缀 `/api/v1`。所有响应统一包 `{code, message, trace_id, data}`（模块 00 约定）。分页契约见 3.5。

### 3.1 规则接口（本模块拥有）

#### `GET /api/v1/rules` — 规则列表

**请求（query）**

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `scene_code` | string | | `E06` 场景码之一或 `common` |
| `status` | enum | | `enabled` / `disabled` |
| `keyword` | string | | ≤50 字，匹配 `_id` 或 `name` |
| `page` | int | | ≥1，默认 1 |
| `page_size` | int | | 1~100，默认 20 |
| `sort` | string | | 默认 `priority:asc,_id:asc`；允许 `score:desc` / `updated_at:desc` |

**响应 `data`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `items` | array | 每项：`{_id, name, scene_code, scene_name, condition, condition_summary, score, priority, version, status, is_system, created_by, updated_by, created_at, updated_at}` |
| `total` / `page` / `page_size` | int | 分页元数据 |

**状态码**：`200` / `400 CFG-4008 分页参数越界` / `401` / `403 CFG-4031 无规则查看权限`

#### `POST /api/v1/rules` — 新建规则

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `name` | string | ✔ | 1~50 字 |
| `scene_code` | string | ✔ | 必须存在于 `rule_scenes` |
| `description` | string | | ≤200 字 |
| `condition` | object | ✔ | JSON 条件树；服务端**转调 05 的 `validate_tree()`** |
| `score` | int | ✔ | 0~100 |
| `priority` | int | | 默认 10 |
| `status` | enum | | 默认 `disabled`；传 `enabled` 时校验 BR-06-09 |

**响应**：`201` + 新规则完整对象。`version` 初始为 `1`。
**幂等性**：**无天然幂等键**。用请求头 `Idempotency-Key`（前端每次打开抽屉生成一个 UUID，同一次保存重试复用）防重复建规则；重复键返回首次结果。
**状态码**：`201` / `400 CFG-4003 条件树非法` / `400 CFG-4004 分值越界` / `409 CFG-4002 规则编码重复` / `403 CFG-4031`

#### `PUT /api/v1/rules/{rule_code}` — 修改规则

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `expected_version` | int | ✔ | **乐观锁**，必须等于库中当前 `version`，否则 `409 CFG-4006` |
| `name` / `scene_code` / `description` / `condition` / `score` / `priority` / `status` | — | | 同新建；**`_id`（规则编码）不可修改**，传了直接 `400 CFG-4007` |

**服务端行为**：`validate_tree()` 通过 → `version = expected_version + 1` → 写 `updated_by` / `updated_at` → 写审计（`rule.update`，含 `before` / `after`）→ **失效规则缓存**。
**状态码**：`200` / `400 CFG-4003/4004/4007` / `404 CFG-4001` / `409 CFG-4006 版本冲突`

#### `POST /api/v1/rules/{rule_code}/toggle` — 启停用

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `status` | enum | ✔ | `enabled` / `disabled` |
| `expected_version` | int | ✔ | 乐观锁 |

**服务端行为**：置 `status` → `version+1` → 审计（`rule.toggle`）→ **失效规则缓存**（AD-02 同类语义：管理侧变更后立即失效，不等 TTL）。
**幂等性**：**幂等**——目标状态与当前状态一致时不递增 `version`、不写审计、返回 `200` 并回显 `changed=false`。
**状态码**：`200` / `404 CFG-4001` / `409 CFG-4006` / `403 CFG-4031`

#### `DELETE /api/v1/rules/{rule_code}` — 删除规则

**约束**：`is_system=true` 一律拒绝（`400 CFG-4005`）；已被历史 `decisions.rule_versions` 引用的规则**允许删除**，但删除前必须返回影响面预览（见 5.2）。
**服务端行为**：**软删除**——将 `status` 置 `disabled` 并打删除标记，**不物理删除文档**，保证历史 `decision_hits.rule_code` 可回溯（对应 BR-05-21 的快照语义）。
**状态码**：`200` / `400 CFG-4005` / `404 CFG-4001` / `409 CFG-4006`

#### `POST /api/v1/rules/validate-tree` — 条件树校验（**转发 05**）

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `condition` | object | ✔ | 待校验的 JSON 条件树 |

**服务端行为**：**不实现任何校验逻辑**，直接调用 `app/engine/condition.py` 中 05 提供的 `validate_tree(condition)`，把结果原样包装返回。
**响应 `data`**：`{valid: bool, errors: [{path, code, message}], normalized: object|null}`（`normalized` 为 05 归一化后的树，前端保存时提交它）。
**状态码**：`200`（**校验失败也是 200**，靠 `valid=false` 表达）/ `403 CFG-4031`

#### `POST /api/v1/rules/import` — 规则批量导入

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `file` | file | ✔ | CSV / XLSX，≤2MB，≤500 行 |

### 3.5 列表页统一契约（**规则列表 / 名单列表 / 导入明细共用**）

| 项 | 约定 |
|---|---|
| 分页参数 | `page`（≥1，默认 1）、`page_size`（1~100，默认 20） |
| 分页超界 | `page` 超过总页数时**不报错**，返回空 `items` + 正确 `total`；`page > 200` 才按 `CFG-4008` 拒绝 |
| 排序 | `sort=字段:asc\|desc`，逗号分隔多级；**字段必须在白名单内**，否则 `400 CFG-4008` |
| 复合筛选 | 全部条件之间为 **AND**；同字段多值为 **OR**（如 `entity_type=ip&entity_type=device`） |
| 空态 | 「暂无数据」+ 差异化文案（规则：引导新建；名单：引导新增或导入；筛选命中 0 条：提示「清空筛选」） |

| 失败态 | 保留旧数据 + 顶部错误条 + `重试`；不得白屏 |
| 一致性 | 列表响应携带 `as_of`（服务端时间戳），页面显示"数据截至 xx:xx:xx" |

| `CFG-4032` | 试图移除 `source=auto` 的名单条目 | 403 | 拒绝并给出跳转 | 「该条目由案件处置自动写入，请到案件处置模块处理」 |
| `CFG-5001` | Mongo 写规则失败 | 503 | 拒绝 + 重试按钮；**不产生部分写入** | 「规则保存失败，请稍后重试」 |
| `CFG-5002` | **名单写入失败** | 503 | **置名单降级标记（`degraded=true`）+ 主动失效缓存 + 告警**；见 5.3 | 「名单写入失败，已进入降级状态；新增黑名单暂未生效，请重试」 |
| `CFG-5003` | 审计写失败 | 503 | **业务写操作整体回滚**（BR-06-36） | 「操作未完成（审计写入失败），已回滚，请重试」 |

### 5.2 破坏性操作的二次确认（承接原型评审遗留问题 3）

| 操作 | 确认弹窗必须展示 | 依据 |
|---|---|---|
| **移除名单条目** | 实体值 / 名单类型 / 来源 / 加入时间 / **关联案件数**；提示「移除后该实体不再被拦截或放行，最长 10s 内对线上生效（AD-02，本模块会主动失效缓存，实际为即时）」；按钮文案「确认移除」用危险色 | 原型评审 §6 问题 3 |
| **删除规则** | 规则编码 + 名称 + **近 30 天命中次数** + 「历史决策记录不受影响（命中明细为快照）」 | 本模块补充 |
| **批量导入覆盖** | 成功/失败行数 + 错误明细（**可下载**）+ 「已存在条目将按 `force` 语义处理」 | BR-06-28/29 |

### 5.3 降级策略（**fail-closed 的落地形态**）

| 场景 | 降级动作 | 对决策链路的影响 |
|---|---|---|
| 名单写入失败（新增黑名单） | `degraded=true` + 失效缓存 + 告警 + 返回 `CFG-5002` | 05 无法从缓存确认，**回源查询**；若回源也失败 → 05 按 `CFG-5001` 返回 `review`，**不放行** |
| 名单写入失败（新增白名单） | 同上，**绝不写入半条记录** | 不出现"该放行的被拦"或"该拦的被放" |
| 名单移除失败 | 回滚软删标记，条目保持 `active` | 保持原判定行为，不产生新的宽松窗口 |
| 规则保存失败 | 无部分写入（单文档操作） | 线上规则集不变 |
| 规则缓存失效调用失败 | 记录 `CFG-5003` 级告警，**同时把缓存整体清空**而非保留 | 宁可让 05 全量回源，也不让 05 用旧规则 |
| Mongo 完全不可用 | 所有管理写操作返回 `503`；页面顶部展示降级横幅 | 05 的名单/规则读取失败 → `review` |

> **不可越界的红线**：任何管理侧异常都**不允许**导致 05 返回 `pass`。本模块不提供、也不接受"写失败就跳过"的实现。
