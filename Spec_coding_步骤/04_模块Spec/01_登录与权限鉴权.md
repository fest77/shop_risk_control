## 1. 模块定位

| 项 | 内容 |
|---|---|
| **职责** | 账号密码登录、JWT 签发与校验、三角色 RBAC、**菜单与按钮可见性**、接口级 403 拦截、登录态维持与失效跳转 |
| **触发时机** | 每次请求的鉴权中间件（高频）+ 登录/登出（低频） |
| **上游** | 00 公共基础（错误契约、配置、日志） |
| **下游** | 全部业务模块（提供「当前用户」依赖）；13 系统设置的账号管理 |
| **对应 PRD** | **2.3.2 用户角色与权限** |

| **对应原型** | `01_登录页.pen`、`09_角色-页面可见性矩阵.pen` |
| **对应架构决策** | — （本模块只依赖 00 的错误契约与配置） |

**本模块明确不做的事**：
- 不做账号的新增/停用/改角色——那是**模块 13 系统设置**的职责，本模块只**读取** `sys_users` 做认证
- 不做业务数据权限（本项目不存在按部门隔离数据的需求；权限是**功能级**的）

## 3. 接口字段

### 3.1 `POST /api/v1/auth/login`

**请求**

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `username` | string | ✔ | 4~32 字符，`^[a-zA-Z0-9_.-]+$` |
| `password` | string | ✔ | 6~64 字符 |

**响应 `data`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `access_token` | string | JWT |
| `token_type` | string | 固定 `Bearer` |
| `expires_in` | int | 有效期秒数（默认 8 小时 = 28800） |
| `user` | object | `{username, real_name, role, role_label}` |

**状态码**：`200` 成功 / `401` 账号或密码错误 / `403` 账号已停用 / `422` 参数非法 / `429` 登录过于频繁

### 3.2 `GET /api/v1/auth/me`

**响应 `data`**：`{username, real_name, role, role_label, permissions: ["case:read","case:dispose",...], login_at}`

> `permissions` 由后端按 §2.2 矩阵展开为细粒度权限串下发，**前端不得自行推导权限**。

### 3.3 `POST /api/v1/auth/logout`

无请求体。响应 `data`: `{logged_out: true}`。
**注意**：JWT 无状态，服务端登出只做**前端清 token**；如需真正失效需引入黑名单（见 §8 待确认）。

### 3.4 `POST /api/v1/auth/password`

**请求**：`{old_password, new_password}`（`new_password` 6~64）

**响应**：`{changed: true}`；**改密后当前 token 立即失效**，前端跳登录页。

**权限**：仅本人可改自己的密码。

### 3.5 鉴权中间件契约

| 项 | 规则 |
|---|---|
| 请求头 | `Authorization: Bearer <jwt>` |
| 白名单 | `/health`、`/api/v1/common/*`、`/api/v1/auth/login`、`/static/*`、`/` |
| 缺失/格式错 | `401` `AUTH-4002` |
| 签名错/过期 | `401` `AUTH-4003` / `AUTH-4004` |
| 账号已停用 | `403` `AUTH-4010` |
| 角色无权 | `403` `AUTH-4020` |
| 注入 | 中间件把用户对象放入请求上下文，供 `deps.get_current_user()` 取用 |

**JWT Claims**

| Claim | 值 |
|---|---|
| `sub` | `username` |
| `role` | `reviewer` / `strategist` / `admin` |
| `iat` / `exp` | 签发与过期时间 |
| `jti` | 唯一 id（为将来黑名单预留） |

## 4. 业务规则

### 4.1 认证

| 编号 | 规则 |
|---|---|
| **BR-01-01** | 密码用 **bcrypt 加盐**存储（直接依赖 `bcrypt` 库，**不用 passlib**），库中**绝不存明文或可逆密文** |
| **BR-01-02** | 登录失败时**统一返回"账号或密码错误"**，不区分"账号不存在"与"密码错误"（防账号枚举） |
| **BR-01-03** | 账号 `status=disabled` 时**即使密码正确也拒绝登录**，返回 `AUTH-4010`「账号已停用，请联系管理员」 |
| **BR-01-04** | 登录成功更新 `sys_users.last_login_at` |
| **BR-01-05** | 同一账号连续失败达阈值即锁定（返回 `AUTH-4005`）。**当前取值 10 次 / 60 秒**（用户 2026-09-24 确认，见 15_决策记录 D31；原定 5 次 / 10 分钟）——PRD 未要求，见 §8 |
| **BR-01-06** | 密码比较使用恒定时间比较，避免时序侧信道 |

### 4.2 令牌

| 编号 | 规则 |
|---|---|
| **BR-01-07** | JWT 有效期 **8 小时**（覆盖一个工作日），不提供刷新令牌（演示场景，见 §8） |
| **BR-01-08** | 签名密钥从 `.env` 读取；**密钥缺失时启动失败**（BR-00-02） |
| **BR-01-09** | 令牌校验必须同时验**签名**与**过期时间**；不使用 `alg=none` 分支 |
| **BR-01-10** | 改密成功后，**该用户旧令牌立即视为失效**（校验时比对 `sys_users.password_changed_at` 与 token 的 `iat`） |

### 4.3 角色与权限

| 编号 | 规则 |
|---|---|
| **BR-01-11** | 系统只有三个角色：`reviewer`（风控审核员）、`strategist`（风控策略师）、`admin`（系统管理员）；**不允许自定义角色** |
| **BR-01-12** | 权限矩阵以 §2.2 为**唯一真源**；前端菜单过滤与后端鉴权必须读同一份定义（后端下发 `permissions`） |
| **BR-01-13** | **强制职责分离**：处置动作仅 `reviewer` 可执行、规则与名单变更仅 `strategist` 可执行、审计与系统配置仅 `admin` 可执行；三者的可执行集合**互不重叠**（仿真测试例外，允许 reviewer 与 strategist） |
| **BR-01-14** | 权限判断必须**同时**作用于两处：① 前端不渲染 ② 后端返回 403。**仅隐藏菜单不算权限控制** |
| **BR-01-15** | 权限不足的**写操作**必须拒绝并写审计日志（`action=auth.denied`），防止越权尝试无痕 |

### 4.4 登录态前端行为

| 编号 | 规则 |
|---|---|
| **BR-01-16** | token 存 `localStorage`（键 `rc_token`）；页面加载时若存在则先调 `/auth/me` 验证 |
| **BR-01-17** | 任意接口返回 `401` → 清 token → 跳登录页 + toast「登录已失效，请重新登录」（由 `api.js` 统一处理，各视图不重复实现） |
| **BR-01-18** | 任意接口返回 `403` → 不跳页，toast 后端 `error.message` |
| **BR-01-19** | 已有有效 token 时访问登录页 → 直接跳 `#/dashboard` |
| **BR-01-20** | 登出仅清本地 token 与用户信息，不清除其他本地数据 |

## 5. 异常处理

> **⚠️ 勘误（模块 01 实现时修正，见 15_决策记录 D26）**：本节原有**两张**错误码表，
> **下面第一张（§5.1）已作废**，因为两张表**同码两义**：
> `AUTH-4004` 分别是"签名无效"与"已过期"、`AUTH-4005` 分别是"账号已停用"与"登录锁定"、
> `AUTH-4006` 分别是"角色越权"与"密码复杂度不符"——违反 BR-00-13「同一错误码全项目唯一」。
> **以 §5.2 为唯一真源**（实现见 `app/errors.py` 的 `AUTH_CODES`）；§5.1 仅作历史留存，不得据此实现。

### 5.1 （已作废）早期草稿表

| 错误码 | 场景 | HTTP | 用户可见提示 |
|---|---|---|---|
| `AUTH-4001` | 账号或密码错误 | 401 | 「账号或密码错误」 | 不区分「账号不存在/密码错」，防用户名枚举 |
| `AUTH-4002` | 令牌缺失或格式非法 | 401 | 「请先登录」 | 前端清除本地状态并跳回登录页 |
| `AUTH-4003` | 令牌已过期 | 401 | 「登录已过期，请重新登录」 | 同上 |
| `AUTH-4004` | 令牌签名无效（被篡改） | 401 | 「登录状态异常，请重新登录」 | **记安全日志**，可能是攻击尝试 |
| `AUTH-4005` | 账号已停用 | 403 | 「账号已停用，请联系管理员」 | 停用不影响其历史审计记录 |
| `AUTH-4006` | 角色越权（无该操作权限） | 403 | 「当前角色无权执行该操作」 | 前端同时置灰入口；**后端必须独立校验** |
| `AUTH-5001` | 鉴权依赖不可用（用户库查询失败） | 503 | 「登录服务暂时不可用」 | **fail-closed：不得因查不到用户就放行** |

### 5.2 权威表（**唯一真源**，实现以此为准）

| 错误码 | 场景 | HTTP | 用户可见提示 |
|---|---|---|---|
| `AUTH-4001` | 账号或密码错误 | 401 | 「账号或密码错误」 |
| `AUTH-4002` | 未携带令牌 | 401 | 「请先登录」 |
| `AUTH-4003` | 令牌签名无效或格式错误 | 401 | 「登录凭证无效，请重新登录」 |
| `AUTH-4004` | 令牌已过期 | 401 | 「登录已失效，请重新登录」 |
| `AUTH-4005` | 登录失败次数过多被锁定 | 429 | 「失败次数过多，请 10 分钟后再试」 |
| `AUTH-4006` | 新密码不符合复杂度要求 | 422 | 「新密码需 6~64 位」 |
| `AUTH-4007` | 原密码错误 | 422 | 「原密码不正确」 |
| `AUTH-4008` | 密码已变更导致令牌失效 | 401 | 「密码已修改，请重新登录」 |
| `AUTH-4010` | 账号已停用 | 403 | 「账号已停用，请联系管理员」 |
| `AUTH-4020` | 角色无权访问该功能 | 403 | 「当前角色无权执行该操作」 |
| `AUTH-5001` | 用户表查询失败 | 503 | 「鉴权服务暂时不可用」 |
| `AUTH-5002` | JWT 签名密钥缺失（启动期） | — | 进程退出并打印缺失键名 |

> **fail-closed 原则**：`AUTH-5001`（鉴权依赖不可用）时**一律拒绝请求**，不得放行。
> 鉴权服务的默认必须是"失败即拒绝"，这与风控决策的 fail-closed 同源。

| 文件 | 职责 | 可单测 |
|---|---|---|
| `security/password.py` | 哈希与恒定时间校验 | ✔ |
| `security/jwt.py` | 令牌签发/解析/失效判定 | ✔ |
| `security/permissions.py` | **权限矩阵唯一真源**，导出给前端 | ✔ |
| `middleware/auth_middleware.py` | 白名单、校验、拦截 | ✔（TestClient） |
| `services/auth_service.py` | 认证编排 | ✔ |
| `api/auth_api.py` | 路由 | 集成 |

**权限矩阵的单一来源**：`security/permissions.py` 定义后，由 `GET /auth/me` 下发给前端；**前端不得再维护一份**（否则必然漂移）。

> **实际落地布局（模块 01 实现时确认）**：规划稿的三处差异已收敛，功能不减：
> ① **口令哈希**从模块 00 的 `app/utils/password.py` **迁入 `app/security/password.py`**——
>    口令哈希属于鉴权域，与 JWT、权限矩阵同包更利于评审安全边界；
> ② 新增 `app/security/login_guard.py`（BR-01-05 的登录失败锁定，进程内滑动窗口）；
> ③ `middleware/` 作为包存在（`app/middleware/__init__.py` + `auth_middleware.py`），
>    且鉴权中间件是**纯 ASGI**实现而非 `BaseHTTPMiddleware`——后者会包装/缓冲响应体，
>    而模块 02 需要 SSE 长连接。
> 另外：`app/deps.py` 新增 `require_permission()` 依赖工厂承担**授权**（角色能否做这件事），
> 中间件只承担**认证**（是否登录）。原因是中间件在路由解析之前执行，
> `scope["route"]` 尚不存在，靠路径前缀猜权限表必然出错。

## 7. 验收标准

| # | 验收项 | 如何验证 | 对应 PRD |
|---|---|---|---|
| V-01-01 | 能通过账号密码正常登录 | 用种子账号登录，断言返回 token 与 user 信息 | 2.3.2 |
| V-01-02 | 密码错误拒绝且提示统一 | 错误密码登录，断言 `AUTH-4001` 且提示不区分账号是否存在 | BR-01-02 |
| V-01-03 | 停用账号无法登录 | 将账号置 `disabled`，断言 `AUTH-4010` | BR-01-03 |
| V-01-04 | 密码为 bcrypt 存储 | 直接查库断言**不以明文出现**，且形如 `$2b$...` | BR-01-01 |
| V-01-05 | 令牌过期后失效 | 签发一个 `exp` 已过的令牌请求，断言 `AUTH-4004` 且前端跳登录页 | BR-01-09/17 |
| V-01-06 | 改密后旧令牌立即失效 | 登录拿 token → 改密 → 用旧 token 请求，断言 `AUTH-4008` | BR-01-10 |
| V-01-07 | 三角色菜单差异正确 | 分别以三种角色登录，截图/断言菜单项数量与文案与 §2.2 一致 | 2.3.2 |
| V-01-08 | 无权限菜单不渲染 | 断言无权限菜单项在 DOM 中**不存在**（非 `display:none`） | BR-01-14 |
