## 1. 模块定位

| 项 | 内容 |
|---|---|
| **职责** | 案件的**查看与联动**：多维筛选、列表分页、**三栏联动**（案件列表 / 画像·事件·快照·图谱 / 判定摘要·命中明细·处置区）、**认领案件** |
| **触发时机** | 审核员进入工作台时（人工操作）；案件由 05 判 `review`/`reject` 后经 08 落库，本模块**不产生案件** |
| **上游** | 08 案件流转（提供 `risk_cases` 列表与详情）、**09 画像与图谱**（中栏画像 / 快照对比 / 关联图谱）、**05 规则决策引擎**（右栏判定摘要 / 命中明细）、01 登录鉴权（角色） |
| **下游** | **08 案件处置与业务联动**（本页把用户的结论 + 动作 + 备注**提交给 08**，由 08 执行）、02 态势大盘（卡片下钻带 `status=pending` 进入本页） |
| **对应 PRD** | **2.3.3 风控审核工作台**（筛选与列表区 / 证据链与画像详情区 / 研判与处置协同区）、2.3.5 审核工作台模块、2.3.7-2 高危案件调查与处置流程（第 1、2 步） |
| **对应实体** | 读 **E08 `risk_cases`**；经 E08 的 `event_id` / `decision_id` **引用** E01 / E02 / E03 / E04 / E10~E14（均由 05、09 提供，本模块不计算） |
| **对应原型** | `03_风控审核工作台.pen`（三栏）；处置交互与二次确认弹窗属 `06_处置二次确认弹窗.pen`（归 08） |
| **对应架构决策** | AD-06（图谱 2 跳）、AD-01（快照与决策已落库，本页只读）、AD-09（模型引擎空实现 → 摘要只显示规则分） |

### 1.1 边界裁定（本模块只"看"与"选"，不"算"也不"做"）

| 能力 | 归属 | 本模块的做法 |
|---|---|---|
| 案件创建与状态机 | **08** | 只读列表、只提交认领 |
| **处置动作执行**（写 `case_actions`、写 `list_entries`、调 `BizAdapter`、写审计） | **08** | **不做**。右栏处置区只收集「结论 + 动作 + 备注」，提交给 08 的接口 |
| 用户画像聚合、设备/IP/地址聚集度 | **09** | 调 `GET /api/v1/profiles/{user_id}`，只渲染 |
| 关联实体图谱与团伙发现 | **09** | 调 `GET /api/v1/graph/{entity_type}/{entity_id}?max_hop=2`（AD-06），只渲染 |
| 风险判定摘要（分值 / 等级 / 建议） | **05** | 读 `decisions`，只格式化展示；**禁止页面重算分值或重定级别** |
| 规则命中明细与 `reason` | **05** | 读 `decision_hits`（冗余快照），只展示 |
| 特征快照 18 项 | **04** | 读 `feature_snapshots.features`，只展示与对比 |
| 审计日志写入 | **12** | 认领动作的审计由 08/12 负责，本模块不直接写 |
| 指标统计（待审数等） | **11** | 顶部「共 N 条待审」取列表接口的 `total`，**不另算拦截率等指标** |

> **一句话边界**：本模块是**只读编排层 + 认领写操作**。所有"算出来的数"都来自别的模块，本模块只负责把它们**对齐、同步、正确展示**。

## 2. 页面结构

独占页面 `03_风控审核工作台.pen`。前端为零依赖单文件 HTML + 原生 JS，hash 路由 `#/cases?level=high&status=pending&page=1&case=CASE0923001`。元素名严格对齐 `_原型元素清单.md` 的 `03_风控审核工作台.pen` 段落。

### 2.1 顶部筛选区 `wbFilter`

| 元素 | 文案 | 绑定参数 | 交互 |
|---|---|---|---|
| `fLevel` | `风险等级 ▾` | `risk_level` | 全部 / 中风险（`medium`）/ 高风险（`high`） |
| `fScene` | `事件场景 ▾` | `scene_code` | 全部 / 登录 / 领券 / 下单 / 支付 / 售后（选项来自 `E06 rule_scenes`，**经 05 的 `GET /api/v1/rule-scenes` 获取**） |
| `fStatus` | `审核状态 ▾` | `status` | 全部 / 待审（`pending`）/ 审核中（`reviewing`）/ 已处置（`disposed`）/ 已归档（`archived`） |
| `fTime` | `触发时间 ▾` | `created_from` / `created_to` | 快捷项（近 1 小时 / 近 24 小时 / 近 7 天）+ 自定义区间；**上限跨度 90 天** |
| `fReset` | `重置` | — | 清空全部筛选并回到 `page=1` |
| `wbFilterR` | `共 {total} 条待审` | `total`（当 `status=pending`） | 其他状态时文案为 `共 {total} 条案件` |
| `wbRefresh` | `刷新` | — | 重新拉取列表；**保留当前选中案件与筛选** |

**筛选交互约束**：任一筛选变化 → `page` 重置为 1 → 写入 hash → 发一次请求。筛选项全部为下拉，**不提供自由文本输入**（避免与 `keyword` 检索混淆）。

### 2.2 左栏 `colList` · 案件列表

#### 2.2.1 表格 `caseTbl`（4 列，与原型逐列对齐）

| 列 | 字段 | 展示规则 |
|---|---|---|
| 案件号 `caseTblH0` | `risk_cases._id` | 等宽字体，如 `CASE0923001` |
| 用户 `caseTblH1` | `user_id` | 可点击（跳转 09 画像详情新页签，**不改变当前三栏选中**） |
| 风险分 `caseTblH2` | `risk_cases.risk_score` | 整数；配色：≥80 红 / 60~79 橙 |
| 状态 `caseTblH3` | `risk_cases.status` | `pending`→「待审」/ `reviewing`→「审核中」/ `disposed`→「已处置」/ `archived`→「已归档」 |

**行选中态**：当前案件行高亮并左侧加色条；**除 4 列外，行尾另有 2 个不在原型列内的补充字段作为 hover 提示**（`scene_code`、`created_at`），不占列宽。

**排序**：默认 `risk_level(high→medium) , created_at desc`（见 BR-07-03）。
**空态**：区分两种——无任何案件时「暂无风控案件」；筛选命中 0 条时「当前筛选条件下无案件」+「清空筛选」按钮。
**加载态**：表体骨架行 ×7；切筛选时表体遮罩 + **保留旧列表**，避免三栏闪断。

#### 2.2.2 分页条 `pgBar`

| 元素 | 行为 |
|---|---|
| `pgPrev` 上一页 | `page=1` 时置灰不可点 |
| `1 / 4` | 展示 `page / total_pages`；`total_pages = ceil(total / page_size)` |
| `pgNext` 下一页 | 末页时置灰不可点 |

每页条数固定 **20**（页面不提供切换，见 BR-07-04）。

### 2.3 中栏 `colMid` · 证据链与画像

数据来源：**09 画像与图谱** + `E01`/`E02`。四张卡片顺序与原型一致。

#### 2.3.1 画像卡 `profileCard`

| 元素 | 绑定字段 | 来源 | 约束 |
|---|---|---|---|

#### 2.3.2 当前触发事件卡 `evtCard`

| 元素 | 绑定 | 来源 |
|---|---|---|
| 事件编号 `evtId` | `risk_events._id` | E01 |
| 事件类型 `evtType` | `event_type`（中文附注，如 `coupon_receive（营销领券）`） | E01 |
| 业务单据号 `evtBiz` | `biz_no` + 关键 `scene_extra`（如 `面额 200 元`） | E01 |
| 请求时间戳 `evtTime` | `ts`（毫秒 → `yyyy-MM-dd HH:mm:ss.SSS`） | E01 |

> **`scene_extra` 的展示口径**：按 `event_type` 展示对应关键字段（领券→面额；支付→支付渠道；售后→退款原因码与金额），字段清单以 E01 的 `scene_extra` 差异表为准。**`amount` 一律按"分"存储、"元"展示**（÷100，两位小数）。

#### 2.3.3 特征上下文快照卡 `snapCard`（**本次值 vs 基线值 vs 偏离**）

| 列 | 字段 | 说明 |
|---|---|---|
| 特征名 `snapTblH0` | `feature_snapshots.features` 的键 | 18 项，顺序固定（按 E02 五分组顺序），**不随机排序** |
| 本次值 `snapTblH1` | `features[field]` | `null` → 显示「—（缺失）」并置灰（对应 `missing_features`） |
| 基线值 `snapTblH2` | `baseline[field]` | 由 **09** 提供（见 BR-07-11 与待确认项）；无基线时显示 `—` |
| 偏离 `snapTblH3` | 前端计算的展示值 | 数值型：`▲ N 倍` / `▼ 偏低`；布尔型：`▲ 命中`；相等/无基线：`—` |

**偏离渲染规则**（**仅为展示格式化，不是风控判定**）：

| 情况 | 展示 |
|---|---|
| 本次 > 基线 且基线 ≠ 0 | `▲ {本次/基线:.1f} 倍`，红色 |
| 本次 < 基线 且基线 ≠ 0 | `▼ {本次/基线:.1f} 倍`，灰蓝色 |
| 基线为 0 或 `null` | `—` |
| 布尔型且本次为 `true`、基线为 `false` | `▲ 命中`，红色 |
| 值相等 | `正常` |

**折叠**：默认展开，超 18 行时卡片内滚动（`max-height` + 内部滚动），不撑破三栏高度。

#### 2.3.4 关联实体图谱卡 `graphBox`

| 项 | 约定 |
|---|---|
| 渲染 | 力导向图；**默认 2 跳**（AD-06） |
| 节点 | 中心 = 用户 `U000128`；一跳 = 设备 / IP / 地址；二跳 = 同设备账号 / 同 IP 账号 / 同地址账号 |
| 边 | 颜色区分 `relation`：`used_device` / `shared_ip` / `shared_address` / `same_phone`；**红色边 = `entity_edges.risk_flag=true`**（已判定风险关联） |
| 图例 | 必须区分「同设备 / 同 IP / 同地址聚集账号」（原型注记第 6 条） |
| 交互 | 节点可点击 → 展示该节点摘要浮层（账号/设备/IP/地址 + 关联数）；**不允许**从图中直接发起处置（处置只在右栏，经 08） |
| 上限 | 节点数 > 80 时提示「关联节点过多，仅展示关联度 Top 80」并降级为列表视图 |
| 空态 | 「未发现关联实体」 |
| 超时 | 图谱请求超时（>3s）降级为 **1 跳 + 提示「2 跳数据加载超时，已降级展示 1 跳」**（BR-07-14） |

### 2.4 右栏 `colRight` · 研判与处置协同

#### 2.4.1 系统风险判定摘要 `vdCard`（**数据归 05**）

| 元素 | 绑定 | 约束 |
|---|---|---|
| `vdScore` 风险评分 | `decisions.final_score` | 0~100 |
| `vdLevelV` 风险等级 | `decisions.risk_level` | 低/中/高 |
| `vdActionV` 系统建议 | `decisions.decision` | `pass`→放行 / `review`→人审 / `reject`→拦截 |
| 引擎说明行 | `rule-engine-v1 · 名单未命中 · 命中规则 3 条` | 由 `engine_version` + `list_hit.hit` + `hit_rule_count` 拼装（**与 `05` 的 2.1 文案一致**） |
| 名单直通态 | `list_hit.hit=true` | **直通时不展示分值**，改为「白名单直通放行」/「黑名单直通拦截」并隐藏命中明细表 |

**空态**：无决策记录时展示「该事件未产生决策记录（数据异常）」并置灰，**不显示 0 分**。
**模型分**：`model_score` 恒为 `null`（AD-09 / 悬空点 G-01），页面**不展示模型分栏位**。

#### 2.4.2 规则命中明细 `hitCard`（**数据归 05**）

| 列 | 字段 | 说明 |
|---|---|---|
| 规则编码 / 名称 `hitTblH0` | `rule_code` + `rule_name` | 名称取 `decision_hits` 的**冗余快照**，**不实时联查 `rules`** |
| 分值 `hitTblH1` | `score` | 展示 `+40` |
| 触发原因 `hitTblH2` | `reason` | 含实际特征值（如「近1h同设备下单 12 次 ≥ 阈值 5」） |

**排序**：`score desc`。
**空态**：`未命中任何规则（累计 0 分）`。
**失败规则提示**：当 `05` 报告有规则求值失败时，表格下方追加「有 N 条规则求值失败」（对应 `RUL-5003`），**不隐藏、不美化**。

#### 2.4.3 研判与处置区 `dpCard`（**本页只收集，提交给 08**）

| 元素 | 字段 | 必填 | 交互 |
|---|---|:--:|---|
| `dpConOpts` 处理结论 | `conclusion` | ✔ | 单选：`确认违规`→`violation` / `确认为正常`→`normal` / `存疑待观察`→`suspicious` |
| `dpActOpts` 联动处置动作（可多选） | `action_type[]` | ✔ | 复选：`拦截订单`→`block_order` / `拉黑用户`→`blacklist_user` / `封禁设备`→`ban_device` / `驳回退款`→`reject_refund`（`pass` 不在此列，对应左下的「放行」按钮） |
| `dpRemark` 处置原因备注 *（必填） | `remark` | ✔ | 1~500 字；占位文案与原型一致 |
| `dpBtns` | — | — | `放行` / `违规拦截` / `提交处置` |

**按钮语义（三选一，提交给 08）**

| 按钮 | 提交的默认组合 | 说明 |
|---|---|---|
| `btnRelease` 放行 | `conclusion=normal` + `action_type=[pass]` | 快捷入口，仍需备注（BR-07-13） |
| `btnReject` 违规拦截 | `conclusion=violation` + 勾选项（默认勾 `block_order`） | 快捷入口 |
| `btnSubmit` 提交处置 | 用户在表单中自选的组合 | 通用提交 |

**提交前置校验**（未满足则按钮置灰 + 悬停提示，对应原型 `wbNote` 第 2 条）：

1. 未选中案件 → 「请先选择案件」
2. 案件状态为 `disposed` / `archived` → 「该案件已处置，不可重复提交」
3. 案件状态为 `pending`（未认领）→ 「请先认领案件」
4. `conclusion` 未选 → 「请选择处理结论」
5. `action_type` 为空 → 「请至少选择一项联动处置动作」
6. `remark` 为空 → 「请填写处置原因备注」

**提交后**：跳转 `08` 的二次确认弹窗（`06_处置二次确认弹窗.pen`，归 08 渲染），确认后才真正执行；本模块**不直接调处置执行接口**，只把表单数据交给 08 的提交流程。

**固定注记**（原型原文）：`⚠ 提交后将同步写入名单库与审计哈希链，不可撤销；执行前需二次确认。`

| `estimated_loss` | int | 分；金额统一 ÷100 展示为元 |

**响应 `data`** 另含 `total` / `page` / `page_size` / `as_of`（服务端时间戳）。
**状态码**：`200` / `400 CASE-4004 筛选或分页参数非法` / `401` / `403 CASE-4031 无案件查看权限`

### 3.2 案件详情（**拥有者：08**，本模块一次拉取以驱动三栏）

#### `GET /api/v1/cases/{case_no}`

**设计意图**：**一次请求返回三栏所需的全部数据**，避免中栏与右栏分别异步到达导致"错位"（原型注记第 1 条）。

**响应 `data`**

| 字段 | 类型 | 归属模块 | 说明 |
|---|---|---|---|
| `case` | object | 08 | 同 3.1 的 item 字段 |
| `event` | object | 03/04 | `{event_id, event_type, user_id, biz_no, device_id, ip, phone, address_id, amount, scene_extra, ts}` |
| `snapshot` | object | 04 | `{snapshot_id, features, window_config, computed_at, missing_features}` |
| `decision` | object | **05** | `{decision_id, rule_score, model_score(=null), final_score, risk_level, decision, hit_rule_count, list_hit, engine_version, decided_at}` |
| `hits` | array | **05** | `[{rule_code, rule_name, rule_version, score, reason, matched_facts}]`，按 `score desc` |
| `profile` | object | **09** | `{user:{...}, devices:[...], ips:[...], addresses:[...]}` |
| `baseline` | object | **09** | `{field: 基线值}`，供快照对比列渲染 |
| `graph` | object | **09** | `{nodes:[...], edges:[...], max_hop:2}` |
| `degraded_parts` | array | — | 若某部分数据取用失败，列出 `["graph","profile"]` 等，**前端据此分区降级而非整页失败** |

**状态码**：`200` / `404 CASE-4001 案件不存在` / `403 CASE-4031`
**幂等性**：只读，天然幂等。

> **契约冻结**：`decision` / `hits` 两块的字段**必须与 05 的 `POST /api/v1/engine/evaluate` 响应同源**（同一组装函数），本模块**不得自行拼装**判定摘要。

### 3.3 认领案件（**拥有者：08**，本模块发起）

#### `POST /api/v1/cases/{case_no}/claim`

| 字段 | 类型 | 必填 | 约束 |
|---|---|:--:|---|
| `expected_status` | enum | ✔ | 必须为 `pending`，否则 `409` |
| `expected_version` | int | | 可选乐观锁（若 08 实现）；本模块默认发送 |

**服务端行为**：`status: pending → reviewing`，写 `assignee = 当前用户`、`claimed_at = now`，写审计（`case.claim`，属 08/12）。
**幂等性**：**幂等**——若 `assignee` 已是当前用户且 `status=reviewing`，返回 `200` 且 `changed=false`；若 `assignee` 是他人，返回 `409 CASE-4002`。
**状态码**：`200` / `404 CASE-4001` / `409 CASE-4002 案件已被他人认领` / `409 CASE-4003 案件状态不允许认领` / `403 CASE-4032 无案件处置权限`

### 3.4 列表页统一契约（本模块）

| 项 | 约定 |
|---|---|
| 分页 | `page`（≥1）、`page_size`（1~100，默认 20，页面固定 20） |
| 超界 | `page` 超过总页数返回空 `items` + 正确 `total`（**不报错**）；`page > 200` → `400 CASE-4004` |
| 排序 | `sort=字段:asc\|desc`；字段白名单：`created_at` / `risk_score` / `risk_level` / `status`；其他 → `400 CASE-4004` |
| 复合筛选 | 不同字段之间 **AND**；同字段多值 **OR**；时间区间**含头含尾** |
| 空态 | 无案件：「暂无风控案件」；筛选命中 0：「当前筛选条件下无案件」+ 清空筛选 |
| 加载态 | 首次骨架屏；翻页/筛选遮罩 + 保留旧数据；**请求序号 + `AbortController`，乱序响应丢弃** |
| 失败态 | 保留旧列表 + 顶部错误条 + `重试` |
| 一致性 | 响应带 `as_of`，右上角显示「数据截至 xx:xx:xx」 |

| `POST /api/v1/cases/{case_no}/dispose` | **08** | **处置提交（本模块只把表单数据交给 08 的提交流程）** |

## 4. 业务规则

> 编号规则：`BR-07-xx`，从 01 连续。

### 4.1 筛选与列表

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-07-01** | 四个筛选条件之间为 **AND**：风险等级 ∧ 事件场景 ∧ 审核状态 ∧ 触发时间区间 | PRD 2.3.3 |
| **BR-07-02** | `risk_level` 筛选用案件上的**冗余快照** `risk_cases.risk_level`，**不用当前规则集重算**（案件生成后规则可能已变） | E08 字段设计 |
| **BR-07-03** | 默认排序：`risk_level desc`（`high` 在 `medium` 前）→ `created_at desc`；用户切换排序后写入 hash，刷新不丢 | 本模块取值 |
| **BR-07-04** | 每页固定 **20** 条；`page_size` 由页面写死，不提供切换 | 原型 `pgBar` |
| **BR-07-05** | 任一筛选变化必须**同时**把 `page` 重置为 1，并把筛选状态写入 URL hash（可分享、可前进后退） | 可用性要求 |
| **BR-07-05b** | 顶部「共 N 条待审」中的 `N` 必须来自**列表接口的 `total`**，不得由前端对当前页计数 | 禁止前端自行统计（对齐 00 总纲 §3.2 精神） |

### 4.2 三栏联动（本模块的核心不变量）

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-07-06** | 左栏行点击 → 发起**一次** `GET /api/v1/cases/{case_no}` → **中栏与右栏使用同一次响应渲染，必须同帧更新**；不允许中栏/右栏各自发请求 | 原型注记第 1 条「不得异步错位」 |
| **BR-07-07** | 渲染采用"**先清空、后整体替换**"：切换案件时立即把中栏与右栏切成加载态，**不得继续展示上一个案件的画像/图谱** | 防止串档（审错案件） |
| **BR-07-08** | 竞态防护：每次切换案件生成递增 `request_seq`；响应回来时若 `seq != 当前 seq` **直接丢弃**；同时用 `AbortController` 取消上一个未完成请求 | 连点防护 |
| **BR-07-09** | 响应中的 `case.case_no` 与当前选中案件号不一致时**丢弃该响应**（服务端串号兜底） | 纵深防御 |
| **BR-07-10** | 当前选中案件号写入 hash（`&case=CASE0923001`）；页面刷新后按该参数**自动重新选中并展开三栏**；参数指向不存在或不在当前筛选结果的案件时，清空 `case` 参数并展示列表空选中态 | 可复现/可分享 |
| **BR-07-11** | 快照对比的**基线值由 09 提供**，本模块**不自己算基线**；未提供基线时该列显示 `—`（见待确认项「新增-3」） | 边界裁定 |
| **BR-07-12** | `degraded_parts` 非空时**分区降级**：只把对应卡片显示为「xx 加载失败 + 重试」，其余卡片与左栏保持可用；**不得整页白屏、不得静默隐藏失败卡片** | fail-safe 展示（不能因缺数据而误导研判） |

## 5. 异常处理

### 5.1 错误码清单（前缀 `CAS`）

| 错误码 | 场景 | HTTP | 处理策略 | 用户可见提示 |
|---|---|---|---|---|
| `CASE-4001` | 案件不存在或已归档 | 404 | 返回错误 | 「案件不存在或已被归档」 |
| `CASE-4002` | 认领冲突（已被他人认领） | 409 | 返回错误并刷新列表 | 「该案件已被 XXX 认领」 |
| `CASE-4003` | 列表查询参数非法 | 422 | 返回错误 | 「筛选条件不合法」 |
| `CASE-5001` | 详情聚合超时（画像/图谱慢） | 200（降级） | **分区降级** | 「画像加载失败，其余信息正常展示」 |
| `CASE-5002` | 关联图谱查询降级 | 200（降级） | 图谱区单独占位 | 「关联图谱暂时不可用」 |
| `CASE-4001` | 案件不存在 | 404 | 拒绝 | 「案件不存在或已被归档清理」+ 自动取消选中 |
| `CASE-4002` | 案件已被他人认领 | 409 | 拒绝，并刷新该案件 | 「案件已被 {assignee} 认领」 |
| `CASE-4003` | 案件状态不允许认领（`disposed`/`archived`） | 409 | 拒绝 | 「该案件已处置，无法认领」 |
| `CASE-4004` | 筛选/分页/排序参数非法（时间跨度 >90 天、非法排序字段、`page>200`、`created_from > created_to`） | 400 | 拒绝 | 「查询条件不合法：…」 |
| `CASE-4005` | 处置表单不完整（结论/动作/备注缺失） | 400 | **前端前置拦截**，不发请求；服务端兜底同样拒绝 | 「请选择处理结论 / 至少一项处置动作 / 填写备注」 |
| `DSP-4003` | 处置提交时案件状态已变更（**08 定义**） | 409 | 由 **08** 返回；本模块展示后刷新案件 | 「案件状态已变更，请刷新后重试」 |
| `CASE-4031` | 无案件查看权限 | 403 | 拒绝 | 「当前角色无案件查看权限」 |
| `CASE-4032` | 无案件认领/处置权限（`admin`） | 403 | 拒绝 | 「当前角色为只读，请联系风控审核员处置」 |
| `CASE-5001` | 案件详情聚合超时（画像/图谱/决策任一子请求超时） | 200 | **部分成功 + `degraded_parts`**，分区降级 | 对应卡片显示「xx 加载失败」+ `重试` |
| `CASE-5002` | 图谱服务不可用 | 200 | 图谱卡降级为「图谱服务暂不可用，仅展示画像」 | 见左 |
| `CASE-5003` | 画像服务不可用 | 200 | 画像卡降级占位，其余可用 | 「画像加载失败」+ `重试` |
| `CASE-5004` | 判定摘要（`decisions`）读取失败 | 200 | **右栏摘要区显示「判定数据缺失」并置灰，同时顶部显式告警**；**不得显示 0 分或"放行"** | 「未取到系统判定数据，请勿据此放行」 |
| `CASE-5005` | 列表接口 5xx | 503 | 保留旧列表 + 错误条 + `重试` | 「案件列表加载失败，请重试」 |

### 5.2 fail-safe 展示原则（**本模块的红线**）

| 原则 | 说明 |
|---|---|
| **缺数据≠放行** | `CASE-5004` 时右栏必须显式告警"判定数据缺失，请勿据此放行"，**绝不用 0 分/绿色/放行默认值填充** |
| **部分失败不隐瞒** | `degraded_parts` 涉及的卡片必须显示失败态，**不允许静默隐藏**——审核员有权知道哪些证据没看到 |
| **不产生误动作** | 任何加载失败都**不得**把处置区自动设为"已勾选动作"或"已选结论"；失败时处置区回到空表单 |
| **不越权代执行** | 处置执行失败由 08 负责；本模块不重试执行、不做本地乐观状态更新 |

### 5.3 破坏性操作与二次确认（承接原型评审遗留问题 3）

| 操作 | 归属 | 本模块职责 |
|---|---|---|
| 处置提交（不可撤销） | **08** 渲染 `06_处置二次确认弹窗.pen` | 本模块只把表单数据交给 08；**不得自行弹一个简化确认框就调执行接口** |
| 认领 | 本模块 | 认领**可撤销性弱**（仅是占用），采用一次点击 + 结果提示，不强制二次确认；但并发冲突必须给出明确提示（BR-07-14） |

### 5.4 降级与依赖不可用

| 依赖 | 不可用时 | 对审核员的影响 |
|---|---|---|
| 09 画像/图谱 | 中栏对应卡片降级占位 | 仍可看事件、快照、判定摘要与命中明细，**足以完成基本研判** |
| 05 判定数据 | 右栏摘要区告警置灰 | 仍可看画像与快照；**必须人工更谨慎**，页面明示 |
| 08 列表接口 | 保留旧列表 + 错误条 | 无法翻页/筛选，但已加载的数据仍可查看 |
| 04 快照 | 快照卡显示「快照缺失（冷启动或异步落库未完成）」 | 提示可重试（快照异步落库，AD-01） |
