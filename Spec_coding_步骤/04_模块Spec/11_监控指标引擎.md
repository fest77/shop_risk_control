## 1. 模块定位

| 项 | 内容 |
|---|---|
| **职责** | 指标桶**写入时增量聚合**（`$inc` upsert，AD-03）；四类维度（`global` / `rule` / `level` / `scene`）统计口径计算；时间桶对齐与多粒度（`1m` / `1h` / `1d`）；吞吐与延迟统计；对外查询接口（含 SSE 实时事件流） |
| **触发时机** | ① 每次决策**落库成功后**异步聚合（高频，不阻塞决策链路）；② 定时 rollup（每 60s / 每日 00:05）；③ 大盘查询时只读指标桶 |
| **上游** | 05 规则决策引擎（`decisions` + `decision_hits` 落库成功事件）；00 公共基础（Mongo 连接、错误码、枚举）；13 系统设置（指标桶粒度参数） |
| **下游** | **02 态势大盘**（4 卡片 + 3 图表 + SSE 事件流）；13 系统设置（吞吐与接口健康度） |
| **对应 PRD** | 2.3.3 风控态势大盘页（五项展示）、**2.3.6 监控与审计模块**（“风控决策指标统计汇总”）、2.3.10 验收“能在态势大盘查看实时拦截率、风险分布与规则命中排行” |
| **对应实体** | **写/读 E15 `metric_buckets`**；读 E03 `decisions`、E04 `decision_hits`（仅作聚合输入，**不写**）、读 E08 `risk_cases`（仅统计待审数） |
| **对应原型** | `02_风控态势大盘页.pen`（4 卡片 / 拦截率趋势 / 风险等级分布 / 规则命中排行 / 实时事件流）、`08_系统设置页.pen`（实时 QPS、决策 P95 延迟） |
| **对应架构决策** | **AD-03**（写入时 `$inc` upsert，不做查询时聚合）、AD-01（决策同步返回 / 落库异步）、AD-06（与图谱无关，明确不涉及） |

**本模块明确不做的事**（防止与 02 / 05 / 12 重叠）：

- **不做页面渲染、不做格式化**（`12,847`、`4.7%`、分转元全在 02）——见 `00_模块划分与边界.md` §3.2
- **不写** `decisions` / `decision_hits`（归 05）；**不判定**事件是否拦截（归 05），只统计 05 已产出的结论
- **不做审计哈希链**与操作留痕（归 12）；查询接口为只读，不写 `audit_logs`
- **不在查询时聚合 `decisions` 全表**（AD-03 硬约束）；查询只扫 `metric_buckets`
- **本模块不参与放行判定**：指标写入失败**不改变**任何决策结果，也不触发 `review`（详见 §5）

### 2.1 展示点 A：`02 大盘` · 4 张指标卡片（`statRow`）

### 3.7 `GET /api/v1/metrics/stream`（SSE）

**请求**：`Accept: text/event-stream`；参数 `scene`、`level` 可选（服务端过滤）。

**响应头**：`Content-Type: text/event-stream`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`、`Connection: keep-alive`。

**帧格式**（按 SSE 规范，事件之间以空行分隔）

```
retry: 3000

id: 10231
event: risk_event
data: {"seq":10231,"event_id":"EVT20260923000218","ts":1758600271208,"event_type":"coupon_receive","user_id":"U000128","final_score":86,"risk_level":"high","decision":"reject","list_hit":null,"hit_rule_count":3,"biz_no":"CPN-20260923-8821","amount":20000,"case_no":"CASE0923001","dropped_cnt":0}

event: heartbeat
data: {"ts":1758600286208,"subscribers":3}
```

| 帧 | 频率 | 说明 |
|---|---|---|
| `risk_event` | 每个事件决策落库成功后 | `id` = 单调递增 `seq`，供 `Last-Event-ID` 补偿；`dropped_cnt` 为**本连接**因背压丢弃的累计条数 |
| `heartbeat` | 每 **15s** 一次（无事件时也发） | 防代理 / 网关空闲断链，同时供页面判活 |
| `gap` | 重连后无法补偿时一次性发送 | `data: {"missed":true,"reason":"buffer_exhausted"}`，02 显示「事件流存在缺口」提示 |
| `shutdown` | 服务端优雅停机前 | `data: {"reason":"server_shutdown"}`，02 不重连直至用户手动刷新 |

**重连与补偿**：浏览器 `EventSource` 按 `retry: 3000` 自动重连，并在请求头携带 `Last-Event-ID`；服务端从**进程内环形缓冲（容量 200 条）** 中补发 `seq > Last-Event-ID` 的事件；缺口超出缓冲则发 `gap` 帧并转为纯实时推送。

**背压**：每个订阅者独立 `asyncio.Queue(maxsize=500)`；队列满时丢弃**最旧**事件并把丢弃数累加到后续事件的 `dropped_cnt`，同时记告警日志；**不阻塞**决策链路。

**订阅上限**：并发订阅数上限 50，超出返回 `503` + `MET-5004`。

**鉴权**：`EventSource` 无法写入 `Authorization` 头，故本端点**同时接受** `Authorization: Bearer <JWT>`（供 `fetch + ReadableStream` 方案）与查询参数 `?token=<JWT>`（供原生 `EventSource`）；实现优先用原生 `EventSource`，并把「token 出现在 URL / 访问日志」的风险登记在第 8 章。

### 3.8 `POST /api/v1/metrics/rollup`

**请求**：`{granularity: "1h"|"1d", from_ts: long, to_ts: long, dimension: "all"|"global"|"rule"|"level"|"scene"}`

**响应**：`{upserted: int, scanned_1m_buckets: int, elapsed_ms: int}`

**幂等**：rollup 使用 `$set`（覆盖）而非 `$inc`，**同一时间窗重复执行结果完全一致**（BR-11-15）。

### 3.9 内部契约（非 HTTP，供 05 / 08 的异步落库任务调用）

```python
async def record_decision(event: EventLite, decision: DecisionDoc, hits: list[HitDoc]) -> None
```

| 入参 | 说明 |
|---|---|
| `event` | `{event_id, event_type, user_id, ts, amount}` |
| `decision` | `{event_id, scene_code, risk_level, decision, final_score, elapsed_ms}` |
| `hits` | `[{rule_code, score}]`，命中 0 条时为空数组 |

**调用约定（重要）**：必须在 `decisions` **落库成功之后**调用；`decisions` 的 `event_id` 唯一索引冲突（重复事件）时**跳过**调用——这是本模块幂等性的唯一保障（BR-11-10）。

### 3.10 桶文档结构（写入契约）

```json
{
  "_id": "global:all:1m:1758600000000",
  "bucket_type": "global",
  "bucket_key": "all",
  "granularity": "1m",
  "bucket_ts": 1758600000000,
  "metrics": {
    "event_cnt": 1280, "pass_cnt": 1100, "review_cnt": 120, "reject_cnt": 60,
    "score_sum": 30080, "score_cnt": 1280,
    "elapsed_sum": 15360, "elapsed_cnt": 1280,
    "elapsed_hist": {"le5": 120, "le10": 400, "le20": 500, "le30": 150, "le50": 80, "le75": 20, "le100": 8, "le200": 2, "gt200": 0},
    "estimated_saved_amount": 3580000,
    "saved_amount_by_type": {"login": 0, "coupon_receive": 600000, "order_create": 1200000, "order_pay": 1300000, "after_sale_apply": 480000}
  },
  "updated_at": 1758600001234
}
```

| 维度 | `bucket_key` | `metrics` 实际写入字段 |
|---|---|---|
| `global` | 固定 `all` | 上述全量字段 |
| `level` | `low` / `medium` / `high` | `event_cnt` `pass_cnt` `review_cnt` `reject_cnt` `score_sum` `score_cnt` `estimated_saved_amount` `saved_amount_by_type` |
| `scene` | `login` / `coupon` / `order` / `aftersale` | 同 `level` |
| `rule` | `rule_code`（**每条命中一次**） | `hit_cnt` `pass_hit_cnt` `review_hit_cnt` `reject_hit_cnt` `hit_score_sum` |
| `global`（延迟） | 固定 `all` | `elapsed_sum` `elapsed_cnt` `elapsed_hist` |

> ⚠️ 与 E15 的两处差异（已在第 8 章登记）：① `_id` 增加了 `granularity` 段（否则整点处 `1m` 与 `1h` 桶同 `ts` 会**互相覆盖**）；② E15 样例中的 `block_rate` / `avg_score` / `avg_elapsed_ms` **不在桶内存放**，改为读取时由原始累计量导出（见 BR-11-07）。

## 4. 业务规则

> 编号规则：`BR-11-xx`，从 01 连续。每条可判定、可测。

### 4.1 桶结构与时间对齐

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-11-01** | 桶主键 `_id = {bucket_type}:{bucket_key}:{granularity}:{bucket_ts}` | E15（**修正**：原格式缺 `granularity` 段，见第 8 章） |
| **BR-11-02** | `1m` 桶按分钟对齐 `floor(ts/60000)*60000`；`1h` 桶按整点对齐 `floor(ts/3600000)*3600000`；**`1d` 桶按 `Asia/Shanghai` 00:00 对齐**（`floor((ts+8h)/86400000)*86400000 - 8h`，不可用 UTC 整日对齐，否则日桶边界落在北京时间 08:00） | E15 `bucket_ts` 定义 + 时区约定 |
| **BR-11-03** | **写入时只写一个基础粒度桶**（默认 `1m`，可由 13 的运行参数改为 `1m`/`1h`，**不允许 `1d`**）；`1h` / `1d` 桶由 rollup 生成 | AD-03 + 性能（见 BR-11-16） |
| **BR-11-04** | 一次决策写入的桶数 = `3 + N`（`global` + `level` + `scene` + 每条命中规则的 `rule` 桶，`N = hit_rule_count`） | E15 四维度 |
| **BR-11-05** | 全部计数一律 `$inc` upsert + `$setOnInsert` 写静态字段（`bucket_type` / `bucket_key` / `granularity` / `bucket_ts` / `created_at`）；**禁止** `findAndModify` 读改写 | AD-03（概要设计 §4.3） |
| **BR-11-06** | 若 `event_type` 无法映射 `scene_code`，`scene` 维度桶写入 `unknown` 键并记告警，**不阻断**其余维度写入 | 容错设计 |
| **BR-11-07** | 派生量 `block_rate` / `avg_score` / `avg_elapsed_ms` / `hit_ratio` / `p95_elapsed_ms` **一律在读取时由原始累计量计算**，桶内不存派生值（避免读改写与并发覆盖） | E15 `metrics` 样例的澄清，见第 8 章 |
| **BR-11-08** | 分母为 0 的派生量返回 `null`，**不得返回 0**（页面显示 `—`）；`null` 与“真实的 0”必须有区别 | 空态/冷启动正确性 |
| **BR-11-09** | 派生浮点量统一**服务端四舍五入到 4 位小数**，页面只负责展示位数 | 边界 §3.2（计算在 11） |

### 4.2 幂等与一致性

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-11-10** | 指标写入**必须**在 `decisions` 成功落库后触发；重复事件（唯一 `event_id` 冲突）跳过写入 → 语义为 **at-most-once**（宁少计不重复计），跨天重复由 rollup 补算修复 | 概要设计 §6 幂等要求 |
| **BR-11-11** | 桶写入失败**不回滚决策**，进入重试队列；重试与首次写入共享 BR-11-10 的幂等条件 | AD-01 / 概要设计 §6 |
| **BR-11-12** | **决策与等级的 1:1 映射是跨筛选的唯一依据**：`pass↔low`、`review↔medium`、`reject↔high`（BR-05-17）。因此 `scene` 桶的分档计数可直接充当该场景下的等级分布，`rule` 桶的分档计数可直接充当该等级下的命中排行——从而**无需**引入 E15 之外的第 5 个维度 | BR-05-17 复用；若未来引入 Challenge 档则本规则失效（见第 8 章） |

### 4.3 统计口径

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-11-13** | 延迟统计用**写入时直方图**：分桶边界 `[5,10,20,30,50,75,100,200,+∞)` ms，每个 `le{k}` 计数 `$inc`；`p95` 由累计直方图**线性插值**求近似值，误差目标 ≤10% | 本模块定义（禁止为 P95 扫 `decisions`） |
| **BR-11-14** | `estimated_saved_amount = Σ(reject 且 event_type ∈ 五类 的 event.amount)`，缺 `amount` 按 0 计；**`login` 恒为 0**；按事件类型分项累计到 `saved_amount_by_type` | ⚠️ 悬空点 **G-09**（默认口径；原型的「Σ 被拦截订单金额」与之一致）。已知偏差：同一 `order_no` 的 `order_create` 与 `order_pay` 均被 reject 时会**重复计入**，缓解措施见第 8 章 |
| **BR-11-15** | rollup 每 **60s** 执行一次，用 `$set` **重算**上一个已闭合的 `1h` 桶（幂等）；每日 `00:05 Asia/Shanghai` 重算前一日 `1d` 桶；只读 `1m` 桶，**不读** `decisions` | AD-03 + BR-11-03 |
| **BR-11-16** | 写入成本上限：单事件最多 `3 + N` 次 upsert（典型 `N=3` → 6 次）；若开启 `1h` 基础粒度，1 小时内的 `1m` 级趋势不可用，`range=1h` 时降级返回 1 个点并置 `truncated=true` | 性能护栏 |
| **BR-11-17** | `pending_case_cnt` 为**当前态 gauge**，直接 `count(status=pending)`，**不套用 `range` / `scene` / `level` 筛选**（筛选变化时仍重新查询，保证同屏数据同刻一致） | 原型标注「status = pending」 |

### 4.4 查询与缓存

| 编号 | 规则 | 依据 |
|---|---|---|
| **BR-11-18** | 查询接口**只读** `metric_buckets`（+ 排行联查 `rules.name`、卡片联查 `risk_cases` 计数），**禁止**触达 `decisions` / `decision_hits` 明细集合 | **AD-03 硬约束** |
| **BR-11-19** | 查询结果进程内缓存 **TTL 3s**（小于页面 5s 自动刷新间隔），并对相同查询键做 **single-flight 合并**（多客户端同时请求只查一次库） | 本模块定义（性能 + 一致性） |
| **BR-11-20** | Mongo 不可用时返回**最近一次成功快照** + `stale=true`；从未成功过则 `503`。降级响应**不得**返回 0 值冒充真实数据 | fail-closed 的数据版本（§5） |
| **BR-11-21** | 桶保留：`1m` **7 天** TTL、`1h` **90 天**、`1d` **永久**；TTL 由 Mongo TTL 索引按 `bucket_ts` 执行（仅作用于 `1m`/`1h`） | E15 + 概要设计 §4.1（`1h`/`1d` 为新增取值，见第 8 章） |
| **BR-11-22** | 列表接口排序固定下沉到数据库：趋势按 `bucket_ts` 升序、排行按计数字段降序 + `rule_code` 升序、分布按 `key` 固定序（`low/medium/high` 或场景 `sort`） | 边界 §3.2（排序即计算） |

## 5. 异常处理

> 错误码前缀 `MET`。**码段划分**：`11` 使用 `MET-4xxx`（参数类）与 `MET-5xxx`（服务端类）；`02` 使用 `MET-6xxx`（页面本地码）。两个模块共用 `MET` 前缀，该划分已登记在第 8 章。

| 错误码 | 场景 | HTTP | 处理策略 | 用户可见提示 |
|---|---|---|---|---|
| `MET-4001` | `range` 非法 / 缺省值越界 | 400 | 拒绝，返回合法枚举 | 「时间范围参数不合法，可选 1h/24h/7d/30d」 |
| `MET-4002` | `granularity` 与 `range` 不匹配（如 `1h` + `1d`） | 400 | 拒绝 | 「时间粒度与范围不匹配」 |
| `MET-4003` | `top` 超出 1~50 | 400 | 拒绝，回落默认 10 并提示 | 「Top 取值需在 1~50，已按 10 返回」 |
| `MET-4004` | `dim` 非法 / `bucket_key` 非法（内部） | 400 | 拒绝 | 「分布维度不合法」 |
| `MET-4005` | `from_ts` > `to_ts`（rollup） | 400 | 拒绝 | 运维接口，无页面提示 |
| `MET-5001` | Mongo 查询不可用 | 200（含 `stale=true`）或 503 | **降级**：返回最近一次成功快照；无快照才 503 | 「数据可能已过期（{stale_at}），正在重试」 |
| `MET-5002` | 指标桶写入失败 | —（异步） | 不进重试队列不阻断决策；记 WARN + 计数；由 rollup / 手动补算修复 | 无（决策不受影响） |
| `MET-5003` | `elapsed_hist` 缺失 | 200 | `p95_elapsed_ms = null` | 「延迟统计暂不可用」 |
| `MET-5004` | SSE 订阅数超上限（50） | 503 | 拒绝新连接，**不踢**既有连接 | 「实时事件流连接数已满，请稍后重试」 |
| `MET-5005` | SSE 订阅者队列溢出 | —（连接内） | 丢弃最旧事件，累加 `dropped_cnt` | 「事件流已丢弃 {n} 条（刷新过快）」 |
| `MET-5006` | rollup 执行失败 | 500（手动）/ 记日志（定时） | 本轮放弃，下一轮重试；查询仍返回已有桶 | 运维接口，无页面提示 |
| `MET-5007` | 桶内计数与 `decisions` 复核不一致（日检） | —（告警） | 记 WARN + 差异计数，提供 `POST /rollup` 修复入口 | 无（运维告警） |

> **fail-closed 说明（本模块不参与放行判定）**：指标引擎是**决策链路的旁路**。它的读写失败既不产生 `pass`，也不产生 `review`——因为本模块**根本不参与**放行判定（PRD 2.3.4 的仲裁归模块 05）。
> 唯一的 fail-closed 义务是**数据侧**：宁可返回 `null` / `stale=true` / `—`，也**不得**用 0、0.00% 或空图表冒充满足的数据（BR-11-08 / BR-11-20），否则会误导运营判断。
