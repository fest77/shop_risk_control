| 项 | 内容 |
|---|---|
| **职责** | ① 审计事件写入（**哈希链**）② **全链完整性校验** ③ 审计流水多维查询 ④ 导出 ⑤ 保证只读、不可篡改 |

| **对应架构决策** | **AD-04**（哈希链单写者 + `asyncio.Lock` 串行化，解决并发分叉） |

### 2.1 哈希链完整性卡片 `vfCard`

| 元素 | 绑定 | 说明 |
|---|---|---|
| 标题「审计哈希链完整性」 | — | 16px/600 |
| 「▶ 执行全链校验」按钮 | 触发校验 | primary；执行中禁用 + 转圈；结果就地展示 |
| 统计项 1「链长度」 | `chain_length` | 如 `12,847 条`（20px/700） |
| 统计项 2「创世哈希」 | `genesis_hash` | 固定 `GENESIS`，等宽字体 |
| 统计项 3「最新区块哈希」 | `head_hash` | 如 `0x8f3a…c21d`，等宽字体 |

| 说明文字 | 静态 | 写明校验算法：`sha256(prev_hash + 本条内容)`，从创世块逐条重算，返回首个不一致位置 |

**状态**

| 状态 | 表现 |
|---|---|
| 未校验 | 结果项显示「未校验」，灰色 |
| 校验中 | 按钮转圈；结果项显示「校验中…」 |
| 通过 | 绿底成功标签 + 显示校验耗时 |
| 失败 | **红底**「发现篡改：第 N 条哈希不匹配」，并列出不匹配条目的 id 与期望/实际哈希 |

## 3. 接口字段

### 3.1 `GET /api/v1/audit/logs` — 审计流水查询

**请求参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `actor` | string | 可选 |
| `action` | string | 可选，支持前缀匹配（如 `rule.`） |
| `target_type` | string | 可选 |
| `target_id` | string | 可选 |
| `from` / `to` | long | 可选，时间范围（毫秒） |
| `page` / `size` | int | 分页，遵循 00 的分页契约 |

**响应 `data`**：`{items: [...], total, page, size, pages}`

`items[]` 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `log_id` | string | `LOG*` |
| `ts` | long | 时间戳 |
| `actor` / `actor_role` | string | 操作人与角色 |
| `action` | string | 动作 |
| `target_type` / `target_id` | string | 目标 |
| `before` / `after` | object \| null | 变更前后快照 |
| `ip` / `ua` | string | 来源 |
| `hash` / `prev_hash` | string | 哈希链 |

**权限**：仅 `admin`。其他角色 → `403 AUTH-4020`。

### 3.2 `GET /api/v1/audit/verify` — 全链完整性校验（**核心接口**）

**请求**：`from_seq`（可选，默认从创世块开始）、`limit`（可选，分段校验用）

**响应 `data`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | bool | 全链是否一致 |
| `chain_length` | int | 校验的区块数 |
| `genesis_hash` | string | 固定 `GENESIS` |
| `head_hash` | string | 最新区块哈希 |
| `broken_at` | object \| null | `{log_id, ts, seq, expected_hash, actual_hash}`；一致时为 `null` |
| `elapsed_ms` | int | 校验耗时 |

**要求**：必须**真实逐条重算**（不得返回固定值或只校验长度）。校验过程中**不得写入新审计**（否则期间新写入会导致误报），实现上取"校验开始时的 head"作为终点。

### 3.3 `GET /api/v1/audit/export` — 导出

**请求**：同 3.1 的筛选参数；`format` = `csv` / `markdown`

**响应**：文件流（`Content-Disposition: attachment`）。导出操作本身**也要写一条审计**（`action=audit.export`）。

### 3.4 内部写入接口（供各业务模块调用）

```python
async def audit(
    actor: str, actor_role: str, action: str,
    target_type: str, target_id: str,
    before: dict | None = None, after: dict | None = None,
    ip: str | None = None, ua: str | None = None,
    strict: bool = False,     # True 时写入失败向上抛错，阻断业务操作
) -> str: ...
```

| 参数 | 说明 |
|---|---|
| `strict` | **紧操作必须传 `True`**（处置、规则/名单变更、配置变更）；普通操作传 `False`（失败仅告警） |
| 返回 | `log_id` |

## 4. 业务规则

### 4.1 哈希链算法（**必须精确，否则校验无法复现**）

| 编号 | 规则 |
|---|---|
| **BR-12-01** | 创世块：`prev_hash = "GENESIS"`（字符串常量），首条记录的 `prev_hash` 必须为 `GENESIS` |
| **BR-12-02** | 哈希公式：`hash = sha256(prev_hash + "|" + canonical_payload)`，输出 **64 位小写十六进制**（页面展示时缩略为 `0x前4…后4`） |
| **BR-12-03** | `canonical_payload` 的**规范化规则必须固定**：字段顺序固定为 `ts\|actor\|actor_role\|action\|target_type\|target_id\|before\|after`；`before`/`after` 用 **JSON 序列化且 `sort_keys=True, separators=(",",":"), ensure_ascii=False`**；`null` 序列化为空串 |
| **BR-12-04** | 规范化函数**只有一份实现**（`audit_hash.py`），写入与校验必须调用同一个函数——两处各写一份必然漂移 |
| **BR-12-05** | 每条记录同时存 `prev_hash` 与 `hash`；**不允许只存 `hash`**（否则无法定位断链点） |

### 4.2 并发与写入

| 编号 | 规则 |
|---|---|
| **BR-12-06** | 写入必须**单写者串行化**（AD-04）：持有 `asyncio.Lock` 完成「读 head → 计算 hash → 插入」整个复合操作，**不允许跨 await 释放锁** |
| **BR-12-07** | 为降低锁竞争，审计写入**异步排队**（内存队列 + 单消费者协程），业务侧只入队不等待；但 `strict=True` 时必须**等待落库确认** |
| **BR-12-08** | 队列写入失败时**重试 3 次**（指数退避）；仍失败且 `strict=True` → 抛 `AUD-5001` 阻断业务操作 |
| **BR-12-09** | 进程重启后 `head` 从库中最后一条恢复；**若库为空，以创世块重新开始** |
| **BR-12-10** | **禁止多个进程同时写审计**（会分叉）。当前单进程部署；若上多进程必须改为集中式写（见 §8） |

### 4.3 不可篡改与只读

| 编号 | 规则 |
|---|---|
| **BR-12-11** | `audit_logs` **append-only**：不提供 update/delete 接口，代码中不得出现对该集合的 `update_*`/`delete_*` 调用 |
| **BR-12-12** | 审计记录**不设 TTL**（永久保留），与 `risk_events` 的 90 天 TTL 不同 |
| **BR-12-13** | 校验失败（发现篡改）时必须**页面显红 + 记录一条 `audit.tamper_detected`**（这条本身也进链），并告警 |
| **BR-12-14** | 校验接口**只读**，不得在链中插入标记（除 BR-12-13 的告警记录） |
| **BR-12-15** | 导出操作本身也要审计（`action=audit.export`），防止"谁导走了数据"无迹可查 |

### 4.4 必须审计的动作（清单）

| 编号 | 规则 |
|---|---|
| **BR-12-16** | **必须记录且 `strict=True`** 的动作：`rule.create`、`rule.update`、`rule.toggle`、`rule.delete`、`list.add`、`list.remove`、`list.import`、`case.dispose`、`case.claim`、`config.update`、`user.create`、`user.disable`、`user.role_change` |
| **BR-12-17** | **必须记录但 `strict=False`** 的动作：`event.receive`、`auth.denied`、`audit.export`、`sim.run`、`auth.login`、`auth.logout` |
| **BR-12-18** | 变更类动作（`rule.update`/`config.update`/`user.role_change`）**必须携带 `before` 与 `after`**；缺任一项即为缺陷 |
| **BR-12-19** | `auth.denied`（越权尝试）必须记录 `target_type`/`target_id` 与尝试的动作，**不得省略**（对齐 01 的 BR-01-15） |

### 4.5 查询与呈现

| 编号 | 规则 |
|---|---|
| **BR-12-20** | 查询默认按 `ts desc`；**不允许按 `hash` 排序**（无意义且无法走索引） |
| **BR-12-21** | 单页最大 `size=100`；导出上限 **10000 条**，超出提示缩小范围（`AUD-4002`） |
| **BR-12-22** | 变更摘要由**前端派生**（对比 `before`/`after` 生成"分值 30→40"式文案）；后端只返回结构化 before/after |
| **BR-12-23** | 哈希在列表中以**缩略形式**展示（`0x8f3a…c21d`），hover/展开显示完整 64 位 |
| **BR-12-24** | 仅 `admin` 可访问本页与接口；越权访问本身记为 `auth.denied` |

## 5. 异常处理

| 错误码 | 场景 | HTTP | 用户可见提示 | 处理 |
|---|---|---|---|---|
| `AUD-4001` | 校验参数非法（`from_seq` 超范围） | 422 | 「校验参数不合法」 | — |
| `AUD-4002` | 导出条数超上限 | 422 | 「导出数据量过大，请缩小时间范围」 | 上限 10000 |
| `AUD-4003` | 查询时间跨度超上限 | 422 | 「时间跨度不能超过 30 天」 | 防全表扫描 |
| `AUD-5001` | 审计写入失败（**紧操作**） | 503 | 「审计服务不可用，操作已中止」 | **阻断业务操作**并回滚，`strict=True` 语义 |
| `AUD-5002` | 审计写入失败（普通操作） | — | 无（后台） | 重试 3 次后告警，**不阻断**业务 |
| `AUD-5003` | 哈希链校验发现不一致 | 200 | **红底**「发现篡改：第 N 条」+ 明细 | 记录 `audit.tamper_detected` 并告警 |
| `AUD-5004` | 校验过程超时（链过长） | 200 | 「链较长，已校验前 N 条，可分段继续」 | 支持 `from_seq` 分段校验 |
| `AUD-5005` | 检测到多进程并发写风险 | — | 启动告警 | 启动时校验（见 §8） |

> **fail-closed 原则（关键）**：**紧操作**（处置、规则变更、名单变更、配置变更）在审计写入失败时**必须中止**。
> 理由：这些操作一旦执行就改变了风控行为，若没有留痕，事后无法追溯与问责——**宁可不做，不可无痕地做**。

## 8. 本模块遗留与待确认

| 编号 | 事项 | 当前取值 | 说明 |
|---|---|---|---|
| **G-10** | 审计哈希链并发写方案 | **单写者 + `asyncio.Lock` + 内存队列单消费者**（AD-04） | ⚠️ 当前方案**只支持单进程**。若上多进程/多副本必须改为集中式（如由唯一 writer 服务或数据库序列保证顺序），否则必然分叉 |
