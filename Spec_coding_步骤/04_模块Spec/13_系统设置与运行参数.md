## 2. 页面结构

对应原型 `08_系统设置页.pen`（画布 1440×1520），纵向 4 个卡片。

### 2.1 卡片一 · 风控运行参数 `rcCard`

两行三列，每项为「标签 + 输入/选择」。

| 参数 | 控件 | 默认 | 单位 | 生效方式 |
|---|---|---|---|---|
| 短窗口 | 输入（数字） | **60** | 分钟 | **下一事件生效** |
| 长窗口 | 输入（数字） | **1440** | 分钟 | **下一事件生效** |
| 内存窗口容量上限 | 输入（数字） | **10000** | 条/维度 | **立即生效**（下次 sweep 裁剪） |
| 名单缓存 TTL | 输入（数字） | **10** | 秒 | **立即生效**（同时清空现有缓存） |
| 决策链路超时 | 输入（数字） | **200** | 毫秒 | **立即生效** |
| 指标桶粒度 | 下拉 | **1 分钟** | — | **需重启** |

**底部说明行**：写明「窗口时长与容量对应悬空点 G-02 / G-12；名单缓存 TTL 决定新增黑名单的最长生效延迟（AD-02）」。
**按钮**：`保存运行参数`（primary）/ `恢复默认`（ghost）

**校验提示**：短窗口必须 < 长窗口；容量上限 1000~1000000；TTL 1~600；超时 50~5000。

### 2.2 卡片二 · 吞吐与接口健康度 `hcCard`

**4 张指标卡**

| 卡片 | 数据字段 | 配色规则 |
|---|---|---|
| 实时 QPS | `qps` | 正常品牌色 |
| 决策 P95 延迟 | `decision_p95_ms` | **> 50ms 标红**（对齐概要设计 §6 目标） |
| 名单缓存命中率 | `list_cache_hit_rate` | < 90% 标橙 |
| Mongo 连通性 | `mongo.connected` | 正常绿 / 异常红 |

**组件状态表**

| 组件 | 状态 | 说明 |
|---|---|---|
| MongoDB | `正常/异常` | `库 risk_control · N 个集合` |
| MinIO | `未使用/正常` | 当前不启用（Step2 §1.3） |
| 事件流模拟器 | `运行中/已停止` | `模式=羊毛党 · 5 events/sec · seed=42` |
| 决策引擎 | `rule-engine-v1` | **标注「模型引擎未启用（G-01）」** |

**刷新**：本卡片随页面自动刷新（10 秒），不受"保存"影响。

### 2.3 卡片三 · 账号与角色管理 `usCard`

| 列 | 字段 | 宽 |

## 3. 接口字段

### 3.1 `GET /api/v1/system/config` — 读取运行参数

**响应 `data`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `short_window_min` / `long_window_min` | int | 窗口（分钟） |
| `window_capacity` | int | 内存窗口容量上限 |
| `list_cache_ttl_sec` | int | 名单缓存 TTL |
| `decision_timeout_ms` | int | 决策链路超时 |
| `metric_bucket_granularity` | enum | `1m` / `1h` / `1d` |
| `effective_at` | long | 本次配置生效时间戳 |
| `config_version` | string | 配置版本（每次保存 +1） |

**权限**：仅 `admin`。

### 3.2 `PUT /api/v1/system/config` — 保存运行参数

**请求**：上述字段的子集（部分更新）。
**响应**：`{config_version, applied: ["list_cache_ttl_sec","decision_timeout_ms"], requires_restart: ["metric_bucket_granularity"]}`

> **必须返回 `applied` 与 `requires_restart` 两个数组**——让前端能明确告知"哪些已生效、哪些要重启"，避免用户以为改了没生效。

**状态码**：`200` / `422`（`SYS-4001` 取值越界、`SYS-4002` 短窗≥长窗）

### 3.3 `GET /api/v1/system/stats` — 吞吐与健康度

**响应 `data`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `qps` | float | 近 1 分钟事件 QPS |
| `decision_p50_ms` / `decision_p95_ms` / `decision_p99_ms` | int | 决策延迟分位 |
| `list_cache_hit_rate` | float | 名单缓存命中率（0~1） |
| `window` | object | `{total_events, per_dimension_max, est_mem_mb, last_sweep_at}` |
| `components` | array | `[{name, status, detail}]`（Mongo/MinIO/模拟器/引擎） |
| `uptime_sec` | int | 进程运行时长 |

### 3.4 账号管理接口

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| `GET` | `/api/v1/system/users` | 列表（分页 + `role`/`status` 筛选） | admin |
| `POST` | `/api/v1/system/users` | 新增账号 | admin |
| `PUT` | `/api/v1/system/users/{username}` | 改姓名 / 改角色 | admin |
| `POST` | `/api/v1/system/users/{username}/disable` | 停用 | admin |
| `POST` | `/api/v1/system/users/{username}/enable` | 启用 | admin |
| `POST` | `/api/v1/system/users/{username}/reset-password` | 重置密码 | admin |
| `DELETE` | `/api/v1/system/users/{username}` | 删除（受 §2.3 规则限制） | admin |

**`POST /users` 请求**：`{username, real_name, role, initial_password?}`
**响应**：`{username, generated_password?}`（未传 `initial_password` 时后端生成并**仅返回一次**）

**`PUT /users/{username}` 请求**：`{real_name?, role?}`

### 3.5 决策引擎配置接口

`GET /api/v1/system/engine-config` → `{engine_type, fuse_mode, rule_weight, model_weight, model_available: false, note}`

`PUT /api/v1/system/engine-config` → **当前仅接受 `engine_type=rule`**；传其他值返回 `SYS-4003`「模型引擎尚未实现」。

## 4. 业务规则

### 4.1 运行参数

| 编号 | 规则 |
|---|---|
| **BR-13-01** | 参数取值约束：短窗 `1~1440`、长窗 `1~10080`、且**短窗 < 长窗**；容量 `1000~1000000`；TTL `1~600` 秒；超时 `50~5000` ms |
| **BR-13-02** | 保存必须返回**生效方式**：`applied`（已立即生效）与 `requires_restart`（需重启）。**不得静默保存后不告知** |
| **BR-13-03** | 参数保存必须写审计（`action=config.update`，`strict=True`，含 `before`/`after`）——对齐 12 的 BR-12-16 |
| **BR-13-04** | **名单缓存 TTL 变更时必须立即清空现有缓存**，使新 TTL 立即对名单生效（对齐 AD-02 的"最长生效延迟"承诺） |
| **BR-13-05** | 窗口参数变更**不重启**：热更新到 `FeatureStore` 配置，**在下一个事件生效**；已有窗口数据在下次 sweep 时按新窗口裁剪 |
| **BR-13-06** | 窗口容量上限变更**立即生效**：超限部分在下次 sweep 被裁剪（需提示用户"可能丢弃历史窗口数据"） |
| **BR-13-07** | `metric_bucket_granularity` 变更**需重启**：因为涉及定时聚合任务周期的重建；返回在 `requires_restart` 中 |
| **BR-13-08** | 参数变更后 `config_version` **+1**，并随事件决策的快照/决策记录留存，保证"当时的参数"可追溯 |
| **BR-13-09** | 「恢复默认」需二次确认（影响在线行为），确认后按 §2.1 默认值保存 |

### 4.2 账号与角色

| 编号 | 规则 |
|---|---|
| **BR-13-10** | **本模块是 `sys_users` 的唯一写入方**；01 只读。禁止在 01 里新增/停用账号 |
| **BR-13-11** | `username` **全局唯一**，创建后**不可修改**（只改姓名与角色） |
| **BR-13-12** | 角色只能是 `reviewer` / `strategist` / `admin` 三者之一；**不允许自定义角色**（对齐 01 的 BR-01-11） |
| **BR-13-13** | **不允许停用或删除自己**（防止把自己锁在系统外） |
| **BR-13-14** | **不允许停用/删除最后一个可用的 `admin`**（系统必须始终至少有一个可用管理员） |
| **BR-13-15** | 停用账号时，其名下**未处置案件需转交**：提示管理员指定接收人（`reviewer` 角色），转交后原账号方可停用（对齐 01 §8 的待确认项） |
| **BR-13-16** | 重置密码后**该账号所有令牌立即失效**（依赖 01 的 BR-01-10 机制），并提示用户需重新登录 |
| **BR-13-17** | 删除账号仅限 `status=disabled` 且**无待处置案件**；删除为**软删除**（`status=deleted`），保留审计可追溯性 |
| **BR-13-18** | 所有账号变更（创建/停用/启用/改角色/重置密码/删除）**必须写审计且 `strict=True`** |
| **BR-13-19** | 密码规则与 01 一致（6~64）；后端生成的初始密码必须**足够随机**（≥12 位）且**只在响应中返回一次**，不落明文日志 |
| **BR-13-20** | 账号列表**不得返回密码哈希**；任何接口响应中都不允许出现 `password_hash` |

### 4.3 决策引擎配置（模型引擎预留）

| 编号 | 规则 |
|---|---|
| **BR-13-21** | `model_configs` 为**架构预留**，当前只有一条默认记录（`engine_type=rule`、`fuse_mode=rule_first`、`rule_weight=1.0`、`model_weight=0.0`）（AD-09 / **G-01**） |
| **BR-13-22** | 尝试切换到 `model` 或 `hybrid` 必须**明确拒绝**（`SYS-4003`「模型引擎尚未实现」），**不得静默忽略或假装成功** |
| **BR-13-23** | 页面必须**显著标注**模型引擎未启用及原因（橙色警示条），避免评审误以为已支持模型决策 |
| **BR-13-24** | 融合权重在 `engine_type=rule` 时**只读**（`1.0 / 0.0`），不可编辑 |

### 4.4 健康度与统计

| 编号 | 规则 |
|---|---|
| **BR-13-25** | `decision_p95_ms` 来源于 11 的运行时统计（或进程内滚动窗口），**不在本模块自己聚合** |
| **BR-13-26** | 健康度卡片**自动刷新间隔 10 秒**，页面隐藏时暂停 |
| **BR-13-27** | `decision_p95_ms > 50ms` 时该卡片**标红**并按 11 的口径展示（对齐概要设计 §6 目标） |
| **BR-13-28** | 组件状态探测**必须有超时**（单个组件 ≤1s），任一组件探测超时不得导致整卡加载失败——超时的组件显示「探测超时」 |
| **BR-13-29** | `/system/stats` 与 `/health` 的区别：`/health` 是**存活探针**（轻量、无鉴权），`/system/stats` 是**运维看板**（含统计、需 admin 权限） |

## 5. 异常处理

| 错误码 | 场景 | HTTP | 用户可见提示 | 处理 |
|---|---|---|---|---|
| `SYS-4001` | 参数取值越界 | 422 | 「参数 xxx 超出允许范围（a~b）」 | 字段标红，不保存任何参数（**原子性**） |
| `SYS-4002` | 短窗口 ≥ 长窗口 | 422 | 「短窗口必须小于长窗口」 | 同上 |
| `SYS-4003` | 请求切换到未实现的模型引擎 | 422 | 「模型引擎尚未实现（G-01）」 | 明确拒绝，不改配置 |
| `SYS-4004` | 账号已存在 | 409 | 「账号 xxx 已存在」 | — |
| `SYS-4005` | 停用/删除自己 | 403 | 「不能停用或删除当前登录账号」 | — |
| `SYS-4006` | 停用/删除最后一个管理员 | 403 | 「系统必须保留至少一个可用管理员」 | — |
| `SYS-4007` | 账号有待处置案件 | 409 | 「该账号有 N 个待处置案件，请先转交」 | 返回案件列表供转交 |
| `SYS-4008` | 删除未停用的账号 | 409 | 「请先停用该账号再删除」 | — |
| `SYS-5001` | 配置保存失败 | 503 | 「配置保存失败，已回滚」 | **必须原子**：任一项失败则全部不生效 |
| `SYS-5002` | 账号数据写入失败 | 503 | 「账号操作失败」 | 不留半成品 |
| `SYS-5003` | 组件探测超时 | 200 | 该组件显示「探测超时」 | 不影响其他组件 |
| `SYS-5004` | 配置热更新广播失败 | 200 | 「配置已保存，但部分模块未生效，建议重启」 | 记录告警并在响应 `requires_restart` 中体现 |

> **原子性要求**：配置保存与账号操作都必须**全成或全不成**（`SYS-5001`/`SYS-5002`）。
> 半个配置生效比不生效更危险——例如 TTL 改了但超时没改，行为不可预期。
