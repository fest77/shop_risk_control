# 09 · 画像与关联图谱模块 Spec

> **文档编号**：04_模块Spec / 09
> **所属项目**：shop_risk_control
> **模块类型**：引擎（无独占页面）
> **上游依据**：`PRD.md` · `01_数据实体` · `02_概要设计` · `03_原型图`

---

## 1. 模块定位

| 项 | 内容 |
|---|---|
| **职责** | ① 用户/设备/IP/收货地址的**画像聚合**（风险标签、累计统计）② **实体关联边**的构建与维护 ③ **2 跳关联网络查询** ④ 聚集度指标（同设备/同 IP/同地址的账号数） |
| **触发时机** | 图的写入为**异步**（决策链路之后）；查询为人工复核时按需触发 |
| **上游** | 03（事件，作为建图输入）、05（决策结果，用于打风险标记） |
| **下游** | 07 审核工作台（中栏画像卡与关联图谱） |
| **对应 PRD** | 2.3.1「多维画像下钻、关联团伙图谱分析」、2.3.3「证据链与画像详情区（同设备/同 IP/同地址聚集账号）」、2.3.6「画像与图谱模块」 |
| **对应实体** | E10 `users`、E11 `devices`、E12 `ip_pool`、E13 `user_addresses`、**E14 `entity_edges`（核心）** |
| **对应原型** | `03_风控审核工作台.pen` 中栏：用户画像卡 `profileCard` + 关联实体图谱 `graphBox` |
| **对应架构决策** | **AD-06**（图谱查询限制 2 跳，`max_hop` 可配） |

**本模块明确不做的事**：
- 不做特征计算（归 04）——本模块的聚集度指标是**全量长期口径**，与 04 的窗口口径**不是一回事**（见 §4.3 的边界说明）
- 不做案件的查看与联动（归 07）
- 不做处置动作（归 08）

## 2. 页面结构

本模块的数据出现在 `03_风控审核工作台.pen` **中栏的两处**。

### 2.1 展示点 A：用户画像卡 `profileCard`

| 区块 | 元素 | 绑定字段 | 说明 |
|---|---|---|---|
| 头部 | 头像占位（40×40 圆形） | — | 无真实头像，用首字母或色块 |
| 头部 | 用户编号 | `users._id` | 16px/600 |
| 头部 | 风险等级标签 | `risk_level`（来自最近一次决策） | 高/中/低，红/橙/绿 |
| 头部 | 账号状态标签 | `users.status` | `active` → 「账号正常」；`frozen`/`banned` 显示对应色 |
| 头部 | 副标题行 | `user_age_days` + `level` + `stat.order_cnt` | 文案：`注册 42 天 · 等级 normal · 累计下单 3 单` |
| 标签区 | 风险标签组 | `users.risk_tags` | 每个标签一个 `tag`；高危标签红底、中危橙底、其余灰底 |
| 明细 | 手机号（脱敏） | `users.phone`（mask） | `138****6621` |
| 明细 | 设备指纹 | `E11`：`device_id · 关联 N 个账号` | **N ≥ 5 时数值标红** |
| 明细 | 来源 IP | `E12`：`ip · 代理 IP` | `is_proxy = true` 时标橙 |
| 明细 | 收货地址 | `E13`：`同地址关联 N 个账号` | **N ≥ 5 时标红** |

**风险标签配色表**

| 标签 | 含义 | 配色 |
|---|---|---|
| `device_cluster` | 设备聚集 | 红底红字 |
| `address_cluster` | 地址聚集 | 红底红字 |
| `aftersale_abuse` | 售后滥用 | 红底红字 |
| `blacklist_history` | 历史黑名单 | 红底红字 |
| `ip_cluster` | IP 聚集 | 橙底橙字 |
| `new_account` | 新账号 | 橙底橙字 |
| `proxy_ip` | 代理 IP | 橙底橙字 |
| `high_freq` | 高频行为 | 灰底 |

**空态**：用户不存在时整卡显示「未找到该用户画像」。

### 2.2 展示点 B：关联实体图谱 `graphBox`

| 元素 | 说明 |
|---|---|
| 标题 | 「关联实体图谱」 |
| 副标题 | 力导向图 · 2 跳 · 中心：用户 U000128 |
| 画布 | 高约 180~200px；力导向布局 |
| 中心节点 | 当前用户（大号实心节点，品牌色） |
| 一跳节点 | 该用户的设备 / IP / 收货地址（中号） |
| 二跳节点 | 同设备、同 IP、同地址关联的**其他账号**（小号） |
| 边 | `used_device` / `shared_ip` / `shared_address` / `same_phone` / `transferred_to` |
| 红色边 | `risk_flag = true` 的边（已判定风险关联） |
| 交互 | 节点 hover 显示名称与关联次数；点击节点 → 右侧滑出该实体详情（或切换到该用户画像） |
| 图例 | 必须区分：中心节点 / 一跳实体 / 二跳账号 / 风险边 / 普通边 |

**规模限制与截断提示**（关键）
- 节点上限 **200**、边上限 **500**
- 超出时**取关联强度（`weight`）最高的前若干条**，并在图下方显示橙字
  「关系过多，已展示关联强度最高的 200 个节点（共 N 个）」
- **不允许静默截断**——人工研判必须知道图不完整

**空态**：该用户无任何关联时显示「该用户暂无关联实体（孤立账号）」——注意这与"查不到"不同。

## 3. 接口字段

### 3.1 `GET /api/v1/profiles/{user_id}` — 用户全貌画像

**响应 `data`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `user` | object | `{user_id, phone_masked, register_at, age_days, level, status, risk_tags[]}` |
| `stat` | object | `{order_cnt, aftersale_cnt, block_cnt, total_amount}` |
| `latest_decision` | object \| null | `{risk_score, risk_level, decision, decided_at}` |
| `device` | object \| null | `{device_id, linked_user_cnt, first_seen_at, os}` |
| `ip` | object \| null | `{ip, linked_user_cnt, is_proxy, region, isp}` |
| `address` | object \| null | `{address_id, masked_detail, linked_user_cnt, aftersale_cnt}` |
| `tag_meta` | object | 标签 → `{label, severity}` 的映射（供前端配色，**避免前端硬编码**） |

**状态码**：`200` / `404`（`GRP-4004` 用户不存在）

### 3.2 `GET /api/v1/graph/{entity_type}/{entity_id}` — 关联网络

**请求参数**

| 参数 | 类型 | 默认 | 约束 |
|---|---|---|---|
| `max_hop` | int | **2** | **1~2**；>2 返回 `GRP-4001`（AD-06） |
| `max_nodes` | int | 200 | 上限 500 |
| `max_edges` | int | 500 | 上限 1000 |
| `risk_only` | bool | false | 只返回 `risk_flag=true` 的边及其端点 |

**`entity_type` 取值**：`user` / `device` / `ip` / `address`
（**不含 `phone`**——手机号是用户属性，不作为独立图节点，见 Step1 §4 的说明）

**响应 `data`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `center` | object | `{type, id, label}` |
| `nodes` | array | `[{id, type, label, hop, risk_level, risk_tags[], linked_user_cnt, is_center}]` |
| `edges` | array | `[{from, to, relation, weight, risk_flag, last_seen_at}]` |
| `truncated` | bool | 是否发生截断 |
| `total_nodes` | int | 截断前的真实节点数（供提示文案） |
| `total_edges` | int | 截断前的真实边数 |
| `elapsed_ms` | int | 查询耗时 |

**状态码**：`200` / `400`（`GRP-4001` `max_hop` 越界）/ `404`（`GRP-4004` 实体不存在）

### 3.3 内部接口（供 04 与 05 调用，非 HTTP）

```python
async def get_linked_user_count(entity_type: str, entity_value: str) -> int: ...
async def bump_stat(user_id: str, field: str, delta: int = 1) -> None: ...
async def add_edge(from_type, from_id, to_type, to_id, relation: str) -> None: ...
async def tag_user(user_id: str, tag: str) -> None: ...
```

| 方法 | 调用方 | 说明 |
|---|---|---|
| `get_linked_user_count` | **04** | 提供 `device_user_cnt` / `ip_user_cnt` / `address_user_cnt` |
| `bump_stat` | 03/05 | 累加 `users.stat`（下单数、售后数、拦截数、金额） |
| `add_edge` | 03（异步） | 事件落库后补写关联边（Step2 §7：边为**异步补写**） |
| `tag_user` | 05/08 | 打风险标签（决策命中或人工处置时） |

## 4. 业务规则

### 4.1 画像聚合

| 编号 | 规则 |
|---|---|
| **BR-09-01** | 画像聚合必须**增量维护**（`$inc` / `$addToSet`），不做每次实时全量扫描 |
| **BR-09-02** | `users.stat` 的字段：`order_cnt`（下单数）、`aftersale_cnt`（售后数）、`block_cnt`（被拦截数）、`total_amount`（累计金额，单位分） |
| **BR-09-03** | `risk_tags` 用集合语义（`$addToSet`）写入，**不允许重复标签** |
| **BR-09-04** | 标签一旦打上**不自动移除**；误打需通过管理操作显式移除并写审计（避免"标签悄悄消失"导致研判失真） |
| **BR-09-05** | 手机号与收货地址详细内容**必须脱敏存储**：手机号中间四位掩码；地址只存 `detail_hash` 不存明文 |
| **BR-09-06** | `users.latest_decision` 只保留**最近一次**决策摘要（覆盖式更新），不做历史数组（历史在 `decisions` 表） |

### 4.2 关联图的构建

| 编号 | 规则 |
|---|---|
| **BR-09-07** | 边的**写入时机为异步**（事件决策返回之后），避免拖慢决策链路（对齐 Step2 §7） |
| **BR-09-08** | 边的唯一性：`from_id + to_id + relation` 唯一；重复出现时**累加 `weight`** 并更新 `last_seen_at`，不新增边 |
| **BR-09-09** | 每次事件产生的关联：`user → device`（`used_device`）、`user → ip`（`shared_ip`）、`user → address`（`shared_address`）、`user → phone`（`same_phone`） |
| **BR-09-10** | 边的 `risk_flag` 由 05/08 在判定违规或人工处置时置为 `true`；**不允许自动清除** |
| **BR-09-11** | 建图失败**不影响决策**（最终一致）；失败入重试队列并计数告警 |
| **BR-09-12** | `linked_user_cnt` 为**冗余冗余字段**（同时存在 `users`/`devices`/`ip_pool`/`user_addresses` 上），由 `bump_stat` 维护，用于避免每次查询都全表统计 |

### 4.3 聚集度口径（与 04 的边界，**易混点**）

| 项 | 04 特征计算引擎 | **09 画像与图谱（本模块）** |
|---|---|---|
| 口径 | **窗口内**（1h/24h）的行为频次 | **全量长期**的关联账号数 |
| 字段 | `device_order_cnt_1h` 等 | `device_user_cnt` 等聚集度 |
| 过期 | 随窗口 sweep 过期 | **不过期**（团伙视角需要长期记忆） |
| 存储 | 进程内 | MongoDB（持久） |

| 编号 | 规则 |
|---|---|
| **BR-09-13** | `device_user_cnt` / `ip_user_cnt` / `address_user_cnt` **以本模块为准**（持久、全量）；04 通过内部接口 `get_linked_user_count()` 获取，**不得自己另算一份** |
| **BR-09-14** | 这保证"同一指标只有一个真源"，避免 04 与 09 给出两个不同的账号数 |

### 4.4 图查询

| 编号 | 规则 |
|---|---|
| **BR-09-15** | `max_hop` **硬上限为 2**（AD-06）；>2 直接拒绝 `GRP-4001`。理由：2 跳已能覆盖"同设备→这些账号的其他设备"这一团伙发现主场景，更高跳数会指数膨胀 |
| **BR-09-16** | 2 跳查询必须**先取 1 跳，再批量取 2 跳**（两批查询），**不允许递归逐节点查询**（N+1 问题） |
| **BR-09-17** | 节点与边超出上限时**按 `weight` 降序保留**，并置 `truncated=true`、返回 `total_*` 真实数量 |
| **BR-09-18** | `truncated=true` 时前端**必须**显示截断提示（§2.2），不得静默 |
| **BR-09-19** | 图查询为**只读**，不写任何数据；查询耗时需记录，P95 目标 < 300ms |
| **BR-09-20** | 返回的节点必须**批量补齐属性**（风险等级、标签），不允许前端对每个节点再单独请求 |

## 5. 异常处理

| 错误码 | 场景 | HTTP | 用户可见提示 | 处理 |
|---|---|---|---|---|
| `GRP-4001` | `max_hop` 越界（>2） | 400 | 「图谱查询最多支持 2 跳」 | 前端已限定，正常不触发 |
| `GRP-4002` | `entity_type` 非法（如 `phone`） | 422 | 「不支持的实体类型」 | 明确拒绝，不静默降级 |
| `GRP-4004` | 用户/实体不存在 | 404 | 「未找到该用户/实体」 | 中栏显示占位 |
| `GRP-5001` | 画像聚合查询失败 | 503 | 「画像服务暂时不可用」 | 中栏画像卡显示错误占位 + 重试；**右栏判定摘要不受影响**（区块隔离） |
| `GRP-5002` | 图查询超时（>3s） | 200 | 「关系过于复杂，已返回部分结果」+ `truncated=true` | 返回已取到的部分，**不报错** |
| `GRP-5003` | 建边失败 | — | 无（后台） | 入重试队列 + 告警；**不影响决策** |
| `GRP-5004` | 节点属性批量补齐部分失败 | 200 | 缺失属性显示 `—` | 部分成功可接受，记录告警 |

> **本模块不参与放行判定**，故不涉及 fail-closed 的决策侧；但**图不完整必须显式告知**（BR-09-18），这是"证据链可信"的前提。

## 6. 文件规划

```
app/
├── services/
│   ├── profile_service.py     # 画像聚合：读用户/设备/IP/地址，组装全貌，维护 stat 与 tags

├── repos/
│   ├── profile_repo.py        # users/devices/ip_pool/user_addresses 的读写与 $inc/$addToSet

├── api/
│   ├── profile_api.py         # GET /profiles/{user_id}
│   └── graph_api.py           # GET /graph/{entity_type}/{entity_id}
├── tasks/
│   └── edge_writer.py         # 异步建边任务（含重试队列）
└── schemas/
    └── profile_schema.py      # 画像与图谱响应模型
```

| 文件 | 职责 | 可单测 |
|---|---|---|
| `profile_service.py` | 画像组装与增量维护 | ✔（可注入假 repo） |
| `graph_service.py` | 图查询与裁剪逻辑 | ✔（重点：跳数、裁剪、批量补齐） |
| `graph_repo.py` | 边 upsert 与双向查询 | ✔ |
| `edge_writer.py` | 异步建边与重试 | ✔ |
| `schema/profile_schema.py` | 响应模型 | ✔ |

**索引依赖**（来自 Step1 E14）：`from_type+from_id`、`to_type+to_id`、唯一 `from_id+to_id+relation`。
**测试重点**：2 跳的节点/边去重、`weight` 排序裁剪、`truncated` 与 `total_*` 正确性。

## 8. 本模块遗留与待确认

| 编号 | 事项 | 当前取值 | 说明 |
|---|---|---|---|
| **AD-06** | 图谱跳数上限 | **2 跳**（硬限制） | 已确认；如需 3 跳需重新评估性能与图规模 |
| **新增** | 聚集度是否随时间衰减 | **不衰减**（长期记忆） | 见 BR-09-14。若要求"近 30 天聚集"，需带时间戳的边集合，内存与查询成本显著上升 |
| **新增** | `same_phone` 边的语义 | 同一手机号关联多个用户时建立 | PRD 只提"同设备/同IP/同地址"，**手机号为我方补充**，若不需要可去掉 |
| **新增** | 标签是否会因时间推移失效 | **不自动失效** | 如需"标签有效期"需引入 `expire_at`，当前无 |
