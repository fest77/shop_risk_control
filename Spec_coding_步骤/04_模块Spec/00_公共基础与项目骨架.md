## 1. 模块定位

| 项 | 内容 |
|---|---|
| **职责** | 为其余 13 个模块立规矩：项目目录结构、配置加载、Mongo 连接管理、日志与 `trace_id`、统一异常与错误码体系、枚举与常量单一来源、前端单页壳与 hash 路由、静态资源与 vendor 组件、HTTP 客户端封装、种子数据脚本入口 |
| **上游** | 无（最底层） |
| **下游** | 全部 13 个模块 |
| **对应 PRD** | 无直接条目；服务于 2.3.1「实时事件接入」的工程底座与 2.3.2「系统管理员维护系统运行配置」 |
| **对应实体** | 无（不拥有业务实体；提供集合名常量与索引声明给各模块） |
| **对应原型** | 全部 9 个原型的**页面外壳**（侧边导航 + 主内容区）、登录页的样式基线 |
| **对应架构决策** | AD-01（异步落库任务模式）、AD-05（以 Protocol 抽象可替换组件） |

**本模块明确不做的事**：
- 不实现任何业务规则、不做任何业务判断
- 不定义业务枚举的**取值**（只在 `enums.py` 汇总导出，取值来源见 §4.5）
- 不实现各模块的接口，只提供路由注册机制与统一响应契约

## 3. 接口字段

### 3.1 统一响应契约（**全项目强制**）

**成功**
```json
{ "ok": true, "data": { ... }, "trace_id": "tr_20260923_102431_ab12" }
```
**失败**
```json
{ "ok": false, "error": { "code": "COM-4001", "message": "参数校验失败", "detail": [...] },
  "trace_id": "tr_20260923_102431_ab12" }
```

**约定**
| 项 | 规则 |
|---|---|
| `ok` | 布尔，唯一成功判据 |
| `error.code` | 形如 `PREFIX-4xxx` / `PREFIX-5xxx`，见 §4.4 |
| `error.message` | **面向用户的中文短句**，可直接展示在 toast |
| `error.detail` | 可选，结构化字段级错误（如 Pydantic 的 `errors()`） |
| `trace_id` | 每个请求必有，前端在错误 toast 里展示后 6 位便于定位 |

> **实现口径（模块 00 收尾时确认，见 15_决策记录 D17）**：上面两段示例是本模块最初的写法
> （成功 `{ok, data, trace_id}`、失败嵌套 `error`），而 `07_案件审核工作台` 的接口章节把响应包写成
> 扁平的 `{code, message, trace_id, data}` 并注明"（模块 00）"。两者**可以同时满足**，故最终实现取**扁平包 + 派生 `ok`**：
>
> ```json
> { "ok": true,  "code": "OK",       "message": "查询成功", "trace_id": "tr_20260923_102431_ab12", "data": { } }
> { "ok": false, "code": "COM-4001", "message": "参数校验失败", "trace_id": "tr_...", "data": { "errors": [ ] } }
> ```
>
> - `ok` **由 `code` 派生**（`ok === (code === "OK")`，由同一个函数生成），因此不存在"两处状态可能打架"的问题
> - 字段级错误明细放在 `data`（即下文 `error.detail` 的落点），前端统一以 `ok` 判断成败、以 `code` 定位问题
> - 所有响应（含 `/health`）都走同一个包，响应头同时回填 `X-Trace-Id`（含未捕获异常的 500）

### 3.2 分页契约（**所有列表接口强制**）

**请求**：`page`（默认 1，≥1）、`size`（默认 20，1~100）
**响应 `data`**：`{ "items": [...], "total": 128, "page": 1, "size": 20, "pages": 7 }`

### 3.3 本模块提供的接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/health` | 健康检查：进程存活 + Mongo 连通性 + 版本 |
| `GET` | `/api/v1/common/enums` | 一次性下发全部枚举（前后端共用单一来源） |
| `GET` | `/api/v1/common/meta` | 返回 `server_time`、`api_version`、`env`（`dev`/`prod`） |

**`GET /health` 响应字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | `ok` / `degraded` / `down` |
| `version` | string | 应用版本 |
| `mongo` | object | `{connected: bool, latency_ms: int, db: "risk_control"}` |
| `uptime_sec` | int | 进程运行时长 |
| `time` | string | ISO8601 服务器时间 |

**`GET /api/v1/common/enums` 响应**（键为枚举组名，值为 `{value, label}` 数组）

必须至少包含：`event_type`、`decision`、`risk_level`、`rule_status`、`list_type`、`list_status`、`entity_type`、`case_status`、`conclusion`、`action_type`、`level`、`user_status`、`relation`、`bucket_type`、`granularity`、`role`、`sys_user_status`、`engine_type`、`fuse_mode`、`condition_op`、`risk_tag`。

> **单一来源原则**：`enums.py` 是唯一真源，前端不再各自硬编码中文标签。

### 3.4 静态资源

| 路径 | 内容 |
|---|---|
| `GET /` | 返回单页壳 `index.html` |
| `GET /static/css/app.css` | 主题变量 + 公共组件样式 |
| `GET /static/js/*.js` | 按视图拆分：`app.js`（路由/壳）、`api.js`（fetch 封装）、`views/*.js` |
| `GET /static/vendor/echarts.min.js` | **本地 vendor**，不从 CDN 加载（D-01 已确认） |

## 4. 业务规则

### 4.1 配置加载

| 编号 | 规则 |
|---|---|
| **BR-00-01** | 配置来源优先级：**环境变量 > `.env` 文件 > 代码默认值**。启动时打印生效的关键配置（**密钥类必须脱敏**为前 4 位 + `****`） |
| **BR-00-02** | 必需配置缺失时**启动即失败**（fail-fast），不允许带着空配置运行 |
| **BR-00-03** | `.env` 通过 `Path(__file__)` 显式定位到项目根，不依赖当前工作目录 |
| **BR-00-04** | `.env` 严禁入库；仓库只提供 `.env.example`（键齐全、值留空） |

### 4.2 连接与资源

| 编号 | 规则 |
|---|---|
| **BR-00-05** | Mongo 客户端为**进程内单例**（`AsyncMongoClient`，pymongo 4.18.1 自带，**不引入 motor**），用 `asyncio.Lock` 保证并发初始化只执行一次 |
| **BR-00-06** | 客户端在应用 `lifespan` 启动时建立、关闭时释放；**不在每次请求里新建** |
| **BR-00-07** | 集合名与索引声明集中定义（`collections.py`），由种子脚本统一建索引，业务代码不得散落硬编码集合名 |
| **BR-00-08** | 所有可替换组件（特征存储、业务适配器、模型引擎）以 `typing.Protocol` 抽象（AD-05），默认提供进程内/空实现 |

### 4.3 日志与可观测

| 编号 | 规则 |
|---|---|
| **BR-00-09** | 每个 HTTP 请求生成 `trace_id`（`tr_<yyyymmdd>_<hhmmss>_<4位随机>`），写入 `contextvar`，**全链路日志自动携带** |
| **BR-00-10** | 日志为结构化单行：`时间 级别 trace_id 模块 消息`；禁止打印密钥、手机号明文、完整地址 |
| **BR-00-11** | 记录每个请求的 `path / method / status / elapsed_ms`；**决策链路额外记录分段耗时**（校验/特征/名单/规则/仲裁） |

### 4.4 错误码体系

| 编号 | 规则 |
|---|---|
| **BR-00-12** | 错误码 = `模块前缀` + `-` + 4 位数字。**4xxx = 客户端错误**（参数/权限/不存在），**5xxx = 服务端或依赖错误** |
| **BR-00-13** | 同一错误码在全项目**唯一**，不得两个模块复用 |
| **BR-00-14** | `message` 面向用户、可展示；技术细节放 `detail` 与日志，**不回显堆栈** |
| **BR-00-15** | 未捕获异常统一兜底为 `COM-5000`，并记录完整堆栈（仅服务端日志） |

**模块前缀分配**（以 `00_模块划分与边界.md` §6 为准：**一个模块一个前缀**）
`00→COM`、`01→AUTH`、`02→DASH`、`03→EVT`、`04→FEA`、`05→RUL`、`06→CFG`、`07→CASE`、`08→DSP`、`09→GRP`、`10→SIM`、`11→MET`、`12→AUD`、`13→SYS`

> **勘误（模块 00 收尾时修正，见 15_决策记录 D18）**：本行原写作 `02/11→MET`、`05/06→RUL`、`07/08→CAS`，
> 即"按模块组分配"，与 `00_模块划分与边界.md` §6 的最终裁定相冲突。§6 已记录改为"一模块一前缀"的原因：
> 模块组方案下 `CAS-4001` 在 07 是「案件不存在」而在 08 是「处置参数非法」，`RUL-4001` 在 05 与 06 同样同号不同义，
> 违反 BR-00-13「同一错误码在全项目唯一」。故以 §6 为准，并新增 `DASH`/`CFG`/`CASE`/`DSP` 四个前缀。

### 4.5 枚举与常量

| 编号 | 规则 |
|---|---|
| **BR-00-16** | 枚举在 `enums.py` 用 `StrEnum` 定义，**每个枚举同时定义 `value` 与中文 `label`** |
| **BR-00-17** | `status` 字段名在六个实体中复用但取值域不同（见 Step1 §4 警示）——**必须按实体各自定义枚举类，禁止共用一个通用 `StatusEnum`** |
| **BR-00-18** | 枚举组集合必须与 Step1 的「枚举字典」22 组完全一致，`/common/enums` 缺一组即为缺陷 |

### 4.6 前端约定

| 编号 | 规则 |
|---|---|
| **BR-00-19** | **零构建**：不使用 npm/打包器/框架；页面直接由 FastAPI 托管，浏览器打开即用 |
| **BR-00-20** | **零 CDN**：第三方库只允许放 `static/vendor/` 本地引用（当前仅 ECharts） |
| **BR-00-21** | 所有接口调用走统一 `api.js` 封装：自动加 `Authorization`、自动解析 `ok/error` 契约、401 自动跳登录、错误自动 toast |
| **BR-00-22** | **禁止在页面里做业务计算**（如拦截率）——一律取后端结果（与模块 02 的边界裁定一致） |
| **BR-00-23** | 所有列表必须实现三态：加载中 / 空态 / 错误态；禁止只写成功分支 |

### 4.7 种子数据

| 编号 | 规则 |
|---|---|
| **BR-00-24** | 提供幂等种子脚本：建索引 + 灌入角色场景、示例规则、示例名单、示例用户、仿真用例 |
| **BR-00-25** | 种子数据**固定随机种子**，保证每次初始化结果一致（演示可复现） |
| **BR-00-26** | 种子脚本支持 `--reset`（清空业务集合后重建），默认不删除已有数据 |

## 5. 异常处理

| 错误码 | 场景 | HTTP | 用户可见提示 | 处理 |
|---|---|---|---|---|
| `COM-4000` | 请求体非法 JSON | 400 | 「请求格式错误」 | 记录原始片段（截断 200 字符） |
| `COM-4001` | 参数校验失败 | 422 | 「参数校验失败：xxx」 | `detail` 带 Pydantic 字段级错误 |
| `COM-4004` | 资源不存在 | 404 | 「请求的资源不存在」 | — |
| `COM-4005` | 方法不允许 | 405 | 「不支持的请求方法」 | — |
| `COM-4290` | 请求过于频繁 | 429 | 「操作过于频繁，请稍后再试」 | 简易内存限流 |
| `COM-5000` | 未捕获异常 | 500 | 「服务内部错误，请稍后重试」 | **完整堆栈入日志**，响应只给 `trace_id` |
| `COM-5001` | Mongo 连接失败 | 503 | 「数据库连接失败」 | `/health` 返回 `down`；决策链路按各模块 fail-closed 规则处理 |
| `COM-5002` | 配置缺失（启动期） | — | 进程退出 | 启动日志列出缺失键名 |
| `COM-5003` | 静态资源缺失 | 500 | 「页面资源缺失」 | 启动时校验 `vendor/echarts.min.js` 存在，缺失则启动告警 |

> **兜底原则**：任何未归类异常都必须落到 `COM-5000`，**不允许出现无 `trace_id` 的 500 响应**。

| # | 验收项 | 如何验证 |
|---|---|---|

| V-00-06 | 密钥不泄露 | 启动日志与接口响应中 grep `.env` 中的真实密钥值，**必须 0 命中** |
